## 五、多标签处理（点击账号跳新标签时）

**镜像站切换账号时会打开新标签**，容易"找不到新标签的聊天入口"。统一按以下标准流程处理：

```bash
# ① 点击账号/登录后，先列出所有标签
opencli browser gpt-ext tab list

# ② 找到新打开的标签（URL 含 chat/new/login，或标题含"聊天/对话/新对话"），记下其 target ID
# ③ 切到该标签
opencli browser gpt-ext tab select <targetId>

# ④ 确认聊天界面；若不对，tab list 重看再选
opencli browser gpt-ext state
```

**兜底方案**（tab select 后仍找不到聊天入口时，用"当前标签导航"绕过新标签）：

```bash
# ① 先切回原账号列表标签
opencli browser gpt-ext tab list
opencli browser gpt-ext tab select <原标签 targetId>

# ② 注入 window.open 钩子，把新开标签 URL 捕获到变量（此时点击不再真开新标签）
opencli browser gpt-ext eval "window.__newUrl=''; window.__o=window.open.bind(window); window.open=function(u){window.__newUrl=u; return null;};"

# ③ 点击账号卡
opencli browser gpt-ext click <账号卡ref>

# ④ 读取捕获到的真实登录 URL
opencli browser gpt-ext eval "window.__newUrl"

# ⑤ 在当前标签直接导航过去（相当于打开了登录/聊天页）
opencli browser gpt-ext eval "location.href = window.__newUrl"

# ⑥ state 确认聊天界面
opencli browser gpt-ext state
```

> 经验：镜像站账号受限时点「切换账号」，弹的是账号卡列表；点账号卡可能又开新标签。全程优先用 `tab list` + `tab select` 找聊天页，别让 opencli 停在旧标签里。

## 六、切换 Extended 思考模式

1. 用 `state` 找到输入框上方模型选择 pill（默认显示 `Auto`），`click` 它。
2. 弹出模型菜单后，**用键盘导航**（直接 click 菜单项会被 Radix 过滤，无效）：
   ```bash
   opencli browser gpt-ext eval "document.querySelector('[role=menuitemradio][data-testid=\"model-switcher-gpt-5-6-thinking\"]')?.focus()"
   opencli browser gpt-ext keys "Enter"
   ```
3. 若 selector 失效，改用通用法：`state` 查看菜单项索引，找到含 "Thinking / Extended" 的项，键盘 focus + Enter。
4. 成功后模型 pill 应显示 **"Extended"**，确认后再继续。

## 七、输入完整提示词

把下方提示词**原样**作为提问内容。建议先写入本地 `prompt.txt`，再用 opencli 真实输入注入（value setter 不会触发 React 提交）：


## 九、持续执行（重要）

这是一个**持续任务**，第一阶段问诊拿到方案后，不要停在"给方案"，要继续推进落地闭环：

1. **阶段一：问诊拿方案**（本指令包主流程）——把 Extend 回复保存到 `docs/ai-advice/`。
2. **阶段二：方案落地**——把方案里的字段设计落进系统：
   - 在飞书「学习日志」表新增调度字段（当前轮次/下次复习时间/难度等级/连续答对次数/连续答错次数等，以方案为准）；
   - 打通与 vocabulary 表（下次复习/记忆阶段/掌握状态）及能力状态表的联动逻辑；
   - 更新相关表结构/配置，确保复习结果能写回飞书、进入 hourly 同步闭环。
3. **阶段三：持续迭代**——用学习日志数据定期检查：旧词回炉率、各轮次正确率、间隔算法是否要调参；用户随时可以说"继续优化记忆策略"继续推进。

每完成一个阶段，按交接规范写简短汇报：**模块×要点 / 变更清单 / 验证方式 / 已知偏差**。
