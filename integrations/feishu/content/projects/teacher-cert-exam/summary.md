## 项目用途

教资备考系统是一个围绕教师资格证考试（初中英语方向）备考全流程的个人数据中台，把分散在飞书多维表格中的知识模块、考点信息、题型模板、错题本和真题库统一组织起来，供 AI 工具在无飞书访问权限的情况下读取数据模型、记录和表间关联，进而提供考点掌握诊断、错题归因、复习计划制定和真题题型分析等能力。

它解决的核心问题是：教资备考数据天然分散在"模块—考点—题型—错题—真题"多条线索上，单看任何一张表都无法回答"我该重点复习哪些考点"这类问题。本项目通过显式的关联字段把这些线索串成一张可遍历的图，并以 846 条考点信息为知识主干，支撑细粒度的间隔复习管理。

---

## 核心目标

1. **知识结构化**：以 `knowledge-modules` 的 20 个知识模块为顶层组织，按"语言知识树""教学知识树""综合素质"三棵知识树覆盖学科知识与教学能力、综合素质两大科目。
2. **考点可追踪**：以 `exam-points`（846 条）为知识主干，记录每个考点的掌握程度、学习状态、连续正确次数、最近检测日期，并通过公式自动计算下次复习日期，支撑间隔复习。
3. **题型可参考**：以 `question-templates`（10 条）提供各题型的答题框架、典型例题与评分要点，作为答题方法参考。
4. **错题可归因**：通过 `error-notebook` 的 `关联考点` 把错题落回具体考点，避免"错完就忘"。**当前错题本为空，尚未投入使用。**
5. **真题可练习**：以 `past-exam-questions`（107 条）为题源中心，覆盖 2021 上至 2026 上的各考次，含题型、难度、分值、答案解析，并通过 `关联考点` / `关联模块` 连接知识体系。

## 间隔复习机制

`exam-points` 表实现了基于公式字段的自动间隔复习调度。`下次复习日期` 为 formula 类型，由以下逻辑自动计算：

| 条件 | 下次复习间隔 | 说明 |
|---|---|---|
| 学习状态 = "未学习" | 空 | 未学习的考点不安排复习 |
| 最近检测日期为空 | 空 | 从未检测的考点不安排复习 |
| 掌握程度 = "未掌握" | 最近检测日期 + 3 天 | 未掌握的考点短期复检 |
| 掌握程度 = "模糊" | 最近检测日期 + 7 天 | 模糊掌握的考点一周后复检 |
| 连续正确次数 ≥ 5 | 最近检测日期 + 30 天 | 稳定掌握的考点一个月后复检 |
| 连续正确次数 ≥ 3 | 最近检测日期 + 21 天 | 基本掌握的考点三周后复检 |
| 其他 | 最近检测日期 + 14 天 | 默认两周后复检 |

该机制是 `exam-points` 的核心调度逻辑，判断"到期复习"时以 `下次复习日期` 与读取时的实际日期比较。

## 常见分析问题

下列问题均可仅凭本项目的公开数据回答，并给出推荐的数据遍历路径。

### 1. 哪些考点需要重点复习？

以 `exam-points`（846 条）为主，按以下优先级合并筛选：

1. `下次复习日期` ≤ 今天（到期复习，间隔复习不可中断）；
2. `掌握程度` 为"未掌握"或"模糊"；
3. `重要性` 为"核心考点"或"重点"；
4. `考察频率` 为"高频"；
5. 通过 `关联真题` 反查 `past-exam-questions`，确认该考点在真题中是否反复出现。

最终"需要重点复习"的考点 = 到期 ∧ 掌握弱 ∧ 重要/高频，三者重叠度越高越优先。

### 2. 某个知识模块的掌握情况如何？

以 `knowledge-modules` 为入口，沿 `关联考点` 跳到 `exam-points`，按 `所属模块` 聚合：
- 统计该模块下考点的 `掌握程度` 分布（熟练/模糊/未掌握的比例）；
- 统计 `学习状态` 分布（已学习/未学习的比例）；
- 检查 `下次复习日期` 到期数量；
- 沿 `关联真题` 查看该模块相关真题的 `难度` 与 `题型` 分布。

### 3. 真题题型和难度分布如何？

以 `past-exam-questions`（107 条）为主，按 `题型` / `难度` / `考次` / `所属科目` 聚合：
- 各题型的数量与分值占比；
- 各难度的数量分布；
- 各考次的题型覆盖情况；
- 通过 `关联考点` 跳到 `exam-points`，查看真题涉及的考点 `重要性` / `考察频率` 分布。

### 4. 如何制定当天教资复习计划？

以 `exam-points` 的 `下次复习日期` 为核心调度字段，按以下顺序排定当日内容：

1. **到期复习**：`下次复习日期` ≤ 今天的考点；
2. **高频核心**：`考察频率` 为"高频" ∧ `重要性` 为"核心考点"或"重点"的考点；
3. **薄弱补漏**：`掌握程度` 为"未掌握"或"模糊" ∧ `最近检测结果` 为"错误"的考点；
4. **新增推进**：`学习状态` 为"未学习"但 `重要性` 高的考点；
5. **题型练习**：参考 `question-templates` 的 `答题框架` 与 `典型例题`，结合 `past-exam-questions` 做对应题型练习。

### 5. 某道真题涉及哪些考点和模块？

以 `past-exam-questions` 为入口，沿两条路径遍历：
- `关联考点` → `exam-points`：查看该题涉及的考点及其 `掌握程度` / `重要性` / `考察频率`；
- `关联模块` → `knowledge-modules`：查看该题所属的知识模块及 `模块说明`；
- 在 `exam-points` 中继续沿 `所属模块` 确认模块层级，或沿 `关联真题` 反查同类真题。

### 6. 如何使用题型模板辅助答题？

以 `question-templates`（10 条）为参考：
- 按 `所属科目` 和 `题型名称` 定位目标题型；
- 读取 `答题框架` 了解答题结构；
- 读取 `典型例题` 参考实际题目；
- 读取 `评分要点` 了解得分关键；
- 沿 `关联模块` 跳到 `knowledge-modules` 获取该题型涉及的知识范围。

## 推荐读取顺序

针对首次接入本项目的 AI 工具，推荐按以下顺序读取，逐步建立上下文：

1. `public/projects/teacher-cert-exam/manifest.json` — 确认表清单、记录数、校验和与 `build_id`，判断数据是否 stale。
2. `public/projects/teacher-cert-exam/schema.json` — 读取字段类型、选项取值与关联解析，建立数据模型。

6. 按任务需要读取具体表数据（`tables/<slug>/records-XXXX.json`）。一般分析任务的读取优先级：

## 数据更新时间与时效性

- **同步层级**：`schedule.tier: hourly`，由 GitHub Actions `sync-hourly.yml`（cron `17 * * * *`）每小时同步一次。
- **时间戳来源**：以 `status.json` 的 `last_success_at` 为准；`build_id`（`manifest.json` / `status.json` / `catalog.json`）反映本次构建版本。
- **staleness 判断**：当 `status.json.sync_status` 为 `failed` 或 `stale`、`is_stale: true` 时，展示的是上一次成功版本，最近一次同步尝试失败。分析前应先检查 `is_stale`。
- **字段级时效**：`exam-points.上次复习日期` / `下次复习日期` / `最近检测日期` 与 `error-notebook.错题日期` 是时间敏感字段；"最近""到期"等判断必须基于读取时的实际日期，不能基于固定假设。
- **`下次复习日期` 为公式字段**：该字段由 `学习状态`、`掌握程度`、`连续正确次数`、`最近检测日期` 自动计算，不是手动录入；`最近检测日期` 为空时 `下次复习日期` 也为空。

## 数据公开范围

本项目公开数据遵循 Feishu Data Hub 的三层防护：

1. **视图级**：仅导出各表的 `AI 公开导出` 视图（`source.export_view_name`），视图之外的记录与字段不导出。
2. **字段级**：每张表配置显式字段白名单（见 `config/projects/teacher-cert-exam.yaml` 的 `tables[].fields`），禁止通配符，禁止敏感字段名（由 `lib/config.mjs` 的 `FORBIDDEN_FIELD_NAMES` 强制）。系统字段（创建人、修改人、创建时间、最后更新时间）不在导出范围。
3. **内容级**：导出时与部署前双重扫描（`lib/security.mjs`），扫描凭证/Token 模式、PII（手机号、身份证、邮箱、银行卡）、高熵字符串、Token 前缀与禁止文件；命中即中止整个部署（`privacy.fail_on_sensitive_content: true`）。
