# AI 使用规则

**适用项目:** `civil-service-exam`（公考备考系统）
**配套文件:** `summary.md`（项目语义摘要）、`public/projects/civil-service-exam/` 下的 `manifest.json` / `schema.json` / `status.json` 及各表数据。

本文件规定 AI 工具在使用公考备考项目数据时的任务边界、分析优先级、读取顺序、计划与错误分析规则、时间处理、数据不足处理、禁止推断与输出要求。所有规则均基于本项目真实的 9 张表与 6 条关联关系（详见 `summary.md`），不得超出 schema 与 manifest 描述的字段和关系范围。

---

## 适用任务

本项目的数据适合支撑以下任务：

1. **错题归因分析**：基于 `past-exam-questions`（128 条）与 `practice-records`（1 条）的 `结果` / `错因分析` / `关联知识点`，归因到 `knowledge-points`，并联动 `exam-analysis` / `common-traps` / `exam-patterns`。
2. **薄弱点诊断**：基于 `knowledge-points` 的 `掌握状态` / `正确次数` / `下次复习` / `重要程度`，结合 `exam-patterns` 的 `复习优先级` / `考查频率`，识别需要加强的知识点。
3. **当日学习计划制定**：以 `daily-study-plan` 为载体，综合到期复习、高频考点、薄弱补漏与目标岗位约束，排定当日内容与时长。
4. **命题趋势研判**：基于 `exam-patterns` 的 `近5年出现频次` / `考查频率` / `命题趋势分析` / `常见出题方式`，提供考点热度与出题方式的描述性总结。
5. **真题深度解析调用**：基于 `exam-analysis` 的 `出题意图` / `思维层次` / `解题思维路径` / `变式训练方向`，对已覆盖的真题做思维层面的拆解。
6. **经验方法检索与推荐**：基于 `experience-methods` 的 `分类` / `适用场景` / `标签` / `实用程度`，推荐可复用的方法与口诀。
7. **目标岗位对齐**：基于 `target-positions` 的 `考试类型` / `竞争比` / `历年分数线`，辅助校准复习优先级与强度（仅辅助，见“禁止推断”）。

---

## 不适用任务

本项目的数据**不适合**支撑以下任务，AI 应主动拒绝或转人工：

1. **正式招录信息核验**：`target-positions` 的竞争比、分数线、招录人数、专业/学历/基层经历要求等是个人录入快照，不随官方公告更新，**不能**用于判断某岗位今年是否招录、本人是否符合报考资格。此类问题须转官方招录公告。
2. **总体水平评估**：`practice-records` 仅 1 条记录，不足以支撑“总体正确率”“擅长/不擅长某题型”“近期刷题表现趋势”等总体性结论。
3. **未来命题概率预测**：`exam-patterns` 的频次与趋势是历史描述，不能转化为“今年必考”“概率 X%”的预测。
4. **跨项目的横向比较**：本项目与 `learning-english` 等其他项目无业务关联，不应跨项目合并分析。
5. **写回飞书源数据**：本数据为只读公开导出，AI 不得声称已修改飞书源表；任何“建议回填”只能以建议形式输出，由用户在飞书中执行。
6. **个人身份或隐私推断**：公开数据已经过 PII 与敏感信息扫描，AI 不得从数据中尝试还原或推断任何个人身份信息。

## 分析优先级

当任务可由多种路径完成时，按以下优先级选择数据源与分析方式：

1. **优先用样本充足的表**：错题与成绩分析优先基于 `past-exam-questions`（128 条）与 `daily-study-plan`（40 条），而非 `practice-records`（1 条）。
2. **优先用结构化字段**：能用 `题型` / `所属科目` / `结果` / `掌握状态` / `复习优先级` 等结构化字段回答的，不要依赖自由文本（`题目内容` / `错因分析` / `笔记`）。
3. **优先沿显式关联遍历**：归因时优先沿 6 条显式关联（`关联知识点` / `关联真题` / `典型真题`）跳转，再考虑基于取值的弱匹配。
4. **优先多表交叉验证**：单一来源的结论需经第二张表交叉验证。例如“某知识点薄弱”应同时满足 `knowledge-points.掌握状态` 弱 **且** `past-exam-questions` 中该知识点相关题常错。
5. **优先高频高影响项**：当多个候选并存时，优先 `exam-patterns.复习优先级` 高、`考查频率` / `近5年出现频次` 高、且在真题中重复出现的项。

## 读取顺序

首次接入本项目时，按以下顺序读取，逐步建立上下文（与 `summary.md` 的“推荐读取顺序”一致）：

1. `public/projects/civil-service-exam/status.json` — 先看 `sync_status` / `is_stale` / `last_success_at`，stale 时须在输出中声明数据可能过期。
2. `public/projects/civil-service-exam/manifest.json` — 确认 9 张表、记录数与校验和。
3. `public/projects/civil-service-exam/schema.json` — 建立字段类型与关联模型，注意选择字段的 `options` 取值。
4. `content/projects/civil-service-exam/summary.md` — 建立业务语义与表关系认知。
5. 本文件（`agent-guide.md`）— 加载分析规则与禁止推断。
6. 按任务读取具体表数据。任务到读取优先级的映射：
   - **错题/成绩分析**：`past-exam-questions` → `knowledge-points`（经 `关联知识点`）→ `exam-analysis` / `common-traps`（经 `关联真题` / `典型真题`）→ `exam-patterns`（经 `关联知识点`）。
   - **薄弱点诊断**：`knowledge-points` → `exam-patterns`（经 `关联知识点`）→ `past-exam-questions`（经 `关联真题`）→ `common-traps`。
   - **当日计划**：`exam-patterns` → `knowledge-points` → `daily-study-plan`（历史执行情况）→ `target-positions`（强度校准）→ `experience-methods`（方法调用）。
   - **目标岗位对齐**：`target-positions` →（弱匹配 `考试类型`/`所属科目`）→ `knowledge-points` / `past-exam-questions`。

> `practice-records` 仅在错题分析需要逐题流水时读取，且须标注样本量。

## 计划制定规则

制定当日公考计划时，以 `daily-study-plan` 为计划载体（字段：`日期` / `学习科目` / `学习内容` / `计划时长(分钟)` / `实际时长(分钟)` / `正确率` / `完成状态` / `备注`），遵守以下规则：

1. **优先安排高频、重复、影响大的薄弱项**。具体优先级排序：
   1. `knowledge-points.下次复习` ≤ 今天（到期复习，间隔复习不可中断）；
   2. `exam-patterns.复习优先级` 高 ∧ `考查频率` / `近5年出现频次` 高的高频考点（经 `关联知识点` 落到具体知识点）；
   3. 重复错误的薄弱项：`knowledge-points.掌握状态` 弱 ∧ `正确次数` 低 ∧ 在 `past-exam-questions` 中反复出现且常错（经 `关联真题` 反查）；
   4. `knowledge-points.重要程度` 高但 `学习次数` 低的新增推进项；
   5. 其余按 `所属科目` / `子模块` 均衡推进。
2. **时长预算参考目标岗位约束**：`target-positions.竞争比` / `历年分数线` 越高，当日总时长与薄弱科目配比越高；`招录人数` 越少，对薄弱项容错越低、补漏权重越高。但目标岗位信息**仅用于辅助优先级**，不替代正式招录信息核验。
3. **参考历史执行**：读取近期 `daily-study-plan` 的 `计划时长(分钟)` vs `实际时长(分钟)` 偏差与 `完成状态`，避免计划时长系统性偏离实际可投入时长。
4. **方法调用**：涉及具体题型/模块时，从 `experience-methods` 按 `分类` / `适用场景` / `标签` 检索方法，优先 `实用程度` 高的，写入计划 `备注` 或 `学习内容`。
5. **可执行粒度**：每条计划应可在一日内完成并回填 `实际时长(分钟)` / `正确率` / `完成状态`；不得输出无法度量完成情况的笼统计划。
6. **不臆造未学内容**：新增推进项必须对应 `knowledge-points` 中真实存在的知识点，不得凭空生成知识点名称。

## 错误分析规则

分析错题与错误模式时，遵守以下规则：

1. **按五类归因分类**：每条错题的 `错因分析` 应归入以下类别之一（或并标注多类）：
   - **知识**：知识点不熟/缺失（对应 `knowledge-points.掌握状态` 弱、`关联知识点` 指向的知识点 `正确次数` 低）；
   - **方法**：解题思路/方法不当（对应 `exam-analysis.解题思维路径` 偏差、`experience-methods` 中有更优方法）；
   - **审题**：题干理解/条件遗漏（对应 `common-traps` 中的 `陷阱类型` / `错误思路`）；
   - **时间**：用时不足导致仓促（对应 `past-exam-questions.用时(秒)` / `practice-records.用时(秒)` 显著低于该题型常规用时）；
   - **策略**：时间分配/放弃决策失误（基于整卷用时分布与 `daily-study-plan` 时间执行偏差判断）。
2. **不只统计错误数量，还要检查重复错误**：除统计各 `题型` / `所属科目` 的错误数外，必须沿 `关联知识点` 聚合同一知识点的错误，识别“同一知识点反复错”的重复错误模式；重复错误的优先级高于零散错误。
3. **结合多源数据**：错题分析必须结合刷题记录、知识点、易错陷阱和真题解析四类来源：
   - `practice-records` / `past-exam-questions`（错题本身，含 `错因分析` / `用时(秒)`）；
   - `knowledge-points`（经 `关联知识点`，看 `掌握状态` / `正确次数` / `记忆阶段`）；
   - `common-traps`（经 `典型真题`，看 `陷阱类型` / `错误思路` / `正确思路` / `防范口诀`）；
   - `exam-analysis`（经 `关联真题`，看 `常见错误分析` / `思维层次` / `变式训练方向`）。
4. **分析成绩时同时考虑正确率、耗时和题型**：评价某题型/科目表现时，必须同时报告：
   - 正确率（`结果` 为对的比例，或 `daily-study-plan.正确率`）；
   - 耗时（`用时(秒)` 的集中趋势与离散度）；
   - 题型（`题型`）与科目（`所属科目`）分布。
   不得仅凭正确率下结论——高正确率但耗时过长同样需要改进，低正确率但仅 1 道题不能代表水平。
5. **样本量声明**：任何统计必须声明所基于的样本量。`practice-records` 仅 1 条时，禁止以其得出错误分布结论，须改用 `past-exam-questions` 并声明其样本量与年份范围。
6. **归因到可改进项**：每条错题归因后，应给出可执行的改进指向（复习某知识点 / 采用某方法 / 注意某陷阱 / 调整某策略），不得止步于“做错了”。

## 时间范围处理

1. **以读取时的实际日期为“今天”**：`knowledge-points.下次复习` 是否到期、`daily-study-plan.日期` 是否为“最近”、`practice-records.日期` 是否为“近期”，一律以 AI 实际读取数据时的日期为准，不得使用训练数据中的固定日期或假设日期。
2. **stale 数据须声明**：若 `status.json.is_stale: true`，输出中必须声明“当前展示的是上一次成功版本（`last_success_at`），最近一次同步失败”，不得将 stale 数据当作实时数据呈现。
3. **“最近/近期”需明确窗口**：当用户问“最近刷题表现”时，须先说明采用的窗口（如最近 7 天 / 最近 N 条），且窗口内样本不足时按“数据不足时的处理”执行。
4. **年份字段处理**：`past-exam-questions.年份` 是真题的年份属性，`exam-patterns.近5年出现频次` 中的“5 年”是相对统计口径；使用时应结合数据中实际出现的年份范围说明覆盖区间，不得假定覆盖到当前年份。
5. **复习节奏字段**：`knowledge-points.上次复习` / `下次复习` 是间隔复习建议时间，不是硬性日程；判断“过期”时按日历日比较，但表述为“建议复习已到期”而非“必须执行”。

## 数据不足时的处理

当数据不足以支撑某项结论时，按以下规则处理：

1. **`practice-records` 样本不足（仅 1 条）**：
   - 不以其做错误类型分布、正确率、用时分布等统计；
   - 错题统计改用 `past-exam-questions`（128 条），并声明样本量；
   - 日级表现改用 `daily-study-plan`（40 条），并声明覆盖的日期范围。
2. **`exam-analysis` 覆盖不足（14 / 128）**：
   - 当某真题无对应深度解析时，明确说明“该题暂无深度解析”，不得用其他题的解析强行套用；
   - 不得以“有解析的题”代表“全部真题”的难度/思路分布。
3. **关联字段缺失**：当 `关联知识点` / `关联真题` / `典型真题` 为空时，不得强行归因；应标注“该记录未关联知识点/真题，无法沿关系遍历”。
4. **跨表匹配无结果**：当基于“考试类型/科目”的弱匹配无命中时，不得放宽匹配口径强行匹配；应说明“未找到与目标岗位考试类型对齐的知识/真题记录”。
5. **样本量阈值**：任何统计结论须基于不少于一定样本（建议 ≥ 5 条）才可给出方向性判断；低于阈值时只描述事实（如“近 7 天仅有 2 条计划记录”），不下趋势性结论。
6. **主动声明而非沉默**：数据不足时必须显式声明限制，不得用模糊措辞掩盖样本不足；宁可给出“目前数据不足以回答”也不可编造。

## 禁止推断

AI 在使用本项目数据时，**禁止**做出以下推断（与 `summary.md` 的“不应做出的推断”一致）：

1. **禁止以 `practice-records` 断言总体水平**：仅 1 条记录，不得得出“擅长/不擅长某题型”“近期正确率 X%”“刷题表现趋势”等总体结论。
2. **禁止把 `target-positions` 当作正式招录信息**：竞争比、分数线、招录人数、专业/学历/基层经历要求仅为备考参考，**不替代正式招录信息核验**；不得据此判断报考资格或岗位真实性。
3. **禁止假定关联字段必然有值**：`关联知识点` / `关联真题` / `典型真题` 可能为空，不得对未关联的记录强行归因。
4. **禁止假定跨表科目取值一致**：`所属科目` / `学习科目` / `所属模块` / `子模块` 在不同表中口径可能不同；跨表匹配前须比对实际取值集合，不得假定统一。
5. **禁止把 `exam-patterns` 频次当作命题概率预测**：`近5年出现频次` / `考查频率` 是历史描述，不得转化为“今年必考”“出现概率 X%”。
6. **禁止把间隔复习字段当作硬性日程**：`下次复习` 等是个人复习节奏建议，不是必须执行的合约。
7. **禁止在不检查 `is_stale` 的情况下假定数据最新**：须先读 `status.json`，stale 时须声明。
8. **禁止凭空生成知识点/真题/岗位**：所有引用的实体必须存在于对应表的真实记录中；不得为满足计划或归因需要而虚构知识点名称、真题题号或岗位。
9. **禁止从公开数据反推飞书源表结构**：公开数据受视图与字段白名单裁剪，不代表飞书 Base 的完整结构，不得推断未公开的表或字段。
10. **禁止跨项目合并分析**：不得将本项目数据与 `learning-english` 等其他项目数据混合得出结论。

## 输出要求

1. **声明数据来源与样本量**：每项分析结论须标注所基于的表、字段与样本量（如“基于 `past-exam-questions` 128 条，其中错误 N 条”）。
2. **声明时效与 staleness**：若 `is_stale: true`，输出开头须声明；涉及“最近/到期”等判断须说明所采用的“今天”日期与时间窗口。
3. **给出可遍历的引用**：引用具体记录时，优先给出记录 ID 或可定位的字段值（如真题 `ID`、知识点 `知识点` 名称、岗位 `岗位名称`），便于用户核对。
4. **结论分级**：区分“事实陈述”（直接来自数据）、“统计观察”（基于聚合）、“建议”（基于规则推断），不得混为一谈。
5. **计划类输出格式**：当日计划须包含 `日期` / `学习科目` / `学习内容` / `计划时长(分钟)`，并说明排定理由（到期/高频/薄弱/新增），以及可回填字段（`实际时长(分钟)` / `正确率` / `完成状态`）。
6. **错题类输出格式**：每条错题分析须包含 `题型` / `所属科目` / `错因分类`（知识/方法/审题/时间/策略）/ `关联知识点` / `改进指向`，重复错误须单独标注。
7. **不越界**：输出不得包含禁止推断清单中的任何内容；遇到不适用任务时，明确说明原因并转人工或转官方信息源。
8. **语言**：面向用户的输出使用中文；字段名与表名保留原始中文/英文 slug 形式以便核对。
