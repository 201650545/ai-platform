# 英语学习系统

**Slug:** `learning-english`

**项目分组:** learning

**同步层级:** hourly（每小时第 17 分钟同步）

**数据规模:** 9 张数据表，共 8,019 条记录（2026-08-11 manifest 实测）

---

## 项目用途

本项目是一个个人英语学习的完整数据系统，从飞书多维表格（Bitable）公开导出，供 AI 工具和其他消费者读取数据模型、记录和表间关联，无需飞书访问权限。

系统覆盖英语学习的完整闭环：词汇积累、文本阅读、计划制定、学习执行、测验记录、能力追踪和错误改进。数据以静态 JSON 形式部署在 GitHub Pages 上，每小时自动同步一次。

核心使用者是 AI 代理——它读取这些数据来回答学习者关于"今天该复习什么"、"最近学得怎么样"、"哪类错误反复出现"等问题，并据此制定当天的英语学习计划。

---

## 核心目标

1. **词汇掌握追踪**：记录 6000 个单词的学习状态、记忆阶段、复习间隔和测验正确率，支撑间隔重复（Spaced Repetition）决策。
2. **文本输入管理**：管理阅读文本库，追踪每篇文本的词汇覆盖率和生词暴露情况，为选择合适难度的阅读材料提供依据。
3. **学习计划与执行**：将学习目标分解为每日计划和具体任务，追踪完成状态、延迟和迁移情况。
4. **测验与日志记录**：记录每次测验的方向、维度、结果和检测方式，形成可回溯的学习日志。
5. **能力状态监控**：按能力维度（听、说、读、写、词汇、语法等）追踪当前等级、稳定度和连续成功/失败次数。
6. **错误归因与改进**：记录错误类型、原始错误、正确形式、原因解释和改进策略，追踪错误的重复次数和解决状态。
7. **词义与表达块积累**：区分词条、词义和表达块三个层次，积累典型搭配、句型框架和语用说明。

## 表之间的关系

表间关系通过飞书 Bitable 的关联字段实现。以下关系已从 schema 中的关联字段确认：

```
vocabulary.关联文本 ────────────→ text-library
vocabulary.学习日志 ────────────→ learning-log
learning-log.关联单词 ──────────→ vocabulary
daily-plan.单词列表(link) ──────→ vocabulary
```

### 关系说明

| 来源表 | 关联字段 | 目标表 | 说明 |
|---|---|---|---|
| `vocabulary` | `关联文本` | `text-library` | 单词关联到出现过该词的阅读文本 |
| `vocabulary` | `学习日志` | `learning-log` | 单词关联到涉及该词的测验记录 |
| `learning-log` | `关联单词` | `vocabulary` | 测验记录关联到被测的单词（与上条为双向关联） |
| `daily-plan` | `单词列表(link)` | `vocabulary` | 每日计划通过 link 字段关联到当日要学的单词 |

### 未确认的关系

`lexical-units`（词义与表达块）表没有显式的关联字段指向 `vocabulary`。虽然语义上词义块可能与词条相关，但 schema 中不存在确认的关联字段。**不应假设两者之间存在显式关联**，除非后续 schema 更新中新增了关联字段。

## 常见分析问题

### 1. 哪些词需要复习？

**数据来源：** `vocabulary` 表

**判断方法：**
- 筛选 `下次复习` 字段 <= 当前日期的记录，这些是已到期的复习任务
- 结合 `掌握状态` 和 `记忆阶段` 判断紧迫程度
- `上次测验` 距今较久且 `正确次数` 较低的词优先级更高
- 优先处理 `记忆阶段` 处于早期（巩固阶段）的词

**注意：** 当前日期应以数据的 `generated_at`（见 manifest.json 或 status.json）为基准，而非 AI 工具的系统时钟，因为数据是快照而非实时。

### 2. 最近学习了什么？

**数据来源：** `learning-log` 表、`vocabulary` 表、`study-sessions` 表

**判断方法：**
- `learning-log` 按 `日期` 倒序排列，查看最近的测验记录
- `vocabulary` 按 `上次测验` 倒序排列，查看最近测验过的单词
- `study-sessions` 按 `日期` 倒序，查看最近的学习会话总结
- 结合 `learning-log.测验方向` 和 `测验维度` 了解最近练习的重点

### 3. 哪类错误重复出现？

**数据来源：** `error-remediation` 表

**判断方法：**
- 按 `重复次数` 降序排列，找出高频重复错误
- 按 `错误类型` 分组统计，识别最常犯的错误类别
- 关注 `是否已解决` 为否且 `最近出现日期` 较近的错误
- 对比 `首次出现日期` 和 `最近出现日期`，判断错误是否持续存在

**注意：** `error-remediation` 表有 52 条记录，样本适中，但分布可能集中在少数错误类型，不应过度泛化。

### 4. 学习计划是否完成？

**数据来源：** `daily-plan` 表、`study-tasks` 表

**判断方法：**
- `daily-plan` 按 `日期` 查找当日计划，检查 `完成状态`
- `study-tasks` 按 `计划日期` 筛选当日任务，检查 `状态` 和 `完成度`
- 关注 `是否延迟任务` 和 `是否迁移任务`，了解任务执行的健康度
- `daily-plan.正确率` 反映当日学习质量

### 5. 能力状态如何？

**数据来源：** `competency-state` 表

**判断方法：**
- 按 `能力维度` 查看 `当前等级` 和 `稳定度`
- `连续失败次数` > 0 的维度需要重点关注
- `下次复习时间` 已到期的维度需要安排测试
- `新语境通过次数` 和 `自由产出通过次数` 较低的维度，说明该能力尚未在真实场景中验证

### 6. 如何制定当天英语计划？

**数据来源：** 综合多张表

**制定逻辑：**
1. 从 `vocabulary` 筛选 `下次复习` 到期的单词 → 确定复习量
2. 从 `study-tasks` 筛选 `计划日期` 为今天且 `状态` 非完成的任务 → 确定任务量
3. 从 `competency-state` 筛选 `下次复习时间` 到期的维度 → 确定能力训练重点
4. 从 `error-remediation` 筛选 `是否已解决` 为否的高频错误 → 安排针对性练习
5. 从 `text-library` 筛选 `使用状态` 可用的文本 → 安排阅读输入
6. 综合以上信息，平衡输入（阅读/听力）、检索（测验/回忆）、输出（造句/写作）和技能训练（听说读写）

## 推荐读取顺序

AI 代理在分析本项目数据时，推荐按以下顺序读取：

| 步骤 | 文件/表 | 目的 |
|---|---|---|
| 1 | `manifest.json` | 了解项目结构：有哪些表、各表记录数和校验和 |
| 2 | `schema.json` | 了解数据模型：字段类型、选项值和表间关联 |
| 3 | `status.json` | 确认数据新鲜度：`sync_status`、`is_stale`、`last_success_at` |
| 4 | `vocabulary` | 核心数据：筛选到期复习词、评估掌握状态 |
| 5 | `study-tasks` | 查看待办任务：筛选今日计划任务、检查延迟和迁移 |
| 6 | `competency-state` | 了解能力分布：查看各维度等级和稳定度 |
| 7 | `daily-plan` | 查看今日计划：确认完成状态和正确率 |
| 8 | `learning-log` | 回顾近期测验：按日期倒序查看结果 |
| 9 | `error-remediation` | 识别顽固错误：按重复次数排序 |
| 10 | `text-library` | 选择阅读材料：按词汇覆盖率和难度筛选 |
| 11 | `lexical-units` | 补充表达学习：查看队列状态和重要性 |
| 12 | `study-sessions` | 了解学习节奏：查看会话历史和时长分配 |

**原则：** 先读元数据（manifest/schema/status），再读核心数据（vocabulary/study-tasks），最后读辅助数据（text-library/lexical-units/study-sessions）。根据具体问题跳过不相关的表。

## 数据更新时间与时效性

### 同步频率

- **同步层级：** `hourly`（每小时同步一次）
- **触发时间：** 每小时第 17 分钟（UTC），由 GitHub Actions `sync-hourly.yml` 执行
- **数据延迟：** 最长约 1 小时（从飞书数据变更到公开 JSON 更新）

### 如何判断数据新鲜度

1. 读取 `status.json` 中的 `last_success_at` 字段，确认最近一次成功同步时间
2. 检查 `is_stale` 字段：`true` 表示当前展示的是上一次成功版本，最近一次同步尝试失败
3. 检查 `sync_status` 字段：`ok` 表示正常，`failed` 或 `stale` 表示有异常
4. 读取 `manifest.json` 中的 `generated_at` 字段，确认数据生成时间
5. `build_id` 字段（格式 `<时间戳>-<短SHA>`）可用于版本追踪

### 时效性注意事项

- 数据是**快照**而非实时流，分析时应以数据中的时间戳为准
- 判断"今天"时，应基于 `generated_at` 或 `last_success_at`，而非 AI 工具的系统时钟
- 若 `is_stale: true`，应在输出中提示数据可能不是最新的
- `vocabulary.下次复习` 等日期字段是同步时写入的快照值，不反映同步后的状态变化

## 数据公开范围

### 导出范围控制

| 控制层 | 机制 | 说明 |
|---|---|---|
| 视图级 | 仅导出 `AI 公开导出` 视图 | 没有此视图的表不会被导出 |
| 字段级 | 显式字段白名单 | 每张表在项目 YAML 中配置允许导出的字段，禁止通配符 |
| 内容级 | 安全扫描 | 写入和部署前双重扫描敏感信息、Token、PII 和高熵字符串 |

### 公开标志字段

项目配置中 `privacy.require_public_flag: false`，意味着**不要求**记录级别的"是否公开"标志即可导出。但以下 4 张表包含 `是否公开` 字段：

- `lexical-units`（词义与表达块）
- `study-sessions`（学习会话）
- `study-tasks`（计划任务）
- `competency-state`（能力状态）

该字段的存在表明这些表的部分记录可能标记了公开状态，但由于 `require_public_flag: false`，该字段目前作为信息记录而非过滤条件。AI 分析时可将 `是否公开` 作为参考信息，但不应假设未标记公开的记录被排除在外。

### 不公开的数据

以下内容**绝不会**出现在公开导出中：

- 飞书凭据（app_id、app_secret、tenant_access_token）
- 飞书内部标识符（app_token、table_id）
- 敏感个人信息（手机号、身份证、邮箱、银行卡）
- 不在字段白名单中的字段
- 没有 `AI 公开导出` 视图的表

## 已知限制

### 数据规模限制

| 表 | 记录数 | 限制说明 |
|---|---|---|
| `study-sessions` | 7 | 记录较少，无法进行稳健的趋势分析，仅可作为个案参考 |
| `error-remediation` | 52 | 样本量适中，但可能集中于少数错误类型 |
| `daily-plan` | 9 | 仅覆盖少量日期，无法反映长期计划执行情况 |
| `text-library` | 42 | 文本库规模有限，选择空间受限 |

### 结构限制

- `lexical-units` 与 `vocabulary` 之间**没有显式关联字段**，无法直接查询某个词的词义块
- `study-sessions` 与 `study-tasks` 之间**没有显式关联字段**，无法直接查询某个会话包含哪些任务
- `daily-plan` 的 `单词列表` 字段与 `单词列表(link)` 字段可能存在冗余，需注意区分文本字段与 link 关联字段
- `competency-state` 的 `能力维度` 值域未在 schema 中枚举，需从数据中推断

### 时效性限制

- 数据是每小时同步的快照，**不是实时数据**
- 同步失败时展示的是旧版本（`is_stale: true`），可能滞后数小时
- 日期字段（如 `下次复习`、`上次测验`）是快照值，同步后实际状态可能已变化

### 内容限制

- 无音频数据，无法提供发音指导
- `我的造句` 和 `修改后句子` 等字段为自由文本，质量和完整性可能不均
- `掌握维度`、`检测方式` 等字段的值域可能不统一
- `学习日志` 字段（vocabulary 表）为文本类型，格式可能不结构化

---

## 不应做出的推断

1. **不应将"看过"等同于"掌握"**：`学习次数` 高不代表掌握状态好，必须参考 `掌握状态`、`记忆阶段` 和 `正确次数`。

2. **不应根据单次正确就断言长期掌握**：一次测验正确（`learning-log.结果` 为正确）不等于该词已长期掌握，需结合 `连续成功次数` 和 `稳定度` 判断。

3. **不应假设 `lexical-units` 与 `vocabulary` 存在显式关联**：schema 中没有关联字段，任何关于词义块与词条关系的推断都是不可靠的。

4. **不应从稀疏数据推断趋势**：`study-sessions`（7 条）、`daily-plan`（9 条）的样本量太小，不应据此做出趋势性结论；`error-remediation`（52 条）也需谨慎。

5. **不应假设数据完整覆盖所有学习活动**：可能存在未记录的学习活动，数据只反映已录入飞书表格的部分。

6. **不应将 `competency-state` 的等级直接等同于 CEFR 或其他外部标准**：`当前等级` 是项目内部的自定义分级，未在 schema 中映射到外部标准。

7. **不应假设 `是否公开` 字段控制了导出过滤**：由于 `require_public_flag: false`，该字段是信息性的，不作为过滤条件。

8. **不应假设时间字段的时区**：除非 schema 明确标注时区，日期字段可能使用本地时间（UTC+8）或 UTC，分析跨日数据时需谨慎。

9. **不应根据 `词汇覆盖率` 单独判断文本适合性**：还需结合 `难度等级`、`适用词带` 和 `生词暴露数` 综合判断。

10. **不应推断同步间隔内的状态变化**：数据是每小时快照，同步间隔内的学习活动（如刚刚完成的测验）可能尚未反映在数据中。
