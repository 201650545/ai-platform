# AI 使用规则

本文件规定 AI 代理在分析 `learning-english` 项目数据时必须遵守的规则。所有规则基于真实 schema 和 manifest 数据制定，不依赖任何虚构字段或关系。

---

## 适用任务

本项目的数据适合以下 AI 任务：

1. **复习调度建议**：根据 `vocabulary.下次复习`、`掌握状态`、`记忆阶段` 筛选到期单词，生成当日复习清单。
2. **学习计划制定**：综合词汇复习、计划任务、能力状态和错误改进，生成当天的英语学习计划。
3. **学习进度分析**：基于 `learning-log`、`vocabulary.学习次数`/`正确次数`、`competency-state` 分析近期学习进展。
4. **错误模式识别**：基于 `error-remediation` 识别高频重复错误和未解决错误。
5. **计划执行评估**：基于 `daily-plan.完成状态`、`study-tasks.状态`/`完成度` 评估计划执行情况。
6. **能力短板诊断**：基于 `competency-state` 的 `连续失败次数`、`稳定度`、`当前等级` 识别薄弱能力维度。
7. **阅读材料推荐**：基于 `text-library` 的 `难度等级`、`词汇覆盖率`、`使用状态` 推荐合适文本。
8. **学习总结生成**：基于多张表的综合数据，生成日/周学习总结。

---

## 不适用任务

本项目的数据**不适合**以下任务，AI 代理应拒绝或明确说明限制：

1. **实时测验与评分**：数据是每小时同步的快照，不支持实时交互式测验。
2. **发音指导**：数据中无音频字段（仅有 `音标` 文本），无法提供发音示范或语音反馈。
3. **通过公开数据写入飞书**：GitHub Pages 公开导出是只读的，AI 代理不能通过公开数据修改飞书。若需写回（登记测验结果、更新每日计划、调整 `下次复习` 等），须使用 lark-cli 等飞书 API 工具直接操作飞书，属 write 级操作、需用户确认，且与公开导出是两个通道。
4. **长期趋势预测**：`study-sessions`（7 条）、`error-remediation`（52 条）、`daily-plan`（9 条）等表样本量偏小，不支持可靠的统计趋势预测。
5. **CEFR 等外部标准映射**：`competency-state.当前等级` 是项目内部自定义分级，未映射到 CEFR、雅思、托福等外部标准。
6. **词义块与词条的关联查询**：`lexical-units` 与 `vocabulary` 之间无显式关联字段，无法进行关联查询。
7. **同步间隔内的状态查询**：数据每小时同步一次，无法查询最近一小时内的实时状态变化。

## 分析优先级

AI 代理在处理学习相关请求时，应按以下优先级组织分析：

### 第一优先级：已到期复习任务

- 数据源：`vocabulary` 表（`下次复习` 或 `下次复习时间`）
- 筛选条件：`下次复习` <= 当前日期（以 `generated_at` 为基准）
- 附加排序：`记忆阶段` 处于早期阶段优先，`正确次数` 较低优先，`遗忘累计` 较高优先
- 调度依据：已接入 FSRS 的单词参考 `FSRS稳定度`/`复习轮次`；未接入的按冷启动轨迹
- 理由：间隔重复系统中到期未复习的词遗忘风险最高，应最先处理

### 第二优先级：延迟和未完成的计划任务

- 数据源：`study-tasks` 表
- 筛选条件：`状态` 非完成，或 `是否延迟任务` 为是，或 `计划日期`/`截止时间` 已过且 `完成度` < 100%
- 理由：延迟任务会累积债务，应优先清理

### 第三优先级：能力短板与连续失败

- 数据源：`competency-state` 表
- 筛选条件：`连续失败次数` > 0，或 `稳定度` 较低，或 `下次复习时间` 已到期
- 理由：连续失败表明该能力维度存在系统性问题，需要针对性训练

### 第四优先级：高频重复错误

- 数据源：`error-remediation` 表
- 筛选条件：`重复次数` 较高且 `是否已解决` 为否
- 理由：重复出现的错误是顽固错误，需要专项突破
- 注意：该表有 52 条记录，分析结果应作为定性参考而非统计结论

### 第五优先级：近期学习总结

- 数据源：`learning-log`、`study-sessions`、`vocabulary.上次测验`
- 筛选条件：按日期倒序，取最近 N 条
- 理由：帮助学习者回顾近期学习情况，维持学习动力

## 读取顺序

AI 代理应按以下顺序读取数据，以最高效率获取决策所需信息：

```
1. status.json          → 确认数据新鲜度（is_stale, last_success_at）
2. manifest.json        → 了解表结构和记录数
3. schema.json          → 了解字段类型和表间关联
4. vocabulary           → 筛选到期复习词（核心数据，6000 条）
5. study-tasks          → 筛选今日待办和延迟任务（588 条）
6. competency-state     → 查看能力短板（646 条）
7. daily-plan           → 查看今日计划完成情况（9 条）
8. learning-log         → 回顾近期测验（352 条）
9. error-remediation    → 识别顽固错误（52 条）
10. text-library        → 选择阅读材料（42 条）
11. lexical-units       → 补充表达学习（323 条）
12. study-sessions      → 了解学习节奏（7 条）
```

**原则：**
- 始终先读 `status.json` 确认数据可用性，再读业务数据
- 根据具体问题跳过不相关的表，避免全量加载
- `vocabulary` 表有 6000 条记录，应使用筛选条件而非全量遍历

## 记忆策略调度规则（FSRS + 消退提示）

本项目的复习调度遵循 **FSRS 间隔重复** 与 **消退提示（fading cue）** 两套机制，AI 在给出复习建议时必须遵守以下规则：

### 规则 1：调度字段语义（新增于 2026-08-11）

| 字段（表） | 语义 | 用途 |
|---|---|---|
| `复习轮次`（learning-log / vocabulary） | 0–6：0=新词编码日，1-6=消退提示轮次 | 决定**题型与提示强度** |
| `下次复习时间`（learning-log / vocabulary） | FSRS 动态计算的 due | 决定**何时再见**（不硬编码 1/3/7/15/30 天） |
| `本次等级`（learning-log） | Again/Hard/Good/Easy，映射 FSRS 1/2/3/4 | 四级评分，驱动 D/S 更新 |
| `FSRS难度` D（1-10）/ `FSRS稳定度` S（天数） | 单词记忆强度参数 | FSRS-6 更新算法输入 |
| `连续答对次数` / `连续答错次数` | 当前连续正确/错误计数 | 判断回退与 re-learning 触发 |
| `遗忘累计`（lapse_total） | 该词总 lapse 次数 | 30 天 ≥3 次 → 困难词干预 |
| `间隔天数` / `计划间隔天数` | 距上次复习天数 / 本次原计划间隔 | 记录实际 vs 计划偏差 |

**核心**：「复习轮次」与「下次复习时间」是两个独立变量——round 管题型/提示强度，next_review_at 管间隔。

### 规则 2：数据架构职责

- `learning-log` = **事实源（append-only）**：每条测验/复习都追加记录，不回改历史。
- `vocabulary` = **当前状态快照**：同步 learning-log 的最新值（轮次/D/S/连续计数/遗忘累计）。
- `competency-state` = **聚合能力估计**：按能力维度 weighted Beta 聚合，**不能反推单个单词的复习间隔**。

### 规则 3：回退与 re-learning

- 复习轮次递增：R1→R2→…→R6，**答错退回上一轮（round-1）**。
- 连续 2 次正式复习 `Again` → 进入 relearning（重新 R1）。
- 30 天内 `遗忘累计` ≥ 3 → 标记为困难词，进入专项干预。

### 规则 4：R6 不是毕业

- 第 6 轮成功后可进入 **maintenance 维护期**，继续 FSRS 长期维护（60/100/200 天级）。
- 不能因到达 R6 就停止调度。

### 规则 5：中译英提前到 R3

- R3 起固定加入 **中英→拼写 自由产出**，带提示阶梯（语义提示→首字母→3选1→2选1），记录提示级别。
- 历史数据证实：理解端（英中释义 97.2%）远强于生产端（中英拼写 80.7%），生产端需要更多轮次与提示强度。

### 规则 6：同日重测不计正式间隔

- 同日多次测验是「记忆还热着」的产物，正确率虚高，**不计入正式间隔调度**。
- 聚合能力估计时同日任务权重 ×0.5。

### 规则 7：FSRS 参数未拟合前用冷启动轨迹

- 在累积 ~1000 条正式 review 数据前，FSRS 参数按官方默认值；`下次复习时间` 优先参考 `计划间隔天数` 的冷启动参考轨迹（1/3/7/15/30 天级）。

### 规则 8：旧词诊断（legacy_unverified）

- 2026-07 之前的词汇数据大多未经复习闭环验证（96% 词仅测 1 次、94.6% 停在阶段0），应标记 `legacy_unverified`。
- 对这类词建议批量做 R4 自由回忆诊断，区分「真掌握」与「看过而已」，不要直接计入掌握词汇。

## 计划制定规则

AI 代理在制定当天英语学习计划时，必须遵守以下规则：

### 规则 1：优先处理已到期复习任务

- 从 `vocabulary` 筛选 `下次复习` 到期的单词
- 到期复习任务的优先级高于新词学习和能力训练
- 复习量应根据近期 `daily-plan.复习词数` 和 `正确率` 动态调整

### 规则 2：不把"看过"直接当作"掌握"

- 判断掌握状态必须使用 `掌握状态` 和 `记忆阶段` 字段
- `学习次数` 高不等于掌握，必须结合 `正确次数` 和 `上次测验` 结果
- 仅被"暴露"过（出现在 `text-library.覆盖词汇列表` 中）但未经过测验的词，不应计入已掌握词汇

### 规则 3：优先使用延迟回忆和能力状态

- 判断能力水平时，优先参考 `competency-state` 的 `当前等级`、`稳定度`、`连续成功次数`
- 优先参考 `新语境通过次数` 和 `自由产出通过次数`（延迟回忆和真实运用），而非即时的 `learning-log` 结果
- `learning-log` 中的即时测验结果仅作为辅助参考

### 规则 4：兼顾输入、检索、听说读写和输出

制定计划时应平衡以下维度：

| 维度 | 数据来源 | 说明 |
|---|---|---|
| 输入 | `text-library`（阅读）、`study-sessions.输入分钟` | 通过阅读文本获取语言输入 |
| 检索 | `vocabulary`（复习测验）、`learning-log` | 通过回忆和测验强化记忆 |
| 听说读写 | `competency-state.能力维度`、`study-tasks.训练维度` | 覆盖四项技能 |
| 输出 | `vocabulary.我的造句`、`lexical-units.我的例句`、`study-sessions.输出分钟` | 通过造句和写作练习产出 |

- 不应只安排词汇复习而忽略阅读输入和技能训练
- 不应只安排输入而忽略检索测验和输出练习

### 规则 5：区分词条、词义和表达块

三个层次的学习单位有不同的数据来源和分析方式：

| 层次 | 数据来源 | 关键字段 | 说明 |
|---|---|---|---|
| 词条 | `vocabulary` | `单词`、`词性`、`最简中文` | 单词级别的记忆和复习 |
| 词义 | `lexical-units`（`学习单位类型` 为词义时） | `中文释义`、`英文释义`、`典型搭配` | 同一词的不同释义 |
| 表达块 | `lexical-units`（`学习单位类型` 为表达块时） | `句型框架`、`使用语域`、`语用说明` | 固定搭配和句型 |

- 制定计划时不应混淆三个层次
- `vocabulary` 和 `lexical-units` 之间无显式关联，不应假设关联关系

### 规则 6：考虑错误改进

- 从 `error-remediation` 筛选 `是否已解决` 为否的高频错误
- 将错误相关的练习纳入计划
- 注意该表有 52 条记录，分析结论应标明样本量限制

### 规则 7：参考历史执行情况

- 参考 `daily-plan` 的 `完成状态` 和 `正确率`，避免计划过载
- 参考 `study-tasks` 的 `是否延迟任务` 和 `是否迁移任务`，了解计划执行的健康度
- 若近期延迟任务较多，应适当减少新任务量

## 错误分析规则

### 规则 1：使用 `error-remediation` 表作为主要数据源

- 按 `重复次数` 降序识别高频错误
- 按 `错误类型` 分组统计错误分布
- 关注 `是否已解决` 为否且 `最近出现日期` 较近的错误

### 规则 2：交叉验证

- 将 `error-remediation.错误类型` 与 `learning-log` 中的错误记录交叉验证
- 将 `competency-state.最近错误类型` 与 `error-remediation` 对照，确认能力短板与错误模式的一致性

### 规则 3：不过度泛化

- `error-remediation` 表有 52 条记录，分析结论必须标明样本量限制
- 不应根据少量错误推断学习者的整体能力水平
- 不应假设已记录的错误覆盖了所有错误类型

### 规则 4：区分已解决和未解决

- `是否已解决` 为是的错误不应纳入当前改进计划
- 但可参考 `改进策略` 字段了解历史有效的改进方法

### 规则 5：不根据单次错误断言系统性问题

- 单次出现的错误可能是偶然失误
- 只有 `重复次数` >= 2 的错误才应被视为模式性问题
- 同时参考 `首次出现日期` 和 `最近出现日期`，判断错误是否持续

## 时间范围处理

### 规则 1：以数据快照时间为准

- "今天"的定义应以 `manifest.json` 的 `generated_at` 或 `status.json` 的 `last_success_at` 为基准
- **不应**使用 AI 工具的系统时钟作为"今天"的判断依据
- 若 `last_success_at` 距当前已超过 2 小时，应提示数据可能不新鲜

### 规则 2：处理 `is_stale` 状态

- 若 `status.json` 中 `is_stale: true`，表示当前数据是上一次成功同步的版本
- 输出中必须明确提示："数据可能不是最新的，最近一次同步尝试失败"
- 基于过期数据给出的计划建议应更加保守

### 规则 3：日期字段的时区

- 日期字段（如 `下次复习`、`上次测验`、`计划日期`）可能使用 UTC+8（北京时间）
- 跨日分析时应注意时区可能导致的日期偏移
- 若无法确定时区，应在输出中说明假设

### 规则 4：时间范围筛选

- 查询"最近"数据时，应在输出中明确时间范围（如"最近 7 天"）
- `learning-log.日期`、`vocabulary.上次测验`、`study-tasks.计划日期` 等字段用于时间筛选
- 注意部分记录的日期字段可能为空，空值不应被纳入时间范围筛选

### 规则 5：不推断同步间隔内的变化

- 数据每小时同步一次，同步间隔内的学习活动不会反映在数据中
- 不应假设"如果学习者刚完成了一次测验，数据中会立即更新"
- 若学习者声称完成了某项活动但数据中未体现，应说明可能是同步延迟

## 数据不足时的处理

### 规则 1：明确说明数据不足

当遇到以下情况时，AI 代理**必须**在输出中明确说明数据不足：

- 相关表的记录数为 0 或极少（如 `study-sessions` 仅 7 条）
- 筛选后的结果集为空（如今天没有到期的复习词）
- 关键字段为空值（如 `vocabulary.下次复习` 为空）

### 规则 2：不编造数据

- 数据不足时**绝不**编造记录或字段值
- **绝不**根据其他字段"推测"未提供的字段值
- **绝不**用训练知识填补数据空白

### 规则 3：说明影响

- 说明数据不足对分析结论的影响程度
- 例如："由于 `study-sessions` 仅有 7 条记录，无法分析学习会话的时间分配趋势"

### 规则 4：建议补充数据

- 在可能的情况下，建议学习者补充哪些数据可以改善分析
- 例如："建议在飞书表格中记录更多的学习会话，以便分析输入/输出的时间分配"

### 规则 5：区分"无数据"和"无问题"

- 筛选结果为空可能意味着"没有到期任务"（好事），而非"数据缺失"
- 应根据上下文判断空结果的含义，并在输出中正确解读

## 禁止推断

AI 代理**严禁**做出以下推断：

### 1. 禁止将"看过"等同于"掌握"

- `text-library.覆盖词汇列表` 中包含某词，仅表示该词在文本中出现过（被暴露）
- 不等于该词已被学习、已被测验或已被掌握
- 掌握判断必须基于 `vocabulary.掌握状态` 和 `记忆阶段`

### 2. 禁止根据单次正确断言长期掌握

- `learning-log` 中一次 `结果` 为正确，不等于该词/能力已长期掌握
- 长期掌握判断必须基于 `competency-state.连续成功次数`、`稳定度`、`间隔天数`
- 或基于 `vocabulary.正确次数` 与 `学习次数` 的比率

### 3. 禁止假设不存在的表间关联

- `lexical-units` 与 `vocabulary` 之间**无显式关联字段**，禁止假设关联
- `study-sessions` 与 `study-tasks` 之间**无显式关联字段**，禁止假设关联
- 只有 schema.json 中确认的关联字段才可用于关联查询

### 4. 禁止从稀疏数据推断趋势

- `study-sessions`（7 条）、`error-remediation`（52 条）、`daily-plan`（9 条）样本量偏小
- 禁止基于这些表做出趋势性、统计性结论
- 分析结论必须标明样本量限制

### 5. 禁止将内部等级映射到外部标准

- `competency-state.当前等级` 是项目内部自定义分级
- 禁止将其映射到 CEFR、雅思、托福、四六级等外部标准
- 禁止说"当前等级 3 相当于 CEFR B1"之类的推断

### 6. 禁止假设数据完整覆盖

- 数据只反映已录入飞书表格的学习活动
- 禁止假设所有学习活动都被记录
- 禁止根据"无记录"推断"未学习"

### 7. 禁止推断 `是否公开` 字段的过滤作用

- 项目配置 `require_public_flag: false`，`是否公开` 字段不作为导出过滤条件
- 禁止假设 `是否公开` 为否的记录被排除在导出之外
- 该字段仅作为信息记录

### 8. 禁止基于 `词汇覆盖率` 单独判断文本适合性

- `text-library.词汇覆盖率` 仅反映词汇覆盖比例
- 禁止仅根据该字段判断文本是否适合当前水平
- 必须结合 `难度等级`、`适用词带`、`生词暴露数` 综合判断

### 9. 禁止推断同步间隔内的状态

- 数据是每小时快照
- 禁止推断同步间隔内发生的学习活动对数据的影响
- 禁止假设数据反映的是"当前此刻"的状态

### 10. 禁止根据词频或常见度推断难度

- `vocabulary.难度等级` 是项目自定义的难度分级
- 禁止根据单词在英语中的常见度推断其 `难度等级`
- 禁止说"这个词很常见所以应该很简单"之类的推断

## 输出要求

### 规则 1：标注数据来源

- 每项分析结论必须标注数据来源（表名和字段名）
- 示例："根据 `vocabulary` 表，当前有 45 个单词的 `下次复习` 日期已到期"

### 规则 2：标注数据新鲜度

- 输出开头应说明数据的新鲜度
- 示例："本分析基于 `generated_at: 2026-07-26T06:35:53Z` 的数据快照，`sync_status: ok`"

### 规则 3：标注样本量限制

- 涉及稀疏表的分析必须标注样本量
- 示例："（注：`error-remediation` 表有 52 条记录，以下分析为定性参考）"

### 规则 4：标注不确定性

- 对不确定的结论使用"可能"、"建议"等措辞
- 避免使用绝对性表述（"一定"、"必然"）
- 对基于推断的结论，明确标注"推断"而非"事实"

### 规则 5：结构化输出

- 学习计划应按优先级排序（复习 > 任务 > 能力训练 > 错误改进 > 输入）
- 每项建议应包含：做什么、为什么（数据依据）、预计时长（参考 `study-tasks.预计时长分钟`）
- 总结性分析应分点列出，每点有明确的数据支撑

### 规则 6：区分事实和建议

- "事实"是数据中直接可见的信息（如"该词 `下次复习` 为 2026-07-25，已到期"）
- "建议"是基于数据的分析推断（如"建议优先复习该词"）
- 输出中应明确区分两者，不将建议伪装为事实

### 规则 7：使用项目术语

- 使用飞书表名和字段名的中文原名（如"掌握状态"、"记忆阶段"）
- 不自行翻译或改写字段名
- 引用 slug 时使用反引号（如 `vocabulary`、`study-tasks`）

### 规则 8：空结果的正确处理

- 筛选结果为空时，应明确说明"当前没有到期复习任务"而非省略该部分
- 空结果本身是有意义的信息（表示无需行动），不应被忽略
- 应进一步分析空结果的原因（如"所有单词均已复习"或"该字段为空"）
