# API 转发网关 · 四主题体系

> 每套都是一个完整的**世界观**，而非"白/蓝/黑"皮肤。共同讲述同一件事：
> **一个请求进入复杂世界，系统替它找到最合适的一条路。**
> 落地目标：在 `api_page.html` 上以新增 `data-style` 的形式并存（不另起主题系统）。

## 总览

| 主题 | 文件 | 核心世界 | 核心隐喻 | 性格 | 适用场景 |
|---|---|---|---|---|---|
| 黑白建筑极简 | `主题设置-黑白建筑极简.md` | 现代建筑 | 空间即秩序 | 理性、克制、专业 | 常驻工作台·长期工作 / 品牌默认 |
| 云海天舟 Cloudsea Ark | `主题设置-云海天舟.md` | 东方山水 | 航道即路由 | 空灵、自然、流动 | 展示·讲解 / 东方美学 |

## 共享绑定边界（落地时遵守，勿伪造动态加权）

- 四者都表达同一真实结构：**单一 alias（目的）→ 成员池 members → 渠道/渡口/星宿/侧厅节点**；
- 状态区分仍须真实：①模型成员冷却（`_model_cooldown` 30s）②渠道/凭据限流（rate_limit 的 open/throttled/blocked）③共享代理故障域熔断（fault_domains.is_tripped）；
- 防空头：禁止呈现“额度+延迟动态加权”等并未真实实现的机制；`select_members()` 现状仍按 members 原序返回。
