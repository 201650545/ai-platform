# 主题设置 · 星河枢机 / Celestial Relay

> **以星河为网络，以星轨为路由，以浑天仪为智能决策中枢。**
> 加入**东方观天哲学**：古人通过观星理解秩序，现代网关通过遥测理解系统 —— **观星 ≈ Observability**。
> 不是普通“太空科技 UI”，不是赛博朋克。核心气质：**深邃、秩序、宏大、精密、安静。**

整个天空本身就是拓扑。

## 视觉隐喻

| 业务概念 | 星河枢机隐喻 |
|---|---|
| 请求 | 划入星空的一颗流星 |
| alias | 需要解析的目标星位 |
| members | 不同星宿 |
| route | 星轨 |
| health | 星体是否明亮 |
| cooldown | 暂时黯淡的星体 |
| fault domain | 不同星域 |
| rate limit | 星轨承载能力 |
| fallback | 改变观测轨道 |
| route log | 最近星迹 |
| **浑天仪** | **Routing Intelligence 的物理化身**（不是 Provider 容器，是判断本身） |

## 为什么高级

一套主题同时解决三件事，三者自然成立：
1. **中式文化**——浑天仪、观星台、山海、星宿；
2. **AI 基础设施**——调度、遥测、观测、路由；
3. **宇宙尺度**——网关不是“一个后台工具”，而像一套运行于巨大网络中的基础设施。

## 构图

比「云海天舟」更暗、更聚焦。页面主体处于一座极高山巅观星台，下方仍是大片云海，**天空占据巨大面积**。
- 浑天仪不一定放正中央，可**略微偏下**，让银河成为真正最大的视觉主体。
- 各 Provider 就像星图标注，沿真实星轨自然散布：

```text
         Anthropic ·

OpenAI ·                 · Google

             ◉
           天枢

Moonshot ·               · Azure
```

- **空间关系比对称关系重要**，不是机械排列。

## UI 融合（尤其不能放普通 SaaS 卡片）

- **左侧导航**：直接成为观星台的一面深色建筑墙体，导航文字像刻度或铭牌。
- **顶部 KPI**：放在天空最安静的一片区域，只保留数字与极小的曲线：
  `12,480` REQUESTS / MIN　`99.2%` SUCCESS　`842 ms` LATENCY　`78%` QUOTA —— 像天文数据。
- **右侧 Telemetry**：不是悬浮玻璃，而是观星台建筑本身的一块**观测壁 / 星图墙**；实时波形像古代天文记录被现代化。
- **Admission Pipeline**：成为五道**同心观测刻度** `01 HEALTH / 02 COOLDOWN / 03 FAULT DOMAIN / 04 RATE LIMIT / 05 ROUTE`，甚至直接刻在浑天仪下方的平台上。UI 彻底进入世界。

## 配色

一定不能做成蓝紫霓虹。**90% 是低饱和蓝黑和灰**：

| 颜色 | 色值 | 用途 |
|---|---|---|
| 深夜蓝黑 | `#101820` | 背景 |
| 黛青 | `#24333B` | 次级块面 |
| 星雾灰 | `#68777E` | 辅助 |
| 月白 | `#DDDCD4` | 文字 |
| 暖星金 | `#C0A16C` | 星、路径、选中状态 |
| 极淡青光 | `#86A9A6` | 点缀 |

暖金只负责**星、路径、选中状态**。非蓝紫 RGB，比之高级。

## 字体

- 中文标题可稍有力量，带一点**碑刻、金石、天文仪器铭文**感：**星 河 枢 机**。
- 具体数据全部用现代无衬线或窄体数字。
- 形成：**古代器物铭文 × 现代观测仪器**。

## 动效（若落地为网页）

非常慢的动态：银河极慢移动；浑天仪几乎不可察觉地旋转；请求到来一颗微弱星光进入；经过 HEALTH / COOLDOWN / FAULT DOMAIN / RATE LIMIT 后某条星轨逐渐变亮；对应 Provider 星体亮起。fallback 时第一颗星慢慢暗下，另一条星轨接续点亮。

整个过程像：

> **一套天体系统正在做决定。**

而不是后台系统在播放 Loading Animation。
