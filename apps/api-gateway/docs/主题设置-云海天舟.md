# 主题设置 · 云海天舟 / Cloudsea Ark

> **以云海为网络，以舟行为请求，以远山节点为渠道。**
> 它不是传统意义上的“水墨后台”，而是一种**东方山水中的智能调度系统**。

核心审美：**空、远、静、流动。** 整个页面像一片没有边界的云海——远山、薄雾、水面和天空形成大量留白，**一叶舟成为全系统中唯一明显具有运动感的主体**。

舟天然解释了 API Gateway：用户发一次请求，不需画 `Request → 大圆球 → 五根线 → 五个 Provider`，而是——

> **一叶请求之舟进入云海 → 智能判断航路 → 沿不同水道驶向不同远方。**

## 视觉隐喻（业务结构与自然世界是同一个东西）

| 业务概念 | 云海天舟隐喻 |
|---|---|
| 用户请求 | 启程的一叶舟 / 一束进入水面的微光 |
| 统一模型 alias | 舟所承载的“目的” |
| 成员池 | 云海中不同方向的山岛、渡口、灯塔 |
| 智能路由 | 水道、航迹、云流 |
| Fallback | 改变航线，进入另一条水路 |
| 成员健康 | 远方灯火是否点亮 |
| 延迟 | 航线距离 / 水流状态 |
| 额度 | 航道负载或渡口承载能力 |
| 路由日志 | 近期航迹 |

## 画面语言

- 拥有非常大的**横向空间**；不要塞满亭台楼阁。
- **70% 天空、云、水和空气，30% 信息。**
- 远处只有极少量山峰。每个 Provider 对应一座很小的“山岛”，只需一个灯火和名字：
  `OpenAI` `Azure` `Anthropic` `Google` `DeepSeek`
- **不要再套一块块白色卡片**。文字像地图标注一样安静地存在。

## UI 融入

- **顶部 KPI**：直接悬在天际留白中——`12.4K 请求　99.2% 成功　320ms 延迟　78% 额度`；数字之间只用非常细的竖线。
- **右侧 Admission Pipeline**：不做大玻璃面板，做成一张半透明的“**航海簿**”：`01 HEALTH / 02 COOLDOWN / 03 FAULT DOMAIN / 04 RATE LIMIT / 05 ROUTE`。可作为五道“**出航检查**”。
- **左侧导航**：淡墨、石灰、雾灰半透明材质，像一块融入云层的**界碑**。

## 配色

尽量**避免**传统“中国红 + 金”。主色非常轻：

| 颜色 | 色值 | 用途 |
|---|---|---|
| 月白 | `#ECEAE2` | 主背景 |
| 云灰 | `#D7D9D5` | 辅助 |
| 远山青 | `#81959A` | 远山/节点 |
| 黛蓝 | `#3C5057` | 强调 |
| 水青 | `#A6BEC0` | 水道/航迹 |
| 微暖日光 | `#C6AE7B` | 点缀 |
| 墨色 | `#202827` | 文字 |

金色只能像**夕阳一样偶尔出现**。

## 字体

- 中文标题可略有宋体 / 书卷气（如「云海天舟」）。
- 后台正文、数字必须非常现代。
- **不要满屏书法**——书法应像印章，**一次就够了**。

## 动效（若落地为网页）

水面极慢呼吸；云层缓慢漂移；请求到来时一道极淡航迹从近处驶向远山；真正被选择的渠道灯火微亮；fallback 时航迹自然改道。

不是科技激光，而是：

> **风改变了，舟换了一条路。**

这就是「云海天舟」最重要的灵魂。
