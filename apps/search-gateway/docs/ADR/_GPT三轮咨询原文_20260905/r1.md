2. 路由原则

明确：

Markdown
### 正常路径

model alias
→ catalog resolve
→ route resolve
→ primary
→ upstream

### 异常路径

primary failure
→ 显式 backup
→ 显式 fallback

禁止：

- 自动遍历所有可用渠道
- 未声明的隐式 fallback
- 根据渠道列表顺序偷偷改变产品语义
3. 配置修改规则

例如：

Markdown
新增模型：
1. 先登记 model_catalog.json
2. 再登记 model_routes.json

4. 验证 alias → route → channel 完整闭环

新增渠道：
1. 登记 channel_registry.json
2. 不自动获得任何模型流量
3. 只有被 model_routes.json 显式引用后才能进入路由
