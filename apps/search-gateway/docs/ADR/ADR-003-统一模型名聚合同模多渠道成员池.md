# ADR-003：统一模型名聚合同模多渠道成员池

> 决策来源：GPT 镜像站（Extended）针对性决策咨询（2026-09-06，同窗口 2 轮）。本 ADR 只记结论与边界，不重复咨询原文。

## 状态

Accepted（决策已采纳，成员池实现待排期）

## 背景

ADR-002 定下「默认单渠道单模型 + 显式备用链」，核心诉求是**可预测、可审计、故障链清晰**。但网关的免费能力在实际中同一模型分散在多家渠道（deepseek / openrouter / groq / siliconflow / zhipu / nvidia / tokenrhythm），单一渠道额度/限流不稳，需要把「同一能力」收敛成一个逻辑模型名、由健康/冷却调度选具体渠道，以摊平单点波动——这是对 ADR-002 未覆盖场景（免费池经济性）的必要补充。

关键问题：在网关这层做模型建模时，该用「①单渠道单模型 pin」还是「②统一模型名聚合多渠道成员」？以及成员池粒度该是「同模跨渠道」还是「异构混池」。

## 决策

1. **主抽象 = 统一逻辑模型名 → `(channel, member)` 候选池**（①同模跨渠道聚合）。请求先落到逻辑模型，再由**健康（近 30s 故障剔除）+ 模型级 429 冷却 + 额度 + 延迟加权**选具体成员（沿用既有 fault_domains / BREAKER 判读）。
2. **逐请求落日志记录实际选中成员** —— 这是保住 ADR-002「可审计/可复现」硬约束的关键，聚合不等于不可追踪。
3. **候选池粒度 = 同一模型跨渠道**，例：`deepseek-v4-flash → deepseek / openrouter / siliconflow / nvidia` 的 DeepSeek 实例。
4. **禁止异构混池**（如 `smart-free → DeepSeek + Qwen + GLM + Llama` 揉一个名）。异构模型路由属更高层的**模型/任务路由**（质量、上下文、工具调用、行为一致性均入决策），应放到 `auto/task-router` 另起一层，**不进本池**。
5. 模型层次固定两级：`logical model（同模跨渠道聚合） → provider member`；`auto/task class → logical model` 属未来可加的更高层，不与池子混叠。

## 何时退回 ①（特定实例 pin，不走聚合池）

仅当请求语义需要「必须命中具体实例」时，暴露可 pin 的底层名，判据：

- 供应商特有参数 / 工具（function calling）能力不等价
- 上下文长度、输出行为显著差异（同名校、版本/量化不齐）
- 合规 / 数据驻留要求
- benchmark / 排障需要指定 provider 复现
- 用户显式指定 provider

## 与 ADR-002 的关系

- **不推翻** ADR-002 的三拆、显式备用链、禁隐式轮动；其「可预测 / 可审计」目标是硬约束。
- 把「默认单渠道单模型」**细化为**「逻辑名下聚合同模渠道；特定实例才 pin」。聚合仅在**语义同一**前提下引入，且每次选择有日志，仍可审计、可复现、故障链清楚。
- ADR-002 的 `primary` 语义保留：成员池实现为其扩展形态，`primary` 可作为池内首选或 pin 直连。

## 现状核对（2026-09-06）

> 用户要求核对 unified_models.json；核对后发现真源已迁。

- `data/unified_models.json` **已清空（3B 遗留）**，非真源；ADR-002 三拆后真源为：
  - `data/model_routes.json` —— 路由（怎么走）
  - `data/model_catalog.json` —— 目录（是什么）
  - `data/channel_registry.json` —— 渠道状态（怎么样）
- `model_routes.json` 现 **5 条 route 全为 `primary` 固定单渠道单模型**，`backup` 全空，`fallback_policy.enabled=false` → 现状 **100% 走 ①**，**无任何异构混池，无违规项**。ADR-003 引入的是「新增」聚合层（对这个文件做 schema 扩展加 `members[]`），非整改存量。
  - 受益候选（同模多渠道）：`glm-flash`（free_quota，可加 openrouter/siliconflow 等渠道）；未来 `ds-flash` 同理。
- `channel_registry.json` 的 `channels` 目前**为空 {}** —— 渠道状态未登记（运行时靠 fault_domains）。实现成员池前需补登记，作为前置项。

## 后果

正面：
- 免费池稳定性提升（摊平单渠道额度/限流波动）
- 仍可审计：逐请求记录实际选中成员
- 边界清晰：特定实例可 pin，异构路由另起层
- 复用既有 BREAKER / 故障域 / 冷却机制

代价：
- 成员池需要 model_routes 的 schema 扩展（`members[]`）与选路实现
- 新增模型 / 渠道需要在池内显式维护，不能自动进流量
- 与 ADR-002「默认单渠道单模型」的措辞需对齐，避免误解

## 迁移要求 / 前置项

1. （前置）补登记 `channel_registry.json` 的渠道健康与凭证状态。
2. model_routes schema 扩展 `members[]`，`primary` 语义保留为 pin / 池内首选。
3. 逐请求记录选中成员，先把日志打通再放池。
4. 异构模型路由（auto/task-router）**不并入本 ADR**，另行评估。
