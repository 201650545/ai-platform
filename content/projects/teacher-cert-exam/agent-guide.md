# AI 使用规则

**适用项目:** `teacher-cert-exam`（教资备考系统）
**配套文件:** `summary.md`（项目语义摘要）、`public/projects/teacher-cert-exam/` 下的 `manifest.json` / `schema.json` / `status.json` 及各表数据。

本文件规定 AI 工具在使用教资备考项目数据时的任务边界、分析优先级、读取顺序、计划与错误分析规则、时间处理、数据不足处理、禁止推断与输出要求。所有规则均基于本项目真实的 5 张表与 6 条关联关系（详见 `summary.md`），不得超出 schema 与 manifest 描述的字段和关系范围。

---

## 适用任务

本项目的数据适合支撑以下任务：

1. **考点掌握诊断**：基于 `exam-points`（846 条）的 `掌握程度` / `学习状态` / `连续正确次数` / `最近检测结果` / `下次复习日期`，识别需要加强的考点。
2. **复习计划制定**：以 `exam-points.下次复习日期` 为核心调度字段，综合到期复习、高频考点、薄弱补漏与新增推进，排定当日内容。
3. **真题题型分析**：基于 `past-exam-questions`（107 条）的 `题型` / `难度` / `考次` / `分值` / `所属科目`，提供题型分布、难度分布与考次覆盖的描述性统计。
4. **知识模块掌握概览**：基于 `knowledge-modules`（20 条）的 `关联考点` 跳转到 `exam-points`，按模块聚合掌握程度与学习状态分布。
5. **题型答题框架参考**：基于 `question-templates`（10 条）的 `答题框架` / `典型例题` / `评分要点`，为答题提供方法参考。
6. **真题与考点关联分析**：基于 `past-exam-questions.关联考点` / `关联模块` 与 `exam-points` / `knowledge-modules` 的双向遍历，定位真题涉及的考点与模块。

---

## 不适用任务

本项目的数据**不适合**支撑以下任务，AI 应主动拒绝或转人工：

1. **错题归因分析**：`error-notebook` 当前 0 条记录，无法执行任何错题统计或归因。需明确告知用户"错题本尚未投入使用"。
2. **未来命题概率预测**：`exam-points.考察频率` 的高频/中频/低频是历史描述性标签，不能转化为"今年必考""出现概率 X%"的预测。
3. **跨项目的横向比较**：本项目与 `learning-english` / `civil-service-exam` 等其他项目无业务关联，不应跨项目合并分析。
4. **写回飞书源数据**：本数据为只读公开导出，AI 不得声称已修改飞书源表；任何"建议回填"只能以建议形式输出，由用户在飞书中执行。
5. **个人身份或隐私推断**：公开数据已经过 PII 与敏感信息扫描，AI 不得从数据中尝试还原或推断任何个人身份信息。
6. **正式考试信息核验**：`past-exam-questions` 中的真题内容、考次、分值等信息为个人录入，不替代官方考试公告；正式报考须以官方公告为准。

## 分析优先级

当任务可由多种路径完成时，按以下优先级选择数据源与分析方式：

1. **优先用样本充足的表**：考点分析优先基于 `exam-points`（846 条），真题分析优先基于 `past-exam-questions`（107 条），而非 `error-notebook`（0 条）。
2. **优先用结构化字段**：能用 `掌握程度` / `学习状态` / `重要性` / `考察频率` / `题型` / `难度` 等选择字段回答的，不要依赖自由文本（`知识内容` / `例词例句` / `答题框架`）。
3. **优先沿显式关联遍历**：归因时优先沿 6 条显式关联（`关联考点` / `关联真题` / `关联模块` / `所属模块`）跳转，再考虑基于取值的弱匹配。
4. **优先多表交叉验证**：单一来源的结论需经第二张表交叉验证。例如"某考点薄弱"应同时满足 `exam-points.掌握程度` 弱 **且** `past-exam-questions` 中该考点相关题常错（经 `关联考点` 反查）。
5. **优先高频高影响项**：当多个候选并存时，优先 `考察频率` 为"高频" ∧ `重要性` 为"核心考点"或"重点" ∧ `下次复习日期` 到期的项。

## 读取顺序

首次接入本项目时，按以下顺序读取，逐步建立上下文（与 `summary.md` 的"推荐读取顺序"一致）：

1. `public/projects/teacher-cert-exam/status.json` — 先看 `sync_status` / `is_stale` / `last_success_at`，stale 时须在输出中声明数据可能过期。
2. `public/projects/teacher-cert-exam/manifest.json` — 确认 5 张表、记录数与校验和。
3. `public/projects/teacher-cert-exam/schema.json` — 建立字段类型与关联模型，注意选择字段的 `options` 取值。
4. `content/projects/teacher-cert-exam/summary.md` — 建立业务语义与表关系认知。
5. 本文件（`agent-guide.md`）— 加载分析规则与禁止推断。
6. 按任务读取具体表数据。任务到读取优先级的映射：
   - **复习/计划**：`exam-points`（按 `下次复习日期` 筛选到期考点）→ `knowledge-modules`（按 `所属模块` 聚合）→ `past-exam-questions`（经 `关联考点` 练习）→ `question-templates`（答题方法）。
   - **掌握诊断**：`exam-points`（按 `掌握程度` / `最近检测结果` 筛选）→ `knowledge-modules`（经 `所属模块` 聚合）→ `past-exam-questions`（经 `关联考点` 交叉验证）。
   - **真题分析**：`past-exam-questions`（按 `题型` / `考次` / `难度` 聚合）→ `exam-points`（经 `关联考点`）→ `knowledge-modules`（经 `关联模块`）→ `question-templates`（答题框架对照）。
   - **题型方法**：`question-templates`（按 `题型名称` 定位）→ `knowledge-modules`（经 `关联模块`）→ `past-exam-questions`（同类题型真题练习）。

> `error-notebook` 当前 0 条记录，仅在用户明确要求查看错题本时读取，并须说明"错题本暂无数据"。

## 计划制定规则

制定当日教资复习计划时，以 `exam-points` 的 `下次复习日期` 为核心调度字段，遵守以下规则：

1. **优先安排到期、高频、薄弱项**。具体优先级排序：
   1. `exam-points.下次复习日期` ≤ 今天（到期复习，间隔复习不可中断）；
   2. `考察频率` 为"高频" ∧ `重要性` 为"核心考点"或"重点"的考点；
   3. `掌握程度` 为"未掌握"或"模糊" ∧ `最近检测结果` 为"错误"的薄弱考点；
   4. `学习状态` 为"未学习"但 `重要性` 为"核心考点"或"重点"的新增推进项；
   5. 其余按 `所属科目` / `所属模块` 均衡推进。
2. **`下次复习日期` 为空的处理**：`下次复习日期` 为空可能是因为 `学习状态` 为"未学习"或 `最近检测日期` 为空。对于这类考点，不应跳过，而应按 `重要性` 和 `考察频率` 排入"新增推进"序列。
3. **按模块组织**：当日计划应按 `所属模块` 组织内容，便于集中复习同一知识模块的考点，避免跨模块频繁切换。
4. **题型练习**：涉及具体题型时，从 `question-templates` 按 `题型名称` / `所属科目` 检索 `答题框架` 与 `典型例题`，结合 `past-exam-questions` 中该题型的真题做练习。
5. **可执行粒度**：每条计划应可在一日内完成，并说明预期完成后的回填方式（更新 `掌握程度` / `连续正确次数` / `最近检测日期` / `最近检测结果`，`下次复习日期` 将自动重算）。
6. **不臆造未学内容**：新增推进项必须对应 `exam-points` 中真实存在的考点，不得凭空生成考点名称。

## 错误分析规则

分析错题与错误模式时，遵守以下规则：

1. **错题本为空时的处理**：`error-notebook` 当前 0 条记录，不得执行任何错题统计或归因。如用户要求错题分析，须明确说明"错题本尚未投入使用，当前无法执行错题归因分析"。
2. **替代数据源**：如需分析"哪些考点容易出错"，可使用 `exam-points.最近检测结果` 为"错误"的记录作为替代，沿 `关联考点` 从 `past-exam-questions` 查看相关真题。但须明确声明数据来源是"考点检测结果"而非"错题本记录"。
3. **按五类归因分类**（当错题本有数据时适用）：每条错题的 `错因分析` 应归入以下类别之一：
   - **知识**：考点不熟/缺失（对应 `exam-points.掌握程度` 为"未掌握"或"模糊"）；
   - **方法**：答题思路/框架不当（对应 `question-templates.答题框架` 偏差）；
   - **审题**：题干理解/条件遗漏（需结合 `past-exam-questions.题目内容` 判断）；
   - **时间**：用时不足导致仓促（当前无用时字段，无法归因）；
   - **策略**：时间分配/放弃决策失误（当前无整卷用时分布数据，无法归因）。
4. **归因到可改进项**：每条错题归因后，应给出可执行的改进指向（复习某考点 / 参考某题型答题框架 / 注意某知识模块），不得止步于"做错了"。

## 时间范围处理

1. **以读取时的实际日期为"今天"**：`exam-points.下次复习日期` 是否到期、`最近检测日期` 是否为"最近"、`error-notebook.错题日期` 是否为"近期"，一律以 AI 实际读取数据时的日期为准，不得使用训练数据中的固定日期或假设日期。
2. **stale 数据须声明**：若 `status.json.is_stale: true`，输出中必须声明"当前展示的是上一次成功版本（`last_success_at`），最近一次同步失败"，不得将 stale 数据当作实时数据呈现。
3. **"最近/近期"需明确窗口**：当用户问"最近检测情况"时，须先说明采用的窗口（如最近 7 天 / 最近 N 条），且窗口内样本不足时按"数据不足时的处理"执行。
4. **`下次复习日期` 为公式字段**：该字段由 `学习状态`、`掌握程度`、`连续正确次数`、`最近检测日期` 自动计算（详见 `summary.md` 的"间隔复习机制"），不是手动录入。判断"到期"时按日历日比较 `下次复习日期` 与今天，但表述为"建议复习已到期"而非"必须执行"。
5. **`下次复习日期` 为空不等于"不需要复习"**：为空可能是 `学习状态` 为"未学习"或 `最近检测日期` 为空，应按"新增推进"处理而非跳过。
6. **考次字段处理**：`past-exam-questions.考次` 的取值形如"2025 上""2025 下"，是历史考次的描述性标签，使用时应结合数据中实际出现的考次范围说明覆盖区间。

## 数据不足时的处理

当数据不足以支撑某项结论时，按以下规则处理：

1. **`error-notebook` 无数据（0 条）**：
   - 不以其做任何错题统计、归因或分析；
   - 如用户要求错题分析，明确说明"错题本尚未投入使用"；
   - 可改用 `exam-points.最近检测结果` 为"错误"的记录做替代分析，并声明数据来源差异。
2. **`question-templates` 覆盖有限（10 条）**：
   - 当某题型无对应模板时，明确说明"该题型暂无答题框架模板"，不得用其他题型的模板强行套用；
   - 不得以"有模板的题型"代表"全部题型"的答题方法分布。
3. **关联字段缺失**：当 `关联考点` / `关联真题` / `关联模块` / `所属模块` 为空时，不得强行归因；应标注"该记录未关联考点/真题/模块，无法沿关系遍历"。
4. **跨表科目匹配**：当基于 `所属科目` 的弱匹配无命中时，须先检查口径差异（`past-exam-questions` 使用"科目三-初中英语"，其他表使用"学科知识与教学能力"），做口径映射后再匹配；映射后仍无命中时，说明"未找到对齐记录"。
5. **样本量阈值**：任何统计结论须基于不少于一定样本（建议 ≥ 5 条）才可给出方向性判断；低于阈值时只描述事实（如"该模块仅有 2 条考点"），不下趋势性结论。
6. **主动声明而非沉默**：数据不足时必须显式声明限制，不得用模糊措辞掩盖样本不足；宁可给出"目前数据不足以回答"也不可编造。

## 禁止推断

AI 在使用本项目数据时，**禁止**做出以下推断（与 `summary.md` 的"不应做出的推断"一致）：

1. **禁止以 `error-notebook` 断言错题情况**：当前 0 条记录，不得得出"没有错题""错题已全部纠正"等结论，只能说明"错题本尚未投入使用"。
2. **禁止假定跨表科目取值一致**：`past-exam-questions.所属科目` 使用"科目三-初中英语"，其他表使用"学科知识与教学能力"；跨表匹配前须做口径映射，不得直接字符串匹配。
3. **禁止假定关联字段必然有值**：`关联考点` / `关联真题` / `关联模块` / `所属模块` 可能为空，不得对未关联的记录强行归因。
4. **禁止把 `下次复习日期` 为空等同于"不需要复习"**：该字段为公式计算结果，为空可能是 `学习状态` 为"未学习"或 `最近检测日期` 为空，不代表考点已掌握。
5. **禁止假定 `知识树路径` 与 `知识树` 取值一致**：前者为自由文本，后者为选择字段，格式可能不同。
6. **禁止把 `考察频率` 当作命题概率预测**：高频/中频/低频是历史描述，不得转化为"今年必考""出现概率 X%"。
7. **禁止把间隔复习字段当作硬性日程**：`下次复习日期` 是公式计算的复习节奏建议，不是必须执行的合约。
8. **禁止在不检查 `is_stale` 的情况下假定数据最新**：须先读 `status.json`，stale 时须声明。
9. **禁止凭空生成考点/模块/真题**：所有引用的实体必须存在于对应表的真实记录中；不得为满足计划或归因需要而虚构考点名称、真题题号或模块名称。
10. **禁止从公开数据反推飞书源表结构**：公开数据受视图与字段白名单裁剪，系统字段（创建人、修改人、创建时间、最后更新时间）已排除，不代表飞书 Base 的完整结构。
11. **禁止跨项目合并分析**：不得将本项目数据与 `learning-english` / `civil-service-exam` 等其他项目数据混合得出结论。

## 输出要求

1. **声明数据来源与样本量**：每项分析结论须标注所基于的表、字段与样本量（如"基于 `exam-points` 846 条，其中掌握程度为'未掌握'的 N 条"）。
2. **声明时效与 staleness**：若 `is_stale: true`，输出开头须声明；涉及"最近/到期"等判断须说明所采用的"今天"日期与时间窗口。
3. **给出可遍历的引用**：引用具体记录时，优先给出记录 ID 或可定位的字段值（如考点 `考点名称` / `考点编号`、模块 `模块名称`、真题 `题号`），便于用户核对。
4. **结论分级**：区分"事实陈述"（直接来自数据）、"统计观察"（基于聚合）、"建议"（基于规则推断），不得混为一谈。
5. **计划类输出格式**：当日计划须按 `所属模块` 组织，包含 `考点名称` / `所属科目` / `掌握程度` / `下次复习日期`，并说明排定理由（到期/高频/薄弱/新增），以及可回填字段（`掌握程度` / `连续正确次数` / `最近检测日期` / `最近检测结果`）。
6. **诊断类输出格式**：每项诊断须包含 `考点名称` / `所属模块` / `掌握程度` / `重要性` / `考察频率` / `下次复习日期`，并给出改进指向。
7. **科目口径声明**：涉及跨表科目匹配时，须声明所采用的口径映射（"学科知识与教学能力" ↔ "科目三-初中英语"）。
8. **不越界**：输出不得包含禁止推断清单中的任何内容；遇到不适用任务时，明确说明原因并转人工或转官方信息源。
9. **语言**：面向用户的输出使用中文；字段名与表名保留原始中文/英文 slug 形式以便核对。
