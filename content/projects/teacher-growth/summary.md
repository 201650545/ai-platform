## 项目用途

教师专业成长系统是一个以**费曼学习法**为核心方法论的教师个人知识管理与学习系统，把分散在飞书多维表格中的知识点明细、知识分类目录、设计说明、学习日志和自测题库统一组织起来，供 AI 工具在无飞书访问权限的情况下读取数据模型、记录和表间关联，进而提供知识点掌握诊断、复习计划制定、学习日志分析、自测题推荐和知识体系浏览等能力。

它解决的核心问题是：教师专业成长的知识天然分散在"分类—知识点—日志—自测"多条线索上，单看任何一张表都无法回答"我该重点复习哪些知识点"或"我的学习进展如何"这类问题。本项目通过显式的关联字段（`knowledge-points.所属分类` ↔ `knowledge-categories.关联知识点`）把分类与知识点串成双向可遍历的图，并以学习日志记录费曼解释、卡壳点与自测结果，以自测题库支撑针对性练习，最终以 `knowledge-points.下次复习日期` 驱动间隔复习调度。

---

## 核心目标

1. **知识结构化**：以 `knowledge-categories` 的知识分类目录为顶层组织，按"一级分类 → 二级分类 → 三级分类 → 学科分类"分层覆盖教师专业成长的六大领域（学科基础知识、教育理论与心理、思维能力、教学实践能力、专业理念与法规、数字素养）。
2. **知识点可追踪**：以 `knowledge-points`（知识点明细表）为知识主干，记录每个知识点的掌握状态、掌握度评分、复习次数、上次学习日期、下次复习日期，并通过 `下次复习日期` 字段支撑间隔复习调度。
3. **设计说明可参考**：以 `design-notes`（📋设计说明）提供项目设计层面的章节性说明，作为参考性文档，**不作为业务数据参与分析**。
4. **学习过程可回溯**：通过 `study-logs`（学习日志）记录每次学习的知识点、学习方式、学习时长、费曼解释、卡壳点、自测结果、学习心得与下一步行动，支撑学习过程回溯与归因。
5. **自测题目可练习**：以 `self-test-questions`（自测题库）为题源，覆盖各知识分类的题目，含题型、难度、参考答案、评分标准、来源，并通过 `关联知识点` 连接知识体系，支撑针对性练习推荐。

## 表之间的关系

关系来自飞书多维表格的"关联记录"字段（link 类型），均通过显式的双向 link 实现。下列关系是本项目分析能力的骨架。

```
                  ┌─────────────────────────┐
                  │  knowledge-categories   │  (分类顶层)
                  │  关联知识点 ◄────────────────┐
                  └───────────┬─────────────┘   │
                              │                 │
                              │ 双向关联         │
                              ▼                 │
                  ┌─────────────────────────┐   │
                  │  knowledge-points       │   │
                  │  所属分类 ──────────────────┘
                  │  (知识主干)
                  └───────────▲─────────────┘
                              │
                              │ 关联知识点 (单向)
                              │
                  ┌─────────────────────────┐
                  │  self-test-questions    │  (题源)
                  │  关联知识点 ──────────────┘
                  └─────────────────────────┘

                  ┌─────────────────────────┐
                  │  study-logs             │  (学习日志)
                  │  知识点 (语义匹配 knowledge-points)
                  └─────────────────────────┘
```

**显式关联（1 条双向关系）：**

| 来源表.字段 | 目标表 | 方向 | 说明 |
|---|---|---|---|
| `knowledge-points.所属分类` | `knowledge-categories` | 双向 | 知识点归属其分类；`knowledge-categories.关联知识点` 反向指向该分类下的知识点 |
| `self-test-questions.关联知识点` | `knowledge-points` | 单向 | 自测题关联其考核的知识点 |

**隐含的语义关联（非外键，需通过字段值匹配）：**

- `study-logs.知识点` ↔ `knowledge-points.条目名称`：学习日志通过知识点名称语义匹配知识点明细，非外键，匹配时需注意名称口径差异。
- `*.一级分类` / `*.二级分类` / `*.三级分类`：跨表的分类口径用于聚合，`knowledge-points`、`knowledge-categories`、`self-test-questions` 均含一级分类字段，可按分类层级跨表聚合。
- `*.适用学段`：跨表的学段口径用于聚合，`knowledge-points` 与 `knowledge-categories` 均含适用学段字段。

## 学习方法论

本项目以**费曼学习法**为核心方法论，并通过 `knowledge-points.学习策略` 字段标注每个知识点采用的学习策略。系统支持以下 6 种学习策略：

| # | 学习策略 | 说明 |
|---|---|---|
| 1 | 费曼四步法 | 核心方法论。选定理 → 用大白话讲给外行听 → 识别卡壳点回补 → 简化语言重讲。`study-logs.费曼解释我的话` 与 `study-logs.卡壳点` 即为该方法的执行记录。 |
| 2 | 精读+笔记 | 对教材/专著进行精读并整理结构化笔记，沉淀到 `knowledge-points.知识要点`。 |
| 3 | 刷题巩固 | 通过 `self-test-questions` 做针对性练习，错题回溯到知识点，更新 `knowledge-points.掌握状态` 与 `掌握度评分`。 |
| 4 | 主题阅读 | 围绕某一知识分类做主题式阅读，沿 `knowledge-categories.关联知识点` 集中推进同一主题下的知识点。 |
| 5 | 教学实践迁移 | 将理论知识迁移到教学设计与课堂实践，在 `study-logs.学习心得` 中记录迁移体会。 |
| 6 | 反思复盘 | 定期复盘学习日志，识别卡壳点与下一步行动，更新 `study-logs.下一步行动`。 |

## 知识分类体系

本项目的知识分类体系按"一级分类 → 二级分类 → 三级分类 → 学科分类"四级组织，一级分类覆盖教师专业成长的六大领域。

### 一级分类（6 大领域）

| # | 一级分类 | 说明 |
|---|---|---|
| 1 | 学科基础知识 | 任教学科的底层知识，如英语语音、词汇、语法、句法等。 |
| 2 | 教育理论与心理 | 教育学、心理学、学习科学等理论性知识。 |
| 3 | 思维能力 | 批判性思维、逻辑思维、创新思维等思维方法论。 |
| 4 | 教学实践能力 | 教学设计、课堂管理、教学评价、教学实施等实践性能力。 |
| 5 | 专业理念与法规 | 教师职业道德、教育法律法规、职业理念等。 |
| 6 | 数字素养 | 信息化教学、数字工具应用、AI 辅助教学等数字时代能力。 |

## 间隔复习机制

`knowledge-points` 表通过 `下次复习日期` 字段实现间隔复习调度。该字段为日期类型，由 `掌握状态`、`掌握度评分`、`复习次数`、`上次学习日期` 等字段驱动，掌握状态越弱、复习次数越少，复习间隔越短。

| 掌握状态 | 复习调度逻辑 | 说明 |
|---|---|---|
| 未开始 | 不安排复习 | 尚未进入学习流程的知识点不安排复习 |
| 学习中 | 按 `下次复习日期` 到期复习 | 学习中的知识点按间隔复习节奏推进，到期即需复习 |
| 已掌握 | 按 `下次复习日期` 到期复习（间隔更长） | 已掌握的知识点复习间隔逐步拉长，但仍按到期复习 |

判断"到期复习"时，以 `knowledge-points.下次复习日期` 与读取时的实际日期比较：`下次复习日期` ≤ 今天即为到期。`下次复习日期` 为空可能是因为 `掌握状态` 为"未开始"或 `上次学习日期` 为空，不代表"不需要复习"，而是"尚未进入复习调度"。

## 常见分析问题

下列问题均可仅凭本项目的公开数据回答，并给出推荐的数据遍历路径。

### 1. 哪些知识点需要重点复习？

以 `knowledge-points`（1503 条）为主，按以下优先级合并筛选：

1. `下次复习日期` ≤ 今天（到期复习，间隔复习不可中断）；
2. `掌握状态` 为"未开始"或"学习中" ∧ `掌握度评分` 偏低的薄弱知识点；
3. `重要程度` 为"必须掌握"的考点；
4. `学习策略` 为"费曼四步法"且 `费曼解释记录` 为空的知识点（需补做费曼解释）；
5. 通过 `所属分类` 跳到 `knowledge-categories`，确认该知识点所属分类的 `掌握状态`。

最终"需要重点复习"的知识点 = 到期 ∧ 掌握弱 ∧ 重要，三者重叠度越高越优先。

### 2. 某个知识分类的掌握情况如何？

以 `knowledge-categories`（71 条）为入口，沿 `关联知识点` 跳到 `knowledge-points`，按 `所属分类` 聚合：
- 统计该分类下知识点的 `掌握状态` 分布（未开始/学习中/已掌握的比例）；
- 统计 `重要程度` 分布（必须掌握/应该掌握/了解拓展的比例）；
- 检查 `下次复习日期` 到期数量；
- 沿 `study-logs.知识点` 语义匹配该分类下的知识点，查看学习日志中的 `自测结果` 与 `卡壳点`。

### 3. 学习日志反映了哪些卡壳模式？

以 `study-logs` 为入口，按 `卡壳点` 字段聚合分析：
- 按卡壳类型分类（知识/表达/迁移/自测）；
- 沿 `study-logs.知识点` 语义匹配 `knowledge-points.条目名称`，归因到具体知识点；
- 查看该知识点的 `掌握状态` / `掌握度评分` / `复习次数`，判断是否需要加强复习；
- 沿 `self-test-questions.关联知识点` 推荐对应难度的练习题。

### 4. 如何为薄弱知识点推荐自测题？

以 `knowledge-points` 中 `掌握状态` 为"学习中"或"未开始"的知识点为起点：
1. 沿 `self-test-questions.关联知识点` 检索对应题目；
2. 按 `难度`（易/中/难）和 `题型` 筛选适合当前掌握水平的题目；
3. 参考 `参考答案` 与 `评分标准` 自评；
4. 无对应自测题时，明确说明"该知识点暂无自测题"。

## 推荐读取顺序

针对首次接入本项目的 AI 工具，推荐按以下顺序读取，逐步建立上下文：

1. `public/projects/teacher-growth/manifest.json` — 确认表清单、记录数、校验和与 `build_id`，判断数据是否 stale。
2. `public/projects/teacher-growth/schema.json` — 读取字段类型、选项取值与关联解析，建立数据模型。
3. `public/projects/teacher-growth/status.json` — 读取 `sync_status` / `is_stale` / `last_success_at`，判断数据时效。
4. 本文件（`summary.md`）— 建立业务语义与表关系认知。
5. `agent-guide.md` — 加载分析规则与禁止推断。
6. 按任务需要读取具体表数据（`tables/<slug>/records-XXXX.json`）。一般分析任务的读取优先级：
   - 复习类：`knowledge-points`（按 `下次复习日期` 筛选到期）→ `knowledge-categories`（按 `所属分类` 聚合）→ `self-test-questions`（按 `关联知识点` 练习）；
   - 诊断类：`knowledge-points`（按 `掌握状态` / `掌握度评分` 筛选）→ `study-logs`（了解学习历史）→ `self-test-questions`（推荐练习）；
   - 日志类：`study-logs`（按 `学习日期` 排序）→ `knowledge-points`（经 `知识点` 语义匹配）→ `knowledge-categories`（按分类聚合）。

## 数据更新时间与时效性

- **同步层级**：以 `config/projects/teacher-growth.yaml` 的 `schedule.tier` 配置为准。
- **时间戳来源**：以 `status.json` 的 `last_success_at` 为准；`build_id`（`manifest.json` / `status.json` / `catalog.json`）反映本次构建版本。
- **staleness 判断**：当 `status.json.sync_status` 为 `failed` 或 `stale`、`is_stale: true` 时，展示的是上一次成功版本，最近一次同步尝试失败。分析前应先检查 `is_stale`。
- **字段级时效**：`knowledge-points.上次学习日期` / `下次复习日期` 与 `study-logs.学习日期` 是时间敏感字段；"最近""到期"等判断必须基于读取时的实际日期，不能基于固定假设。

## 已知限制

1. **`design-notes` 已禁用导出**：该表为项目设计层面的章节性参考文档，因内容含疑似凭证值触发安全扫描，已禁用公开导出，**不参与任何统计、归因或分析**。
2. **`study-logs.知识点` 为语义匹配非外键**：学习日志通过知识点名称语义匹配 `knowledge-points.条目名称`，非外键，存在名称口径差异导致的匹配失败可能。
3. **`下次复习日期` 为日期字段**：该字段为日期类型，由 `掌握状态` / `掌握度评分` / `复习次数` / `上次学习日期` 驱动。`掌握状态` 为"未开始"或 `上次学习日期` 为空时，`下次复习日期` 可能为空，不代表"不需要复习"，而是"尚未进入复习调度"。
4. **`掌握度评分` 可能为空**：该字段为量化评分，可能因尚未自测而留空。**留空不等于"未掌握"**，仅表示"尚未评分"。
5. **学习日志覆盖不完整**：并非所有知识点都有对应的学习日志记录，`study-logs` 仅记录已发生的学习行为，不能用以推断"未记录即未学习"。
6. **自测题库覆盖有限**：`self-test-questions` 可能不完全覆盖所有知识点，部分知识点可能无对应自测题。
7. **状态字段取值依赖选项配置**：`掌握状态` / `重要程度` / `自测结果` / `学习类型` / `难度` 等为选择字段，具体可选取值以各表 `fields.json` 的 `options` 为准，本文件列出的取值基于编写时的实际配置。
8. **关联完整性依赖源数据**：关联字段是否填写、是否指向有效记录，取决于飞书源表的录入质量，存在空值或失效引用的可能。
9. **自动生成摘要的局限**：`public/projects/teacher-growth/summary.md` 由代码机械生成，仅含表清单与字段列表，不含业务语义；语义内容以本文件为准。

## 不应做出的推断

1. **不应以 `design-notes` 作为业务数据**：该表因安全原因已禁用导出，不得用于知识点统计、掌握情况分析或学习进展推断。
2. **不应假定所有知识点都有学习日志**：`study-logs` 仅记录已发生的学习行为，未记录的知识点不能推断为"未学习"。
3. **不应把 `掌握度评分` 为空等同于"未掌握"**：留空仅表示"尚未评分"，不代表掌握状态为"未开始"。
4. **不应把 `下次复习日期` 为空等同于"不需要复习"**：该字段为空可能是 `掌握状态` 为"未开始"或 `上次学习日期` 为空，不代表知识点已掌握。
5. **不应在不检查 `status.json.is_stale` 的情况下假定数据为最新**：stale 状态下展示的是旧版本数据。
6. **不应从公开数据反推飞书源表结构**：公开数据受视图与字段白名单裁剪，不代表飞书 Base 的完整结构（系统字段已排除）。
7. **不应凭空生成知识点/分类/自测题**：所有引用的实体必须存在于对应表的真实记录中；不得为满足计划或归因需要而虚构知识点名称、分类名称或题目。
8. **不应跨项目合并分析**：不得将本项目数据与 `learning-english` / `civil-service-exam` / `teacher-cert-exam` 等其他项目数据混合得出结论。
