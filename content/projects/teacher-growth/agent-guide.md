# AI 使用规则

**适用项目:** `teacher-growth`（教师专业成长系统）
**配套文件:** `summary.md`（项目语义摘要）、`public/projects/teacher-growth/` 下的 `manifest.json` / `schema.json` / `status.json` 及各表数据。

本文件规定 AI 工具在使用教师专业成长项目数据时的任务边界、分析优先级、读取顺序、计划与错误分析规则、时间处理、数据不足处理、禁止推断与输出要求。所有规则均基于本项目真实的 5 张表与表间关联（详见 `summary.md`），不得超出 schema 与 manifest 描述的字段和关系范围。

---

## 适用任务

本项目的数据适合支撑以下任务：

1. **知识点掌握诊断**：基于 `knowledge-points`（知识点明细表）的 `掌握状态` / `掌握度评分` / `复习次数` / `上次学习日期` / `下次复习日期`，识别需要加强的知识点。
2. **复习计划制定**：以 `knowledge-points.下次复习日期` 为核心调度字段，综合到期复习、重要程度、掌握状态与新增推进，排定当日内容。
3. **学习日志分析**：基于 `study-logs`（学习日志）的 `学习日期` / `学习方式` / `学习时长分钟` / `费曼解释我的话` / `卡壳点` / `自测结果` / `学习心得` / `下一步行动`，回溯学习过程与归因卡壳点。
4. **自测题推荐**：基于 `self-test-questions`（自测题库）的 `题型` / `难度` / `一级分类` / `关联知识点` / `参考答案` / `评分标准`，为薄弱知识点推荐针对性练习题。
5. **知识体系浏览**：基于 `knowledge-categories`（知识分类目录）的一/二/三级分类与 `关联知识点`，按分类层级浏览知识体系结构与掌握情况。

---

## 不适用任务

本项目的数据**不适合**支撑以下任务，AI 应主动拒绝或转人工：

1. **未来命题预测**：本项目为教师专业成长知识管理系统，不涉及任何考试命题预测，`重要程度` 的"必须掌握/应该掌握/了解拓展"是学习优先级标签，不能转化为"必考""出现概率 X%"的预测。
2. **跨项目的横向比较**：本项目与 `learning-english` / `civil-service-exam` / `teacher-cert-exam` 等其他项目无业务关联，不应跨项目合并分析或横向比较。
3. **学习效果因果推断**：本项目记录的是学习行为与掌握状态，但不能从相关性推断因果性（如"学习时长更长导致掌握度更高"），仅可描述统计观察。
4. **写回飞书源数据**：本数据为只读公开导出，AI 不得声称已修改飞书源表；任何"建议回填"只能以建议形式输出，由用户在飞书中执行。
5. **个人身份或隐私推断**：公开数据已经过 PII 与敏感信息扫描，AI 不得从数据中尝试还原或推断任何个人身份信息。
6. **以 `design-notes` 作为业务数据**：`design-notes`（📋设计说明）为项目设计层面的章节性参考文档，**禁止作为业务数据**参与任何统计、归因或分析。

## 分析优先级

当任务可由多种路径完成时，按以下优先级选择数据源与分析方式：

1. **先读 `knowledge-points` 的掌握状态和下次复习日期**：知识点掌握诊断与复习计划制定均以 `knowledge-points` 为入口，优先读取 `掌握状态` 与 `下次复习日期`，识别到期与薄弱知识点。
2. **再读 `study-logs` 了解学习历史**：沿 `study-logs.知识点` 语义匹配 `knowledge-points.条目名称`，查看该知识点的学习日志记录，了解学习方式、费曼解释、卡壳点与自测结果，作为掌握诊断的交叉验证。
3. **最后读 `self-test-questions` 推荐练习**：沿 `self-test-questions.关联知识点` 跳到 `knowledge-points`，为薄弱知识点推荐对应难度与题型的自测题，支撑针对性练习。
4. **优先用结构化字段**：能用 `掌握状态` / `重要程度` / `适用学段` / `学习类型` / `难度` 等选择字段回答的，不要依赖自由文本（`知识要点` / `费曼解释我的话` / `学习心得`）。
5. **优先沿显式关联遍历**：归因时优先沿显式关联（`knowledge-points.所属分类` ↔ `knowledge-categories.关联知识点`、`self-test-questions.关联知识点`）跳转，再考虑基于取值的弱匹配（`study-logs.知识点` ↔ `knowledge-points.条目名称`）。
6. **优先多表交叉验证**：单一来源的结论需经第二张表交叉验证。例如"某知识点薄弱"应同时满足 `knowledge-points.掌握状态` 为"学习中"或"未开始" **且** `study-logs` 中该知识点的 `自测结果` 为"未通过"或"部分通过"。

## 读取顺序

首次接入本项目时，按以下顺序读取，逐步建立上下文（与 `summary.md` 的"推荐读取顺序"一致）：

1. `public/projects/teacher-growth/status.json` — 先看 `sync_status` / `is_stale` / `last_success_at`，stale 时须在输出中声明数据可能过期。
2. `public/projects/teacher-growth/manifest.json` — 确认 5 张表、记录数与校验和。
3. `public/projects/teacher-growth/schema.json` — 建立字段类型与关联模型，注意选择字段的 `options` 取值。
4. `content/projects/teacher-growth/summary.md` — 建立业务语义与表关系认知。
5. 本文件（`agent-guide.md`）— 加载分析规则与禁止推断。
6. 按任务读取具体表数据。任务到读取优先级的映射：
   - **复习/计划**：`knowledge-points`（按 `下次复习日期` 筛选到期知识点）→ `knowledge-categories`（按 `所属分类` 聚合）→ `self-test-questions`（经 `关联知识点` 练习）。
   - **掌握诊断**：`knowledge-points`（按 `掌握状态` / `掌握度评分` 筛选）→ `study-logs`（了解学习历史）→ `self-test-questions`（推荐练习）。
   - **日志分析**：`study-logs`（按 `学习日期` 排序）→ `knowledge-points`（经 `知识点` 语义匹配）→ `knowledge-categories`（按分类聚合）。
   - **知识体系浏览**：`knowledge-categories`（按一/二/三级分类浏览）→ `knowledge-points`（经 `关联知识点`）→ `self-test-questions`（经 `关联知识点`）。

> `design-notes` 仅在用户明确要求查看设计说明时读取，且不得用于任何业务分析。

## 计划制定规则

制定当日教师成长学习计划时，以 `knowledge-points` 的 `下次复习日期` 为核心调度字段，遵守以下规则：

1. **优先安排到期、重要、薄弱项**。具体优先级排序：
   1. `knowledge-points.下次复习日期` ≤ 今天（到期复习，间隔复习不可中断）；
   2. `重要程度` 为"必须掌握"的考点；
   3. `掌握状态` 为"未开始"或"学习中" ∧ `掌握度评分` 偏低的薄弱知识点；
   4. `学习策略` 为"费曼四步法"且 `费曼解释记录` 为空的知识点（需补做费曼解释）；
   5. 其余按 `一级分类` / `所属分类` 均衡推进。
2. **`下次复习日期` 为空的处理**：`下次复习日期` 为空可能是因为 `掌握状态` 为"未开始"或 `上次学习日期` 为空。对于这类知识点，不应跳过，而应按 `重要程度` 排入"新增推进"序列。
3. **按分类组织**：当日计划应按 `所属分类` / `一级分类` 组织内容，便于集中复习同一知识分类下的知识点，避免跨分类频繁切换。
4. **自测练习**：涉及具体知识点时，从 `self-test-questions` 按 `关联知识点` 检索对应题目，结合 `难度` 与 `题型` 安排练习，并参考 `参考答案` 与 `评分标准` 自评。
5. **可执行粒度**：每条计划应可在一日内完成，并说明预期完成后的回填方式（更新 `掌握状态` / `掌握度评分` / `复习次数` / `上次学习日期`，并在 `study-logs` 中新增一条学习日志记录 `费曼解释我的话` / `卡壳点` / `自测结果` / `学习心得` / `下一步行动`）。
6. **不臆造未学内容**：新增推进项必须对应 `knowledge-points` 中真实存在的知识点，不得凭空生成知识点名称。

## 错误分析规则

分析卡壳点与错误模式时，遵守以下规则：

1. **以 `study-logs.卡壳点` 为主要数据源**：学习日志的 `卡壳点` 字段记录费曼解释过程中的卡壳点，是错误分析的主要依据。`自测结果` 为"未通过"或"部分通过"的日志记录也应纳入分析。
2. **归因到知识点**：每条卡壳点应沿 `study-logs.知识点` 语义匹配 `knowledge-points.条目名称`，归因到具体知识点，并查看该知识点的 `掌握状态` / `掌握度评分` / `复习次数`，判断是否需要加强复习。
3. **按卡壳类型分类**：每条卡壳点可归入以下类别之一：
   - **知识**：知识点本身不熟/缺失（对应 `knowledge-points.掌握状态` 为"未开始"或"学习中"）；
   - **表达**：费曼解释时无法用大白话讲清（对应 `study-logs.费曼解释我的话` 为空或过于简略）；
   - **迁移**：理论无法迁移到教学实践（对应 `study-logs.学习心得` 中提及迁移困难）；
   - **自测**：自测题作答错误（对应 `study-logs.自测结果` 为"未通过"或"部分通过"）。
4. **归因到可改进项**：每条卡壳点归因后，应给出可执行的改进指向（复习某知识点 / 补做费曼解释 / 做对应自测题 / 沿 `关联知识点` 找相关题练习），不得止步于"卡壳了"。
5. **关联自测题**：当卡壳点对应的知识点在 `self-test-questions` 中有相关题目时，应沿 `self-test-questions.关联知识点` 推荐对应难度的练习题。

## 时间范围处理

1. **以读取时的实际日期为"今天"**：`knowledge-points.下次复习日期` 是否到期、`上次学习日期` 是否为"最近"、`study-logs.学习日期` 是否为"近期"，一律以 AI 实际读取数据时的日期为准，不得使用训练数据中的固定日期或假设日期。
2. **stale 数据须声明**：若 `status.json.is_stale: true`，输出中必须声明"当前展示的是上一次成功版本（`last_success_at`），最近一次同步失败"，不得将 stale 数据当作实时数据呈现。
3. **"最近/近期"需明确窗口**：当用户问"最近学习情况"时，须先说明采用的窗口（如最近 7 天 / 最近 N 条），且窗口内样本不足时按"数据不足时的处理"执行。
4. **`下次复习日期` 为空不等于"不需要复习"**：为空可能是 `掌握状态` 为"未开始"或 `上次学习日期` 为空，应按"新增推进"处理而非跳过。

## 数据不足时的处理

当数据不足以支撑某项结论时，按以下规则处理：

1. **`study-logs` 无对应记录**：
   - 某知识点在 `study-logs` 中无记录时，不得推断为"未学习"，只能说明"暂无学习日志记录"；
   - 可改用 `knowledge-points.掌握状态` / `掌握度评分` 做替代分析，并声明数据来源差异。
2. **`self-test-questions` 覆盖有限**：
   - 当某知识点无对应自测题时，明确说明"该知识点暂无自测题"，不得用其他知识点的题目强行套用；
   - 不得以"有题目的知识点"代表"全部知识点"的练习覆盖情况。
3. **关联字段缺失**：当 `所属分类` / `关联知识点` 为空时，不得强行归因；应标注"该记录未关联分类/知识点，无法沿关系遍历"。
4. **`掌握度评分` 为空**：不得把 `掌握度评分` 为空等同于"未掌握"，只能说明"尚未评分"；应改用 `掌握状态` 字段判断掌握情况。
5. **样本量阈值**：任何统计结论须基于不少于一定样本（建议 ≥ 5 条）才可给出方向性判断；低于阈值时只描述事实（如"该分类仅有 2 条知识点"），不下趋势性结论。
6. **主动声明而非沉默**：数据不足时必须显式声明限制，不得用模糊措辞掩盖样本不足；宁可给出"目前数据不足以回答"也不可编造。

## 禁止推断

AI 在使用本项目数据时，**禁止**做出以下推断（与 `summary.md` 的"不应做出的推断"一致）：

1. **禁止以 `design-notes` 表内容作为业务数据**：该表为项目设计层面的章节性参考文档，不得用于知识点统计、掌握情况分析或学习进展推断。
2. **禁止假定所有知识点都有学习日志记录**：`study-logs` 仅记录已发生的学习行为，未记录的知识点不能推断为"未学习"，只能说明"暂无学习日志记录"。
3. **禁止把 `掌握度评分` 为空等同于"未掌握"**：留空仅表示"尚未评分"，不代表 `掌握状态` 为"未开始"或掌握度低。
4. **禁止跨项目合并分析**：不得将本项目数据与 `learning-english` / `civil-service-exam` / `teacher-cert-exam` 等其他项目数据混合得出结论，本项目与其他项目无业务关联。
5. **禁止把 `下次复习日期` 为空等同于"不需要复习"**：该字段为空可能是 `掌握状态` 为"未开始"或 `上次学习日期` 为空，不代表知识点已掌握。
6. **禁止把 `重要程度` 当作命题概率预测**："必须掌握/应该掌握/了解拓展"是学习优先级标签，不得转化为"必考""出现概率 X%"。
7. **禁止把间隔复习字段当作硬性日程**：`下次复习日期` 是复习节奏建议，不是必须执行的合约。
8. **禁止在不检查 `is_stale` 的情况下假定数据最新**：须先读 `status.json`，stale 时须声明。
9. **禁止凭空生成知识点/分类/自测题**：所有引用的实体必须存在于对应表的真实记录中；不得为满足计划或归因需要而虚构知识点名称、分类名称或题目。
10. **禁止从公开数据反推飞书源表结构**：公开数据受视图与字段白名单裁剪，系统字段（创建人、修改人、创建时间、最后更新时间）已排除，不代表飞书 Base 的完整结构。
11. **禁止从学习行为相关性推断因果性**：不得从"学习时长更长""复习次数更多"等相关性推断"导致掌握度更高"的因果关系，仅可描述统计观察。

## 数据口径说明

### 掌握状态（三档）

`knowledge-points.掌握状态` 与 `knowledge-categories.掌握状态` 字段的取值为以下三档：

| 掌握状态 | 含义 | 间隔复习调度 |
|---|---|---|
| 未开始 | 尚未进入学习流程 | 不安排复习，`下次复习日期` 为空 |
| 学习中 | 已开始学习但尚未掌握 | 按 `下次复习日期` 到期复习，间隔较短 |
| 已掌握 | 已稳定掌握 | 按 `下次复习日期` 到期复习，间隔逐步拉长 |

### 重要程度（三档）

`knowledge-points.重要程度` 与 `knowledge-categories.重要程度` 字段的取值为以下三档：

| 重要程度 | 含义 | 学习优先级 |
|---|---|---|
| 必须掌握 | 教师专业成长的核心知识，不掌握会影响教学基本功 | 最高优先级，到期即复习，新增推进时优先安排 |
| 应该掌握 | 重要但非核心的知识，掌握后能显著提升专业能力 | 中等优先级，到期即复习，新增推进时次优先安排 |
| 了解拓展 | 拓展性知识，掌握后能拓宽专业视野 | 较低优先级，可在核心知识复习之余安排 |

## 输出要求

1. **声明数据来源与样本量**：每项分析结论须标注所基于的表、字段与样本量（如"基于 `knowledge-points` N 条，其中掌握状态为'学习中'的 M 条"）。
2. **声明时效与 staleness**：若 `is_stale: true`，输出开头须声明；涉及"最近/到期"等判断须说明所采用的"今天"日期与时间窗口。
3. **给出可遍历的引用**：引用具体记录时，优先给出记录 ID 或可定位的字段值（如知识点 `条目名称`、分类 `学科分类`、自测题 `题目`），便于用户核对。
4. **结论分级**：区分"事实陈述"（直接来自数据）、"统计观察"（基于聚合）、"建议"（基于规则推断），不得混为一谈。
5. **计划类输出格式**：当日计划须按 `所属分类` / `一级分类` 组织，包含 `条目名称` / `掌握状态` / `掌握度评分` / `下次复习日期` / `重要程度`，并说明排定理由（到期/必须掌握/薄弱/新增），以及可回填字段（`掌握状态` / `掌握度评分` / `复习次数` / `上次学习日期`）与需在 `study-logs` 中新增的日志字段。
6. **诊断类输出格式**：每项诊断须包含 `条目名称` / `所属分类` / `掌握状态` / `掌握度评分` / `重要程度` / `下次复习日期`，并给出改进指向。
7. **不越界**：输出不得包含禁止推断清单中的任何内容；遇到不适用任务时，明确说明原因并转人工或转官方信息源。
8. **语言**：面向用户的输出使用中文；字段名与表名保留原始中文/英文 slug 形式以便核对。
