# AI 使用规则

本文件规定 AI 代理在分析 `ai-resource` 项目数据时必须遵守的规则。所有规则基于真实 schema 和 manifest 数据制定，不依赖任何虚构字段或关系。

---

## 适用任务

本项目的数据适合以下 AI 任务：

1. **能力发现**：根据 `capabilities` 表查询有哪些可调用的 AI 能力、各类别（LLM API / 生图 / 搜索 / 云GPU 等）的可用情况。
2. **调用规格查询**：根据 `capabilities.endpoint`、`调用方式`、`认证方案`、`允许主机`、`请求体模板`、`模型族` 回答「某能力怎么调用」。
3. **实例选择**：根据 `instances.状态`、`剩余额度快照`、`安全余量`、`限速`、`路由优先级` 为一次任务选择合适的实例。
4. **额度状态分析**：筛选剩余额度接近或低于安全余量的实例，识别需要关注/补充额度的资源。
5. **能力↔实例关联**：通过 `instances.所属能力` ↔ `capabilities.capability_id` 定位「某项能力下有哪几个实例、各实例状态如何」。
6. **路由决策辅助**：为 AI 调度器提供「当前可用的实例及其调用规格」作为路由输入之一。

---

## 不适用任务

本项目的数据**不适合**以下任务，AI 代理应拒绝或明确说明限制：

1. **实时额度查询**：`剩余额度快照` 是同步时的快照，不是实时值；不支持「现在还剩多少额度」的实时回答。
2. **凭证/密钥相关**：公开数据不含任何 API key/token/密码；不回答「某平台的 key 是什么」。
3. **执行实际调用**：公开数据只提供调用规格，不含凭证；AI 无法仅凭公开数据发起真实 API 调用。
4. **账号/会话管理**：账号资产汇总、会话状态等数据不公开，不回答账号相关问题。
5. **额度精确统计**：额度总量/剩余值口径不统一（token/元/次），不做跨平台精确汇总比较。
6. **推断凭证存在性**：实例存在不代表凭证存在；不基于实例/能力推断凭证状态。

---

## 分析优先级

AI 代理在回答资源相关问题时应按以下优先级组织分析：

### 第一优先级：实例可用性

- 数据源：`instances` 表
- 筛选条件：`状态=可用`，且 `剩余额度快照` > `安全余量`（当两者都有值时）
- 理由：可用且有额度是路由的先决条件

### 第二优先级：能力匹配

- 数据源：`capabilities` 表
- 筛选条件：`类别` / `模型族` / `逻辑模型` 匹配任务需求
- 理由：先确定「要哪个能力」，再在可用实例中选

### 第三优先级：路由优先级与限速

- 数据源：`instances` 表
- 筛选条件：在候选可用实例中按 `路由优先级`（越小越优先）排序，结合 `限速` 评估是否够用
- 理由：多个可用实例并存时，用路由优先级和限速做最终取舍

### 第四优先级：风险提示

- 数据源：`instances` 表
- 筛选条件：`状态=额度耗尽/失效/待验证` 的实例
- 理由：让使用者知道哪些资源不可用或需人工处理，避免误用

---

## 读取顺序

1. 先读 `manifest.json`、`schema.json` 了解表结构与字段类型。
2. 读 `capabilities`（能力定义）：确定有哪些能力、怎么调用。
3. 读 `instances`（实例状态）：结合能力看具体实例的额度/限速/状态。
4. 做路由决策时：以 `instances.状态` + `剩余额度快照` 筛可用实例，再按 `路由优先级`/`限速` 排序。

---

## 计划制定规则

当 AI 需要基于本项目数据制定资源使用计划时：

1. 先确定任务需要的能力类别和模型族（查 `capabilities`）。
2. 列出满足条件的可用实例（`instances.状态=可用`，额度充足）。
3. 优先选择 `路由优先级` 数值小、`限速` 满足需求的实例。
4. 标注需要人工介入的点（如实例 `状态=待验证/额度耗尽`、或需要补充额度）。
5. 计划中不包含任何凭证信息；实际调用所需的凭据注入由本地 `adapter_id` 对应的 adapter 完成。

---

## 错误分析规则

当分析额度或状态相关的「异常」时：

1. `状态=额度耗尽`：该实例额度已用完，需等待重置（`重置规则=周期重置` + `额度重置日`）或补充额度。
2. `状态=待验证`：该实例尚未完成可用性验证，不应用于实际调用。
3. `状态=失效`：该实例不可用，应从路由候选中排除。
4. `剩余额度快照` <= `安全余量`：接近耗尽，应优先使用其他实例。
5. 当 `额度总量`/`剩余额度快照` 缺失时：不要臆造数值，如实说明数据缺失。

---

## 时间范围处理

1. `instances.额度重置日` / `额度到期日`：用于判断周期重置型实例的额度何时恢复、一次性额度何时到期。
2. `上次验证` / `下次验证`：用于判断实例的验证新鲜度——超过 `下次验证` 未重新验证的实例，可用性存疑。
3. 所有日期字段以同步时的 `generated_at` 为基准解释；数据每日同步，跨天查询时以最新数据为准。
4. 不基于 `剩余额度快照` 推算未来某时刻的精确额度（快照非实时，无法外推）。

---

## 数据不足时的处理

当数据不足以回答问题时，AI 代理应：

1. **明确说明数据缺失**：如 `剩余额度快照` 为空，说明「该实例无额度快照数据，无法判断当前剩余额度」。
2. **不臆造**：不补造额度数值、不虚构实例、不推断凭证状态。
3. **提示查询公开范围**：如需凭证/账号/实时额度信息，明确告知这些数据不在公开范围内，需要本地或人工确认。
4. **缩小答案范围**：只基于公开数据能支撑的结论回答，超出部分标注「超出公开数据范围」。

---

## 禁止推断

1. **禁止推断凭证存在或有效**：实例存在 ≠ 凭证存在，凭证信息不公开。
2. **禁止把额度快照当实时值**：不得断言「此刻还剩 N 额度」。
3. **禁止推断本地环境**：`缺失环境变量` 等本地配置信息已排除，不推断。
4. **禁止跨平台精确汇总**：额度单位不一致（token/元/次），不做精确加总。
5. **禁止推断平台信誉/合规**：`认证方案` 只是调用方式，不代表平台资质。

---

## 输出要求

1. 引用实例/能力时使用唯一键：`capability_id`（能力）、`instance_id`（实例）。
2. 给出额度/限速时标注数据口径（快照 vs 实时、单位）。
3. 实例状态用受控词汇：可用 / 待验证 / 额度耗尽 / 冷却中 / 失效。
4. 涉及路由建议时，说明排序依据（状态 → 额度 → 路由优先级 → 限速）。
5. 输出不得包含任何疑似凭证的内容；如用户索要 key/token/密码，明确拒绝并说明公开范围。
