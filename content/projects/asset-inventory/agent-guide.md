# AI 使用规则

**适用项目:** `asset-inventory`（工具资产明细表）
**配套文件:** `summary.md`（项目语义摘要）、`public/projects/asset-inventory/` 下的 `manifest.json` / `schema.json` / `status.json` 及表数据。

本文件规定 AI 工具在使用工具资产明细表数据时的任务边界、资源选择优先级、读取顺序、计划与资源分配规则、时间处理、数据不足处理、禁止推断与输出要求。所有规则均基于本项目真实的 1 张公开导出表（`assets`）及 8 个字段，不得超出 schema 与 manifest 描述的字段和关系范围。

---

## 适用任务

本项目的数据适合支撑以下任务：

1. **资源发现**：基于 `assets` 表，按「类型」「层级」「状态」等维度筛选可用资源，回答「郭老师有什么资源」。
2. **资源选择**：基于任务需求（如"生成图片"、"搜索信息"、"调用模型"），在资产目录中选择合适的工具，并给出选择理由。
3. **成本分析**：基于 `assets.成本` 字段，比较同类资源的费用差异，辅助成本敏感的资源选择决策。
4. **状态跟踪**：基于 `assets.状态` 字段，标注各资源的当前可用性，识别需要关注的建设中或已归档资源。
5. **工具比对**：基于 `assets.模型` 和 `assets.说明` 字段，比对多个工具的模型能力与适用场景。

---

## 不适用任务

本项目的数据**不适合**支撑以下任务，AI 应主动拒绝或转人工：

1. **资源健康监控**：本项目仅记录资源的元数据（名称、类型、链接、状态等），不包含运行状态监控信息（如延迟、可用率、错误率），无法判断资源是否正在正常运行。
2. **API 调用代理**：本项目不提供 API 调用能力，仅提供资源清单和链接。AI 工具需自行建立连接。
3. **跨项目资源分配决策**：本项目的资源选择不应与其他项目（如 `learning-english` / `teacher-growth` 等）的业务数据混合做决策。
4. **写回飞书源数据**：本数据为只读公开导出，AI 不得声称已修改飞书源表；任何「建议更新资源」只能以建议形式输出，由用户在飞书中执行。
5. **个人身份或隐私推断**：公开数据已经过 PII 与敏感信息扫描，AI 不得从数据中尝试还原或推断任何个人身份信息。

## 分析优先级

当任务可由多种资源完成时，按以下优先级选择资源：

1. **优先选 `状态` = "🟢 使用中" 的资源**：建设中或已归档的资源不应作为首选。
2. **优先选 `层级` 匹配任务层级的资源**：
   - 架构决策类任务 → 优先「架构决策层」
   - 批量执行类任务 → 优先「批量执行层」
   - API 调用类任务 → 优先「API 聚合层」
   - 搜索/检索类任务 → 优先「免费检索层」
3. **优先选成本低的资源**：同类资源中，优先选 `成本` 标注为"免费"或成本较低的。
4. **优先选 `模型` 能力匹配的资源**：当任务需要特定模型能力时，优先选择 `模型` 字段包含该模型的资源。
5. **优先选 `说明` 字段中明确提及适用场景的资源**：`说明` 字段包含更详细的资源用途描述，有助于精准匹配任务需求。

## 读取顺序

首次接入本项目时，按以下顺序读取，逐步建立上下文（与 `summary.md` 的「推荐读取顺序」一致）：

1. `public/projects/asset-inventory/status.json` — 先看 `sync_status` / `is_stale` / `last_success_at`，stale 时须在输出中声明数据可能过期。
2. `public/projects/asset-inventory/manifest.json` — 确认 1 张表、记录数与校验和。
3. `public/projects/asset-inventory/schema.json` — 建立字段类型模型，注意选择字段的 `options` 取值。
4. `content/projects/asset-inventory/summary.md` — 建立业务语义与字段含义认知。
5. 本文件（`agent-guide.md`）— 加载分析规则与禁止推断。
6. 按任务读取具体表数据（`tables/assets/records-XXXX.json`）。任务到读取优先级的映射：
   - **资源发现**：按 `类型` / `层级` / `状态` 组合筛选 `assets` 表。
   - **资源选择**：按 `层级` 匹配任务 → 按 `状态` 筛选可用 → 按 `成本` 和 `模型` 择优。
   - **成本分析**：按 `类型` 分组，读取 `成本` 字段比较。
   - **状态跟踪**：按 `状态` 分组统计，关注 `状态` 为"🟡 建设中"或"🔴 已归档"的记录。

## 资源选择规则

当 AI 工具需要选择资源执行任务时，遵守以下规则：

1. **优先用网关渠道**：当需要调用 AI 模型 API 时，优先选择 `类型` = "网关渠道" 的资源，因为它们通常提供统一的 API 入口和多种模型支持。
2. **任务类型匹配资源类型**：
   - 搜索类任务 → 优先选 `类型` = "AI搜索" 的资源（`层级` = "免费检索层"）
   - 生图任务 → 优先选 `类型` = "生图工具" 的资源
   - 编码任务 → 优先选 `类型` = "编码工作台" 或 "Agent环境" 的资源
   - 代码托管 → 优先选 `类型` = "代码托管" 的资源
3. **多资源备选**：当首选资源不可用时，应按优先级给出备选方案，并说明备选理由。
4. **成本敏感场景**：当任务明确要求低成本或免费方案时，优先选 `成本` 标注为"免费"的资源，其次选按量付费，最后选订阅制。
5. **不推荐已归档资源**：`状态` = "🔴 已归档" 的资源不应被推荐为可用选项，除非用户明确要求查看已归档资源。

## 时间范围处理

1. **以读取时的实际日期为"今天"**：所有时间相关的判断（如"最近""当前"）一律以 AI 实际读取数据时的日期为准，不得使用训练数据中的固定日期或假设日期。
2. **stale 数据须声明**：若 `status.json.is_stale: true`，输出中必须声明「当前展示的是上一次成功版本（`last_success_at`），最近一次同步失败」，不得将 stale 数据当作实时数据呈现。
3. **状态可能滞后**：`状态` 字段反映的是记录时的可用性，可能滞后于实际状态变更。AI 工具在尝试连接资源失败时应考虑状态已过时，并尝试备选资源。

---

## 数据不足时的处理

当数据不足以支撑某项结论时，按以下规则处理：

1. **某类型资源完全缺失**：当 `assets` 表中无某类型资源时，不得暗示该类型资源存在，应明确说明「该类型暂无记录」。
2. **某资源缺少模型字段**：当 `模型` 字段为空时，不得推断该资源不支持任何模型，只能说明「该资源的模型信息未记录」。
3. **成本信息缺失**：当 `成本` 字段为空时，不得假定为"免费"或"低成本"，只能说明「该资源的成本信息未记录」。
4. **样本量阈值**：任何统计结论（如"某层级下资源最多"）须基于不少于 3 条记录才可给出方向性判断；低于阈值时只描述事实，不下趋势性结论。
5. **主动声明而非沉默**：数据不足时必须显式声明限制，不得用模糊措辞掩盖样本不足；宁可给出「目前数据不足以回答」也不可编造。

---

## 禁止推断

AI 在使用本项目数据时，**禁止**做出以下推断（与 `summary.md` 的「不应做出的推断」一致）：

1. **禁止假定所有资源均已录入**：资产目录可能不完整，未记录的资源不代表不存在。
2. **禁止把 `状态` = "🟢 使用中" 等同于"当前可用"**：状态可能滞后于实际变更，连接失败时应考虑重试或切换。
3. **禁止把 `成本` 字段做精确比较**：成本为自由文本，非结构化金额，不同资源的成本描述口径可能不一致。
4. **禁止在不检查 `is_stale` 的情况下假定数据最新**：须先读 `status.json`，stale 时须声明。
5. **禁止凭空生成资源记录**：所有引用的资产必须存在于对应表（`assets`）的真实记录中；不得为满足任务需要而虚构工具名称、类型或链接。
6. **禁止跨项目合并分析**：本项目数据与其他项目（`learning-english` / `teacher-growth` 等）无业务关联，不得混合得出结论。
7. **禁止从公开数据反推飞书源表结构**：公开数据受视图与字段白名单裁剪，系统字段（创建人、修改人、创建时间、最后更新时间）已排除，不代表飞书 Base 的完整结构。
8. **禁止将资源链接视作当前有效的连接凭证**：`链接` 字段为资源的访问地址，可能因资源下线、地址变更或访问权限限制而失效，AI 工具应自行验证可访问性。

## 数据口径说明

### 类型（资源大类）

`assets.类型` 字段的取值为以下 8 种：

| 类型 | 含义 | 典型资源 |
|---|---|---|
| 网关渠道 | 统一的 AI 模型 API 入口 | AI Hub 网关、DeepSeek 官方、OpenRouter |
| 聚合客户端 | 聚合多个 AI 服务的客户端应用 | Cherry Studio 网关 |
| AI搜索 | 搜索引擎或 AI 搜索工具 | AI搜索×7 工具集 |
| 编码工作台 | 在线编码/开发环境 | Trae Work |
| Agent环境 | 自主 Agent 运行环境 | Antigravity |
| 代码托管 | 代码仓库托管平台 | GitHub 仓库 |
| 生图工具 | AI 图片生成工具 | 各生图工具 |
| 其他 | 其他类型的数字资源 | — |

### 层级（架构层级）

`assets.层级` 字段的取值为以下 4 种：

| 层级 | 含义 | 典型资源 |
|---|---|---|
| 架构决策层 | 统领全局的架构决策、工具编排、资源分配中心 | AI Hub 网关、组件编排器 |
| 批量执行层 | 批量/自动化执行任务的工作台和流水线 | Trae Work、Antigravity |
| API聚合层 | 聚合多个 API 渠道的统一入口 | OpenRouter、Cherry Studio 网关、DeepSeek 官方 |
| 免费检索层 | 免费/低成本的搜索引擎和检索工具 | AI搜索×7 工具集 |

### 状态（可用性）

`assets.状态` 字段的取值为以下 3 种：

| 状态 | 含义 | 选择优先级 |
|---|---|---|
| 🟢 使用中 | 当前活跃可用 | 首选 |
| 🟡 建设中 | 正在建设或测试中，尚未稳定 | 备选，需在输出中说明 |
| 🔴 已归档 | 已停止使用或废弃 | 不推荐，仅用户明确要求时查看 |

## 输出要求

1. **声明数据来源**：每项资源推荐须标注所基于的表、字段与筛选条件（如「基于 `assets` 表中 `类型` = "网关渠道" 且 `状态` = "🟢 使用中" 的记录」）。
2. **声明时效与 staleness**：若 `is_stale: true`，输出开头须声明；涉及「当前可用」等判断须说明所用状态字段的时效性局限。
3. **给出具体的选择理由**：推荐资源时，须说明推荐理由（层级匹配、成本优势、模型能力匹配等），并给出备选方案。
4. **结论分级**：区分「事实陈述」（直接来自数据）、「统计观察」（基于聚合）、「建议」（基于规则推断），不得混为一谈。
5. **不越界**：输出不得包含禁止推断清单中的任何内容；遇到不适用任务时，明确说明原因并转人工。
6. **语言**：面向用户的输出使用中文；字段名与表名保留原始中文/英文 slug 形式以便核对。
