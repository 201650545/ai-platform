## 项目用途

工具资产明细表是**郭老师（201650545）个人数字资产的统一目录**，聚合了全部 AI 工具、API 渠道、网关、聚合客户端、编码工作台、Agent 环境、代码托管与生图工具等资源。它在「三端资源整合」架构中承担**唯一真源**的角色：本地扫描脚本更新飞书表，feishu-data-hub 自动导出到 GitHub Pages，AI 工具（ChatGPT 镜像版/GPT-5.6 extend、Claude 5 Sonnet 等）通过 GitHub Pages 静态 JSON 读取完整资源清单，据此知道「郭老师有什么资源」并开始工作。

它解决的核心问题是：AI 工具和郭老师本人都无法快速回答「我有什么资源、各是什么状态、怎么连接」。分散在浏览器书签、本地配置文件和记忆中的工具、API 渠道和网关，需要一个统一的、AI 可读的资产目录。本项目通过飞书多维表格的 8 个字段和 4 个层级（架构决策层/批量执行层/API 聚合层/免费检索层），以「类型」标签区分资源大类，以「状态」标注可用性，以「层级」标明在架构中的位置，让 AI 工具能自主选择合适的资源来完成任务。

---

## 核心目标

1. **资源统一编目**：将分散的数字资产（AI 工具、API 渠道、网关、聚合客户端、代码托管、生图工具等）统一录入飞书多维表格，以「类型」标签区分大类，按「层级」组织架构位置。
2. **状态可追踪**：通过「状态」字段（🟢 使用中 / 🟡 建设中 / 🔴 已归档）标注每个资源的当前可用性，辅助 AI 工具做资源选择决策。
3. **成本可感知**：通过「成本」字段记录每个资源的费用信息（如免费/按量付费/订阅制），辅助 AI 工具做成本敏感的资源选择。
4. **AI 可读取**：通过 feishu-data-hub 自动导出到 GitHub Pages，AI 工具通过 HTTP 读取完整 JSON 清单，无需飞书权限。
5. **本地可同步**：通过本地扫描脚本（Phase 2）自动将本地项目变更同步到飞书表，保持资产目录的实时性。

## 常见分析问题

下列问题均可仅凭本项目的公开数据回答。

### 1. 当前有哪些可用的 API 网关？

以 `assets` 表为主，按 `类型` = "网关渠道" 且 `状态` = "🟢 使用中" 筛选，查看 `工具名称`、`模型`、`链接`、`成本` 字段。

### 2. 某类资源有多少个可用选项？

按 `类型` 分组，统计 `状态` = "🟢 使用中" 的记录数，再按 `层级` 细分。

### 3. 哪些工具处于建设中，何时可用？

按 `状态` = "🟡 建设中" 筛选，查看 `说明` 字段了解当前建设进度和预期可用时间。

### 4. 按成本比较同类资源？

按 `类型` 和 `成本` 字段组合筛选，比较同类资源的费用差异，辅助成本敏感的资源选择决策。

### 5. 在某个层级下有哪些资源？

按 `层级` 筛选，查看该层级下的所有资源及其 `工具名称`、`类型`、`状态`、`模型`。

## 数据更新时间与时效性

- **同步层级**：以 `config/projects/asset-inventory.yaml` 的 `schedule.tier` 配置为准（`hourly`）。
- **时间戳来源**：以 `status.json` 的 `last_success_at` 为准；`build_id`（`manifest.json` / `status.json` / `catalog.json`）反映本次构建版本。
- **staleness 判断**：当 `status.json.sync_status` 为 `failed` 或 `stale`、`is_stale: true` 时，展示的是上一次成功版本，最近一次同步尝试失败。分析前应先检查 `is_stale`。

## 数据公开范围

本项目公开数据遵循 Feishu Data Hub 的三层防护：

1. **视图级**：仅导出「AI 公开导出」视图（`source.export_view_name`），视图之外的记录与字段不导出。
2. **字段级**：配置显式字段白名单（见 `config/projects/asset-inventory.yaml` 的 `tables[].fields`），禁止通配符，禁止敏感字段名。系统字段（创建人、修改人、创建时间、最后更新时间）不在导出范围。
3. **内容级**：导出时与部署前双重扫描，扫描凭证/Token 模式、PII、高熵字符串、Token 前缀与禁止文件；命中即中止整个部署。

## 已知限制

1. **单表无关联**：本项目仅 1 张表，无表间关联，所有筛选与分析均在同一表内完成。
2. **链接字段为纯文本**：`链接` 字段为自由文本，非超链接类型，AI 工具需自行解析 URL 格式。
3. **成本字段为自由文本**：`成本` 字段为自由文本，非结构化金额字段，涉及费用比较时需注意文本口径差异。
4. **模型字段为自由文本**：`模型` 字段为自由文本，非结构化多选字段，同一资源的模型列表以逗号分隔，AI 解析时需注意格式一致性。
5. **记录覆盖不完整**：资产目录仅包含已录入的记录，并非全部数字资产的完整清单；新增资源需手动录入飞书表。
6. **状态更新依赖人工维护**：`状态` 字段反映的是记录时的可用性，可能滞后于实际状态变更；AI 工具在尝试连接资源失败时应考虑状态可能已过时。
7. **自动生成摘要的局限**：`public/projects/asset-inventory/summary.md` 由代码机械生成，仅含表清单与字段列表，不含业务语义；语义内容以本文件为准。

## 不应做出的推断

1. **不应假定所有资源均已录入**：资产目录可能不完整，未记录的资源不代表不存在。
2. **不应把 `状态` = "🟢 使用中" 等同于"当前可用"**：状态可能滞后于实际变更，AI 工具在连接失败时应考虑重试或切换备用资源。
3. **不应把 `成本` 字段做精确比较**：成本为自由文本，非结构化金额，不同资源的成本描述口径可能不一致。
4. **不应在不检查 `status.json.is_stale` 的情况下假定数据为最新**：stale 状态下展示的是旧版本数据。
5. **不应从公开数据反推飞书源表结构**：公开数据受视图与字段白名单裁剪，不代表飞书 Base 的完整结构（系统字段已排除）。
6. **不应凭空生成资源记录**：所有引用的资产必须存在于对应表（`assets`）的真实记录中；不得为满足任务需要而虚构工具名称、类型或链接。
7. **不应跨项目合并分析**：本项目数据与其他项目（`learning-english` / `teacher-growth` 等）无业务关联，不得混合得出结论。
