## 0. 一页摘要

永涛拥有大量数字资源（各厂商 API、免费额度、账号权益、工具、网关），但使用方式高度依赖人工记忆与手动配置。本体系把这些资源**统一收集到飞书多维表格**（配置真源，AI 可读的可执行规格库），凭证安全留在本地；**本地调度器**（本地进程 + SQLite）按额度/轮换规则自主分配调用；AI 用 **Open CLI**（独立 Chrome Profile）以永涛本人身份完成调研、验证、领取；**画布**作为 AI 的运营观察台。飞书经**公开数据桥**（白名单脱敏 + 额度区间模糊化）导出 GitHub Pages，供最先进模型连接器实读仓库、持续优化架构。

**核心承诺：不降质、不换模型、不偷偷省钱。额度到点自动停，用尽自动跳下一个实例。**

> **「不换模型」定义（永涛已拍板）**：以**逻辑模型（canonical model）**为轮换锁定单位——同一底层模型即可互切，轮换只发生在同一 `routing_group` 内（默认 = capability_id）。跨模型、跨质量等级**禁止切换**。

## 1. 项目定位

### 1.1 一句话
让本地 AI 拥有「自己的钱包和工具箱」——读到资源库就能自取自用，不需要人一次次提供密钥和说明。

### 1.2 问题（现状痛点）
| 痛点 | 现状 |
|------|------|
| 资源散落 | API/免费额度/账号/工具分布在几十个平台，无统一目录 |
| 人工配置 | Cherry Studio 已解决网关聚合，但让 Claude Code 用指定模型仍要人反复调 |
| 额度难控 | 各家免费额度用完即失效，无自动切换/停止机制 |
| 信息难验证 | 网上免费资源真假难辨，需登录实测 |

### 1.3 目标
1. 统一收集、分类、验证永涛的数字资源，形成「AI 可读」的资源库。
2. 让本地 AI 自主分配调用，无需人逐步指引。
3. 实现密钥池轮换 + 额度到点停止的智能调度。
4. 用免费/低价 AI 批量执行调研与验证，人工仅在 AI 判定解决不了时介入。
5. 通过 GitHub + 高级 AI 问诊（多模型互校验），持续优化体系架构。

### 1.4 边界（不做什么）
- 不是中转站——**不降级模型、不换底层模型**（轮换锁 `routing_group`）。
- 凭证值**绝不出设备**，只留凭证 ID 在表里；**Secret 不进配置平面**。
- 不强制人工参与——是「需要人工时找人工」，不是「必须人工」。

## 2. 体系总览（四主角 + 真源分工）

```
┌─────────────────────────────────────────────────────────────────────┐
│                    飞书多维表格（配置真源）                            │
│  账号 │ 凭证池 │ 资源能力 │ 资源实例 │ 工具资产 │ 任务日志               │
│  —— 能力/实例分离；Secret 只声明 auth_scheme+allowed_hosts           │
└───────────────┬─────────────────────────────────────────────────────┘
                │ ① sync：飞书配置 → 本地 SQLite（配置流向运行时）
                ▼
┌─────────────────────────────────────────────────────────────────────┐
│                        本地执行层（设备内）                           │
│  ┌────────────┐   ┌────────────┐   ┌────────────────────────────┐   │
│  │  调度器     │   │  Open CLI  │   │  画布                       │   │
│  │ 本地进程    │   │ 独立Profile│   │ 运营仪表盘（直读SQLite）     │   │
│  │ base_url   │   │ 永涛已登录 │   │ （Coverage 指标）            │   │
│  │ 代理+SQLite│   │ Chrome点击 │   └────────────────────────────┘   │
│  └────────────┘   └────────────┘                                    │
│  ┌──────────────────────────────┐  ┌─────────────────────────────┐  │
│  │ 凭证库 credentials.json       │  │ SQLite（运行时真源）         │  │
│  │ （值不出设备，不入库不云同步） │  │ lease/幂等UNIQUE/额度/cooldown│  │
│  └──────────────────────────────┘  └─────────────────────────────┘  │
└───────────────┬─────────────────────────────────────────────────────┘
                │ ② 摘要同步：SQLite 运行态 → 飞书（周期/事件）
                │ ③ 公开数据桥导出（白名单+区间模糊化+敏感扫描）
                ▼
┌─────────────────────────────────────────────────────────────────────┐
│                   GitHub Pages（Public Read Model）                  │
│  manifest/capabilities/health 快照 → ChatGPT/Claude.ai 连接器实读    │
│  → 最先进模型审查架构 → 建议回写方案书（docs/ai-advice/）            │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.1 四主角职责
| 主角 | 职责 | 真源定位 |
|------|------|---------|
| **飞书多维表格** | 长期认识：资源配置唯一真源，可执行规格库 | **配置真源** |
| **本地调度器 + SQLite** | 即时监控：轮换、额度累计、到点停止、任务锁 | **运行时真源** |
| **Open CLI** | 独立 Profile 执行任务状态机，以永涛身份操作 | 执行器 |
| **画布** | 运营仪表盘（Coverage）+ AI 搜索聚合（后置） | 可视化 |

### 2.2 三端数据流
- **配置流**：飞书 → SQLite（sync worker，周期拉取）
- **运行态回流**：SQLite → 飞书（周期/事件同步**摘要**，非每次请求）
- **数据桥**：飞书 → Exporter（白名单 DTO + 脱敏 + 区间模糊化）→ GitHub Pages → 高级 AI 实读

### 2.3 真源分工
| 平面 | 谁 | 存什么 |
|------|-----|--------|
| 配置真源 | 飞书 | 能力定义 / 账号 / 凭证引用 / 实例登记 / 人工可视化 |
| 运行时真源 | 本地 SQLite | 实时额度计数 / cooldown / **lease / 幂等 UNIQUE / 状态转换** |

> **飞书不承担实时额度计数、不做并发锁**（官方不支持并发写）。所有事务性操作以 SQLite 为真源。

## 3. 数据层设计

### 3.1 飞书多维表格（6 表体系，详见 `docs/多维表格设计方案.md` v0.3）
| 表 | 用途 | 关键字段 |
|----|------|---------|
| 账号资产汇总 | 账号与登录状态 | account_id/认证方式/会话状态/Profile引用 |
| 凭证池 | 认证材料引用（只管认证） | credential_id/凭证类型/有效期/本地存储后端 |
| 资源能力规格表 | **逻辑能力定义**（模型+质量+协议+安全边界） | capability_id/逻辑模型/质量等级/auth_scheme/**allowed_hosts**/**routing_group** |
| 资源实例表 | **每个实际入口**（平台+凭证+结构化额度+验证方式） | instance_id/所属能力/结构化额度/验证策略/状态 |
| 工具资产明细表 | 工具/软件/网关注册（已建） | 名称/类型/模型/链接/层级/成本/状态 |
| 自动化任务日志 | 任务状态机 + 审计留痕（真源在 SQLite） | 幂等键/target_config_hash/lease/状态机/evidence_hash |

### 3.2 能力与实例分离 + 单一真源
```
一个逻辑能力（capability）：
  capability_id     = cap-llm-deepseek-v4
  逻辑模型          = deepseek-v4-flash      ← 轮换锁定模型
  质量等级          = T1                     ← 不得降级
  routing_group     = rg-deepseek-v4         ← 轮换组唯一真源（默认=capability_id）

挂多个实际实例（instance）：
  instance_01: 平台=厂商A  credential=main    剩余额度=812万  status=可用
  instance_02: 平台=厂商B  credential=alt     剩余额度=300万  status=可用
  instance_03: 平台=厂商C  credential=free    剩余额度=0      status=额度耗尽

轮换 = 只换实例、不换能力；routing_group 只在能力表维护，实例继承（Lookup），杜绝两处手填。
```

### 3.3 Secret 边界（安全核心，v0.3 关键修正）
```
表格里：credential_id = "siliconflow-main"            ← 只有凭证 ID
能力表：auth_scheme = bearer / allowed_hosts = api.siliconflow.cn
         ← 飞书只声明「认证方案 + 允许主机」，不存 {{CREDENTIAL}} 请求头模板
本地：   config/credentials.json: { "siliconflow-main": { key: "sk-...", ... } }
         ← 受信 adapter 只在向 allowed_hosts 发请求时注入 Secret

规则：
  · Secret 只能由本地受信 adapter 注入，配置平面不能指定任意传输模板
  · 跨域 redirect 不继续携带 Authorization
  · 网页内容一律视为不可信输入，不能修改 Secret policy
  · credentials.json 目录排除 .gitignore + 本地网盘同步
  · 凭证值疑似外泄 → 立即停用并通知
```

## 4. 执行层设计

### 4.1 本地智能调度器（核心引擎，本地进程 + base_url 代理 + SQLite WAL）
- **形态**：单进程监听 `127.0.0.1`，Claude Code 等通过 `base_url` 指向本地端点。不上 Redis/MQ。
- **模块**：`Proxy → Router → Provider Adapter → Quota Ledger → SQLite → Sync/Outbox`
- **路由**：`先过滤，再排序`——过滤：质量/模型/状态/额度余量/冷却；排序：额度到期、剩余、优先级、成本。
- **错误分类**（不能笼统 fallback）：
  ```
  quota_exhausted → EXHAUSTED（硬停止）
  429/rate_limit  → COOLDOWN
  401/403         → CREDENTIAL_INVALID
  model_not_found → CONFIG_INVALID
  5xx/network     → 短暂失败，可切同能力实例
  质量/模型不匹配 → 禁止切换
  ```
- **响应内容校验**：不只看 HTTP 状态码，200 里包错误（choices 缺失 / finish_reason=error）也触发 cooldown。
- **流式安全**：流式一旦已向客户端输出内容，**不再透明切换实例重放**（避免重复回答/计费）；只有未输出任何字节时才允许切。
- **credential 互斥锁**：单个凭证"当前占用"锁，防同凭证并发打爆平台风控。
- **硬停止**：额度达安全余量立即标 `EXHAUSTED`。
- **secret redaction**：日志白名单式——只输出预声明允许记录的字段。

### 4.2 Open CLI（执行手，独立 Profile + 任务状态机）
- 控制**独立、不开同步的 Chrome Profile**（避免 session 云端同步、缩小提示注入身份面）。
- 正式任务状态机：`PENDING → LEASED → RUNNING → SUCCEEDED | FAILED | NEEDS_HUMAN`。
- 幂等键 = `task_type + target_id + verifier_version + target_config_hash`；lease/UNIQUE 在 SQLite 事务。
- **lease 恢复**：周期性"清理"任务扫描过期 LEASED/RUNNING → PENDING；`attempt_no` 上限 3，超限转 NEEDS_HUMAN。
- **NEEDS_HUMAN 阻塞**：不自动重试，直到人工清除。
- **单写者 = 字段级 PATCH**：调度器只 PATCH 额度列，Open CLI 只 PATCH 状态/证据列，**不做整行覆盖**。
- 结构化回写：`{status, resource_id, changes, evidence_hash}`；evidence 存哈希+脱敏摘要，不传整页截图。
- 网页遇到的 MFA/验证码/身份确认/支付 → 立即 `NEEDS_HUMAN`。

### 4.3 画布（观察台，仪表盘优先）
- **功能1 · HTML 运营仪表盘（优先）**：**直读本地 SQLite**（不打飞书 API）。只答 6 问：当前用哪个实例 / 还有几个同模型备用（Coverage）/ 哪个快没额度 / 哪个 cooldown / 哪个需人工 / 哪个验证过期。
- **功能2 · AI 搜索聚合（后置）**：输出只进**候选**，走 `发现 → 候选 → 验证 → 入库`，验证成功才 AVAILABLE。

### 4.4 中央平台（保留）
- feishu_sync / github_manager 组件继续保留；AI Hub 网关已删（Cherry Studio 已覆盖）。

## 5. 工作流

### 5.1 周期1 · 建立（收集 → 验证 → 领取 → 记录）
```
1. 收集    AI 调研新资源 → 直接在表3/表4建记录、状态置"待验证"（候选态落点，不新开候选表）
2. 验证    登录实测：先 HTTP 探测，后浏览器；三层防重（next_verify_at / 配置哈希 / SQLite UNIQUE）
3. 领取    能自动则自动，需人工则停下问用户（NEEDS_HUMAN 阻塞）
4. 记录    回写：能力（表3）+ 实例（表4）+ 凭证引用（表2）+ 任务日志（表6）
           · 实例置"可用"前先跑模板 lint（JSON 能 parse）
```

### 5.2 周期2 · 使用
```
本地 AI 干活时：
  1. 读飞书/本地 SQLite → 找可用能力 + 可用实例
  2. 有 → 调度器按 routing gate 过滤排序 → 注入凭证调用
  3. 无/不足 → 报告缺口，回到周期1 收集
```

### 5.3 高级 AI 问诊（架构持续优化，多模型互校验）
```
触发：方案初稿 / 每次关键架构变更 / 自认为不够好
方式：GitHub 链接（上下文）+ 细致提示词 → 发 GPT 5.6（镜像版 extend 可实读）/ Claude Sonnet
       · 镜像版（问达宝）开 extend 模式可读 GitHub 公开仓库
       · 读不了飞书表格本身 → 靠设计方案文档（已入仓）间接理解
接收：MD 落档 docs/ai-advice/；回复结构：结论/建议/风险/步骤/需确认
交叉校验：多个模型互相校验架构（如 GPT-5.6 + Claude Sonnet 5 第二意见）
```

### 5.4 人工介入原则
- 动态判断：AI 判定解决不了 → 立即停下通知，`NEEDS_HUMAN` 阻塞不重试。
- 人工只需：点验证码、付一次款、指导陌生流程、做最终决策。

## 6. 安全边界

1. **凭证不出设备、Secret 不进配置平面**：表里只有 ID；能力表只声明 auth_scheme + allowed_hosts；受信 adapter 注入。
2. **Chrome 独立 Profile**：Open CLI 用独立、不开同步的 Profile；session/cookie 不接触日常账号、不上云同步。
3. **日志白名单式**：只输出预声明允许记录的字段（request_id/instance/model/latency/tokens/result），凭证、Cookie、Authorization、URL query 一律不落盘。
4. **本地凭证目录隔离**：credentials.json 目录排除 `.gitignore` + 本地网盘同步（OneDrive/坚果云等）。
5. **禁止剪贴板中转凭证**、**密钥不通过命令行/env 传子进程**（走内存/管道）。
6. **以本人身份但有边界**：域名 allowlist + 动作类别限制；MFA/验证码/支付 → NEEDS_HUMAN。
7. **公开数据桥白名单 DTO**：从零构造，不做 blacklist 删除；**额度区间模糊化** + 时间戳 + GitHub Action 敏感字段扫描（git 历史不可逆）。不公开：account_id、credential_id、手机绑定、错误详情、内部路由、精确额度。

## 7. 落地里程碑

| 阶段 | 交付物 | 验收 |
|------|--------|------|
| **M0 方案定稿** | 方案书 v1.0（含两份问诊结论 + 6 表 v0.3） | 无悬而未决 |
| **M1 单模型双实例自动切换** | localhost endpoint → 实例A → 触发 → 实例B，模型不变 | ①人工把 A 调不可用自动切 B；②**A 模拟返回超时/401，N 次失败内自动切 B 并记 cooldown**；③**同平台多 key 轮换**；④请求另一模型→明确失败（不许偷换） |
| **M2 本地状态 + 可观测性** | SQLite（quota/cooldown/lease/审计）+ 最小 HTML 仪表盘（直读 SQLite） | 一眼看到"现在到底在用谁" |
| **M3 飞书规格库同步** | 配置 飞书→SQLite；运行态摘要 SQLite→飞书（outbox 断网不丢） | 双向同步成立，形成运营系统 |
| **M4 自动验证闭环** | 任务调度 + lease + 幂等键 + target_config_hash + 清理任务 | 一个 HTTP provider 的 验证→更新→日志 闭环（先不浏览器） |
| **M5 Open CLI 人机协作** | 独立 Profile 发现/领取/需人工即停/结构化回写 | Open CLI 成为任务系统的 executor |
| **M6 AI 自主调研 + 问诊** | AI 搜索发现 → 候选 → 验证入库 → Public read model → 多模型问诊 | 搜索结果不直接入池 |

> **最小闭环（M0.5）**：`1 canonical model × 2 实例 × 2 凭证 × 1 本地代理 × 1 SQLite × curl 测试`——甚至先不接飞书。三个验收（正常→A / A exhausted→自动 B / 请求另一模型→明确失败）通过即证明核心承诺。
