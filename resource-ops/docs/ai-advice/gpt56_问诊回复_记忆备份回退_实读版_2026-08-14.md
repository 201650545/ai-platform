五个问题的直接回答（编号对应）
1. 【备份】还需不需要额外备份？Git + GitHub 够不够？

针对“Agent 把 STATE 写坏/删错”这一类逻辑故障，Git + GitHub 已经够了，不需要再造备份功能。

因为错误覆盖只产生了一个新 commit；只要旧历史没有被改写，旧 STATE.md blob 仍然在 Git 历史中，可以定位、比较和恢复。这与你现在“仓库 = 唯一真源”的设计也是一致的。
GitHub
+1

但 GitHub 远程本身不是独立灾备域：仓库误删、恶意/误操作 force push、凭证泄漏后的历史重写都可能影响远端历史。所以我的最低成本建议不是“第二套记忆系统”，而是按需 git bundle 离线快照：

Bash
git pull --ff-only
git bundle create ../ai-hub-memory-pre-change.bundle --all
git bundle verify ../ai-hub-memory-pre-change.bundle

只在重大仓库维护、协议迁移等风险动作前做；不用定时。Git 官方把 bundle 明确列为完整/增量备份手段。
git-scm.com

例外：如果正在处理泄露的 key，不要为了“保险”再新建一个包含泄露 key 的 bundle。

2. 【回退】STATE 被旧上下文整体覆盖后怎么恢复？

先定位：

Bash
git pull --ff-only

git log --oneline -- STATE.md

# 查看怀疑的提交到底删了什么
git show <BAD_COMMIT> -- STATE.md

如果这个错误 commit 基本就是一个应整体撤销的错误提交，推荐：

Bash
git revert <BAD_COMMIT>
git push

这是共享仓库最干净的做法：不删除历史，而是追加一个反向提交。
git-scm.com

如果错误 commit 里还有正确的 CHANGELOG.md / DECISIONS.md 内容，只想把 STATE.md 恢复成错误提交之前的版本，并且之后没有需要保留的 STATE 更新：

Bash
git restore --source=<BAD_COMMIT>^ -- STATE.md

git diff -- STATE.md

git add STATE.md
git commit -m "memory: restore STATE before <BAD_COMMIT>"
git push

git restore --source=<commit> 正是 Git 官方提供的“从其他提交恢复指定文件”的机制。
git-scm.com

不要把普通恢复写成：

Bash
git reset --hard ...
git push --force

因为那是在改写共享历史，而不仅仅是在修正记忆。

3. 【发现机制】怎样轻量检测静默语义覆盖？

这是我最建议修改的地方。

给 STATE 中每个仍然有效、不能无声丢失的状态项一个稳定 ID。

例如：

Markdown
# STATE.md

## 当前状态
- [S-20260814-01] 课件编排器运行于 :8791。
- [S-20260814-02] search_gateway 路径为 D:\项目\services\search_gateway。
- [S-20260814-03] 项目 X 当前卡点：等待 Y。

正常更新可以重写文字，但继续保留 ID。

如果确实应该删除：

Markdown
# CHANGELOG.md

- 2026-08-14 Claude DROP S-20260814-03 — Y 已解决，该卡点失效。

于是协议变为：

STATE 中任何已有 S-* ID 的消失，都不是普通重写，而是删除事件；必须同时在 CHANGELOG 追加 DROP <ID> — 原因。

然后 commit 前比较：

Bash
git diff --cached --word-diff=plain HEAD -- STATE.md

更进一步，用 hook 自动阻止“无 DROP 的 ID 消失”。

这样不需要理解自然语言语义，也能捕获你描述的主要事故类型：旧 STATE 里有 A/B/C，新 Agent 重建后只有 A/C，那么 B 的 ID 消失，commit 直接被挡住。

当前 AGENTS.md 虽然要求“单写者 + 整体重写”，但没有这样的删除守卫，所以串行化只能解决并发写冲突，解决不了 stale-context 的合法文本提交。这个结论是对 §2 规则的直接推论。
GitHub

4. 【回退粒度】只救回误删的一条，保留后续 Agent 更新怎么办？

不要恢复整个旧 STATE。

先找这条最后存在于哪个版本：

Bash
git log -p -- STATE.md

查看旧版本：

Bash
git show <GOOD_COMMIT>:STATE.md

如果已经采用 ID：

Bash
git show <GOOD_COMMIT>:STATE.md | grep 'S-20260814-03'

然后把这一条重新插入当前 STATE.md，检查当前状态差异：

Bash
git diff -- STATE.md

追加恢复事件：

Markdown
- 2026-08-14 GPT RESTORE S-20260814-03 — 从 <GOOD_COMMIT> 恢复，此前被误删。

最后：

Bash
git add STATE.md CHANGELOG.md
git commit -m "memory: restore S-20260814-03"
git push

也可以使用 Git 的交互式 patch 恢复：

Bash
git restore --source=<GOOD_COMMIT> --patch -- STATE.md

但因为 STATE.md 是整体重写，Git 很可能把大量文字放在同一个 hunk 中，所以对“一条事实”而言，git show 找出旧内容、手工插回当前最新版反而更安全。restore --patch 本身支持交互式选择 hunk。
git-scm.com
