## 风险

1.  **两个 Agent 并发写同一份 `验证记录_2026-08-10.md`**，若没有编号/分段协调，可能互相覆盖或产生冲突提交——这是 v1 完全没考虑的新风险点。
2.  Google OAuth 遇到未预期的 onboarding/二次验证时，Agent 可能"卡住"反复重试，浪费执行时间（0.5 节边界可缓解但不能完全杜绝）。
3.  免费额度政策随时会变，调研当天记录的数字几天后可能已过期，需要"验证时间戳"配合后续复核周期，而非当作永久事实。
4.  部分额度需要"实际发起一次真实调用"才能验证准确性（如 Colab 是否真给 GPU），过度谨慎拿不到准确数据，过度测试又会消耗永涛的真实额度——需要 Agent 严格把握"只看选项文案，不实际连接消耗"的边界。
5.  官网公开定价页与控制台实际额度可能不一致（常见运营套路），必须双源标注来源，不能只信一处。
6.  Mistral/Together 等免费层若已改为"强制绑卡才可用"，Agent 若按旧认知硬闯，存在被要求填支付信息、误触发实际扣费的风险。
7.  新增的 API endpoint/模型名/限流字段，若页面未明确说明，Agent 有编造数值的倾向，需要在 prompt 里反复强调"未说明就写未说明"。
