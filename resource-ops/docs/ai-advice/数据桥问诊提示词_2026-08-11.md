## 提示词（可直接复制）

```
你是一位资深的安全审计 + CI/CD 架构专家。永涛的「公开数据桥」已上线首跑成功，
现在请你对它的【安全边界】【工作流健壮性】【暴露成本】做三重审查。
请先打开下面的仓库阅读，再回答。

【背景】
永涛把飞书多维表格里的 AI 资源（能力规格 + 实例清单）通过 GitHub Actions 导出成
公开 JSON（GitHub Pages），供高级 AI（ChatGPT/Anthropic 官网连接器）直接读取，
省 API 钱。核心安全立场：凭证值绝不公开；精确额度不公开（只给区间）；
GitHub 历史不可逆，泄漏即事故。

【上下文（请先打开阅读）】
- 仓库主页：https://github.com/201650545/ai-resource-hub
- 公开产物（已上线）：https://201650545.github.io/ai-resource-hub/ 下的
  index.json / capabilities.json / instances.json / schema.json
- 导出器主代码：https://github.com/201650545/ai-resource-hub/blob/main/exporter/export.py
- 白名单/模糊化/扫描配置：
  https://github.com/201650545/ai-resource-hub/blob/main/exporter/config.json
- CI 工作流：https://github.com/201650545/ai-resource-hub/blob/main/.github/workflows/export-public.yml
- 体系方案书（§6.7 数据桥设计）：https://github.com/201650545/ai-resource-hub/blob/main/方案书.md

【当前实现概要】
- 白名单 DTO：只输出白名单字段、从零构造，不用黑名单删除
- 额度模糊化：剩余额度快照/额度总量/安全余量 三字段 → 额度状态区间
  （耗尽/接近安全余量/偏低<20%/中等20-50%/充足>50%/未知），原始数值随后丢弃
- 敏感扫描：对全部输出 JSON 逐条 regex（app_token/tbl_/cli_/api-key/secret/credential_id），
  命中即退出码非 0、中止部署
- 工作流：cron 每天 03:23 + workflow_dispatch(force)；concurrency 组防并发；
  environment=github-pages 读 Secret；stdlib 无依赖

【请审查的点】
1. 【安全 · 反推与绕过】额度区间是否可被反推精确值？例如「充足(>50%)」+ 公开的
   重置规则/重置日/额度单位，能否算出原始额度量级？敏感扫描 regex 有哪些绕过面
   （base64/unicode/拼接/字段名近义词/模板字符串）？跨表关联是否可能拼出敏感信息
   （如 capabilities 的 endpoint+请求体模板 与 instances 的所属能力 关联 → 拼出可调用接口）？
2. 【安全 · 字段级】白名单里哪些字段本身就有风险（如 允许主机/认证方案/健康探测/
   endpoint/请求体模板 公开后够不够被武器化）？「状态」字段若含内部运维信息会否泄漏操作节奏？
3. 【健壮性】飞书 token 过期/secret 轮换时工作流如何失败、如何告警？扫描命中中止后
   如何恢复（当前没有回滚/通知机制）？cron 每 7 天/每 30 天有没有渐进降级？
   产物校验只查文件存在，是否该查记录数突变（比如某天 0 条 = 拉取失败但部署成功）？
4. 【更省】数据是 daily 层级，每天全量拉取+重部署是否有必要？有无「只在数据变化时
   发布 / 构建 id 变化才部署」的更省方案？公开暴露是否必须 GitHub Pages（能否用
   GitHub 仓库文件本身当数据源，省掉 Pages 部署层）？
5. 【演进】后续要加 4 张核心表（工具/账号/权益/网关）时，这套白名单+模糊化+扫描
   怎么保持不退化？有没有更适合的通用化结构？

【输出格式】（严格按此结构）
- 结论（一页以内总评：这套防线当下是否可上线、最大短板是什么）
- 问题清单（按严重度：致命/高危/中/低，每条一句危害 + 具体触发场景）
- 优化方案（可直接落地的、给到 diff 级别建议：改哪行/加哪段/配置怎么调）
- 更省方案（如成立：改动量与收益对比）
- 风险（每条一句话）
- 实施步骤（编号，可执行）
- 需确认（你拿不准、需要永涛拍板的点）
```
