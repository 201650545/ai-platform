# 方案书 · 高级 AI 问诊提示词（内嵌版）

> 用途：**无法联网读 GitHub 链接**的 AI 会话（如问达宝等镜像站）使用
> 完整版见 `方案书问诊提示词_2026-08-10.md`（依赖模型能打开 GitHub 链接）
> 本版把方案书 + 多维表格设计核心直接内嵌，模型无需读外链即可审

---

## 提示词（整段复制，粘贴即发）

```
你是一位资深的 AI 系统架构评审专家。下面是完整的系统背景（已内嵌，无需打开外链），
请直接评审并回答文末 7 个问题。

【背景】
永涛是独立用户，拥有大量数字资源（各厂商 API、免费额度、账号权益、工具、网关）。
他构建「AI 自助资源运营体系」：资源统一收集到飞书多维表格（AI 可读的「可执行规格库」），
凭证值留在本地，本地调度器按额度/轮换规则自主分配调用；AI 用 Open CLI 以他本人身份
完成调研、验证、领取。核心承诺：不降质、不换模型、不偷偷省钱；额度到点自动停，
用尽自动跳下一个密钥。

【体系总览（四主角）】
1. 飞书多维表格 —— 数据中枢：AI 可读的可执行规格库（资源唯一真源）
2. 本地调度器 —— 即时监控：密钥池轮换、额度累计、到点停止
3. Open CLI —— 执行手：控制永涛已登录的 Chrome 点击/填写/导航
4. 画布 —— 观察台：AI 搜索聚合 + HTML 制作可视化
数据流：本地 → 飞书 → GitHub Pages 公开 JSON → 高级 AI 连接器读取审架构

【多维表格设计（4 张表）】
1. 账号资产汇总：平台 / 账号标识 / 登录方式(已登录|Google OAuth|手机短信|微信扫码|账号密码)
   / 绑定手机(复选框) / 凭证ID列表 / 状态(在用|停用|待绑定) / 备注
2. 免费资源大汇总（核心可执行规格库，18 字段）：
   资源ID(唯一键) / 资源名称 / 平台 / 类别(LLM API|生图|搜索|云GPU|...) / 状态(可用|额度耗尽|失效|待验证|待领取)
   / 调用方式(HTTP_REST|OPENCLI_BROWSER|CLI_TOOL) / endpoint / 模型列表 / 免费额度 / 已用剩余(数字)
   / 凭证ID(引用本地 config) / 需人工登录URL / 缺失环境变量 / 请求体模板 / 请求头模板
   / 获取方式备注 / 最后验证日期 / 关联账号(→表1)
3. 工具资产明细表：工具名称 / 类型 / 模型 / 说明 / 链接 / 层级 / 成本 / 状态
4. 自动化任务日志：任务ID / 类型(调研|验证|领取|抓额度|调度|清理) / 执行Agent / 起止时间 / 结果
   (成功|失败|需人工) / 错误信息 / 关联资源ID(→表2) / 回写内容

关系：表1 1──< 表2（关联账号）；表2 1──< 表4（关联资源ID）；表3 独立。
凭证机制：表里只存凭证 ID，值存本地 config/credentials.json，绝不出设备。

【硬约束（方案不可违背）】
1. 凭证值绝不出设备
2. AI 以本人身份执行，被判定需要人工时立即停下通知
3. 密钥池轮换透明：不降级模型、不换低质渠道

【7 个待决策问题】
1. 多维表格：4 张表设计是否最优？免费资源表是否真的够「AI 可执行」？
   密钥池（同模型多厂商轮换）要不要拆独立表？表4 日志能否支撑「避免重复验证」闭环？
2. 调度器形态：密钥池轮换 + 额度停止，最简可靠实现是本地进程 + base_url 代理吗？
3. Open CLI 与飞书回写闭环：调研/验证/领取结果如何可靠回写表、避免重复验证？
4. 画布两功能（AI 搜索聚合 / HTML 制作可视化）优先级？
5. 安全模型：凭证 ID 引用 + 本地读取之外，还有哪些被忽略的泄漏路径？
6. 问诊机制：GitHub 公开 JSON 供官网连接器读取的数据桥，是否够高效？有无更优？
7. 里程碑：M1→M6 顺序与粒度是否合理？有无更早产生价值的最小闭环？

【输出格式】（严格按此结构）
- 结论（一页以内总评）
- 建议方案（逐问题给，可改动我原来的设计）
- 风险（每条一句话）
- 实施步骤（编号，可执行）
- 需确认（你拿不准、需要永涛拍板的点）
```

- **镜像站/读不了链接的**（问达宝等）→ 用本内嵌版
