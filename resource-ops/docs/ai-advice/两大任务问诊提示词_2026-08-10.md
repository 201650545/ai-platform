```
你是一位资深的 AI 资源运营 + 任务执行流程专家。永涛正在构建「AI 自助资源运营体系」，
现在需要把「免费资源调研」任务打包成【两个大任务】发给执行 Agent 直接跑。
请先读下面的仓库与方案，然后优化这份任务方案。

【背景】
永涛拥有大量数字资源（各厂商 API、免费额度、账号权益），要统一收集到飞书多维表格
（AI 可读的可执行规格库），凭证值安全留在本地。本任务是周期1·免费资源调研：
逐平台验证登录态、摸清免费额度现状，为资源库第一张「可执行规格表」提供素材。

【上下文（请先打开阅读）】
- 仓库主页：https://github.com/201650545/ai-resource-hub

- 验证记录（10 平台已确认）：https://github.com/201650545/ai-resource-hub/blob/main/docs/资源调研/验证记录_2026-08-10.md
- 【重点审这个】两大任务方案 v1：
  https://github.com/201650545/ai-resource-hub/blob/main/docs/资源调研/分派/两大任务方案_v1_2026-08-10.md
- 项目方案书（体系总览）：https://github.com/201650545/ai-resource-hub/blob/main/方案书.md

【当前方案概要】
- 任务 A · 海外平台组（4）：GitHub Models、Google Colab、Together.ai、Mistral —— 谷歌登录为主
- 任务 B · 国内平台组（6）：百度千帆、腾讯混元、MiniMax、零一万物、讯飞星火、阶跃星辰 —— 手机/微信为主
- 执行环境：opencli 控制已登录 Chrome；能谷歌登录自动登；需手机/扫码的记待办；账号密码的提示永涛设置
- 每平台记录：登录态/登录方式/免费额度/价值/待办；结果写回 验证记录_2026-08-10.md

【请优化的点】
1. 【明确性】每个平台的「探测要点」是否足够明确、可执行？有无含糊处要改成具体动作
   （如：打开什么页面 → 看什么字段 → 判断标准）？请逐平台给出一版可直接照做的动作清单。
2. 【完整性】有没有明显遗漏？——比如平台入口可能已变（GitHub Models 404 需找新入口）、
   免费额度政策已知在变（Mistral/Colab/Together 都改过政策）、或应该顺带摸的额外字段
   （如 API 端点、模型名、限流、是否需绑卡）？
3. 【分配合理性】海外 4 + 国内 6 的分配是否均衡？要不要拆成「验证登录态」和「细查免费额度」
   两阶段？还是一个 Agent 一次跑完更省事？
4. 【防卡死】海外平台谷歌登录容易遇到 OAuth 弹窗/onboarding 表单，国内平台多要手机验证码。
   任务里该怎么写「做到哪一步就该停下记待办，不无限重试」的边界？
5. 【输出可校验】每个平台记录格式能否再加一个「验证证据」字段（如截图/URL 路径/key 存在与否），
   让永涛能快速复核？

【输出格式】（严格按此结构）
- 结论（一页以内总评）
- 优化后方案（可直接替换 v1 的完整版，两大任务，逐平台给动作清单）
- 风险（每条一句话）
- 实施步骤（编号，可执行）
- 需确认（你拿不准、需要永涛拍板的点）
```
