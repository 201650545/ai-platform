# 背景
我们有一条数据桥链路：
- **数据桥仓库 ai-resource-hub**：飞书多维表 → `exporter/export.py` → `public/` 四 JSON（index/capabilities/instances/schema）→ GitHub Pages → 消费方拉取
- **门户仓库 ai-hub**：`00_中央平台/resources_bridge.py` 作为代理模块，分三文件拉取 GitHub Pages，聚合给 `/api/resources`

# 待评审问题
我写了方案书（链接见下）。核心问题：**跨 build 混搭**——GitHub Pages 经 CDN 分发，门户对三文件独立 GET，各文件 CDN 缓存刷新时机不同，可能拉到「新 capabilities + 旧 index」；现有**双读 index 只能证明 index 自身在两次读取间未变，无法证明 caps/insts 与 index 同 build**。方案书主张用 **manifest.json 提交点**根治（先写数据文件、最后写 manifest；门户读 manifest + 对文件字节算 sha256 逐项比对，全匹配接受、任一不匹配回退本地 fail-closed；无 manifest 降级现有双读 index）。
