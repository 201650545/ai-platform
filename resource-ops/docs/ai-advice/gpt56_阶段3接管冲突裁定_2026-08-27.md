风险

最大风险不是技术失败，而是授权范围漂移：B 若没有“验收后必回原态”这一硬条件，就会把临时测试偷偷变成永久 cutover。

CC Switch 的 provider/current-provider 若是全局状态，切到 gateway-3100 可能同时影响其他正在运行的 Claude Code 会话，因此验收期间应避免并行生产会话。

临时降低 RPM 若未恢复，会制造后续看似随机的路由异常，因此必须记录旧值并在 finally/收尾步骤中恢复。

只做单次 Read/Bash 无法证明“工序链不断裂”；真正关键的是 tool result 已进入消息历史之后再发生模型/渠道切换。

Bash 工具具有副作用风险，验收只允许使用读取型或无副作用命令，不以修改文件、安装包、提交代码作为测试动作。

Anthropic↔OpenAI 转换可能在 tool_call id、tool result 对应关系、并行工具调用或流式 framing 上出问题，HTTP 200 本身不足以证明工具协议正确。

/v1/models 已观察到会随渠道健康从 158→123 波动；如果客户端依赖动态模型列表，这会造成“模型随机消失”，应独立列 backlog，不与阶段3混修。
GitHub

unreachable 优先于 capability_mismatch 是既定 route-plan 展示优先级，不应在阶段3误判为 capability 回归；验收应看实际 eligibility/访问计数，而非只看单一 reason。

失败发生在上游已生成 tool call、但响应状态不确定的边界时可能产生重复决策；真实验收应把故障注入放在调用前的本地 RPM admission，不要故意制造“上游处理到一半断线”。

正式退役 Cherry 是独立变更，涉及回滚点、默认 provider、开机自启和依赖清理，和“tools failover 是否成立”绑在同一验收里会扩大故障域。
