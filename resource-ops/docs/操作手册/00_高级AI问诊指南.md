# 操作手册 00 · 高级 AI 问诊指南（提问策略）

> 用途：**教会任何执行 AI / 新对话如何用「ChatGPT 镜像版 + Claude（Anthropic 官网）」做高级 AI 问诊**
> 定位：这是**策略层**——回答「什么时候问、问什么、怎么问、结果怎么落」；具体「怎么点」的操作细节见 01（GPT）/ 03（Claude）。
> 版本：2026-08-11 首版 ｜ 适用：任何执行 Agent / 新对话，开工前先读本指南

---

## 0. 为什么问（核心理念，先想清楚再动手）

- **主动改进**：做完方案不交差，主动自问「这够好吗？是否值得拿给更聪明的 AI 复核？」——值得就主动发起问诊，不等郭老师催。
- **架构 > 内容**：架构/方案用最先进模型把关，内容用性价比模型执行。高级 AI 问诊 = 让更聪明的模型当"架构审稿人"。
- **人机互查**：每条结论背后要有检索/推理依据，问诊是给结论补依据的方式之一。

> 问诊是**方法**，不是独立工作线。遇到问题、方案需优化、自认为不对时，都可以用。

## 1. 两个工具怎么选

| 工具 | 定位 | 适用场景 | 操作手册 |
|------|------|---------|---------|
| **GPT 镜像版**（GPT-5.6 Thinking·Extended） | 主力深度问诊 | 复杂方案优化、长文本、需要长思考、能读 GitHub 链接 | [01_镜像站GPT操作手册.md](01_镜像站GPT操作手册.md) |
| **Claude**（claude.ai，Sonnet 5 High） | 第二意见 / 交叉校验 / 兜底 | GPT 空回复（多链接触发 Deep Research 失败）、需要另一个视角 | [03_Claude操控手册.md](03_Claude操控手册.md) |

**选型规则**：
- 默认先问 **GPT 镜像版**（思考模型 + Extended）。
- GPT 空回复 / 渲染失败 → **转 Claude** 兜底（claude.ai 无多链接问题）。
- 重大方案（架构/流程/规范）→ 两个都问，交叉验证，合并结论。

## 2. 问诊三步前置（铁律，违反则回答作废）

> 来源：郭老师拍板（2026-08-06）的 GPT 对话流程，对所有高级 AI 问诊通用。

1. **让它先读 GitHub 仓库**——问题包开头写明「请先读 `201650545/<仓库名>`，重点看 <关键文件路径>」。
   - 仓库是高级 AI 了解项目结构的**唯一通道**；它读不了本地磁盘。
2. **有更改先 push**——规范/工具/命令/交付记录变更落盘后，先同步到仓库并 push，再问。
   - 仓库过时 = AI 基于旧结构回答 = 方案作废。
3. **补齐上下文**——问题包必须带：本次要解决什么、涉及文件路径、已知限制/红线、期望输出格式、最近一次仓库更新日期。

## 3. 问诊包怎么写（核心模板）

一个完整问诊包 = 下面七段，缺哪段补哪段：

```
【角色设定】
你是一位资深 <领域> 专家 + <方法论> 审稿人。

【背景】
<这个项目/任务是干什么的，一句话讲清楚>。

【上下文（请先打开阅读）】
- 仓库主页：https://github.com/201650545/<仓库名>
- <关键文档1>：<完整 GitHub 链接>
- <关键文档2>：<完整 GitHub 链接>
- 【重点审这个】：<本次要优化的对象，完整链接>

【当前方案概要】
<3-5 条，让 AI 不用重读也能抓住核心>。

【请优化的点】
1. <问题1，具体、可执行，不要含糊>
2. <问题2>
3. <问题3>

【约束 / 红线】
- <凭证纪律：不写 token/key/密码，只写「key 是否存在 / 是否需绑卡」>
- <其他不可妥协的红线，如：不绑卡 / 不充值 / 不订阅>

【输出格式】（严格按此结构）
- 结论（一页以内总评）
- 优化后方案（可直接替换的完整版）
- 风险（每条一句话）
- 实施步骤（编号，可执行）
- 需确认（拿不准、需要郭老师拍板的点）
```

**写法要点**：
- 「请优化的点」要**具体可数**（编号列出），不要只写"请优化"。
- GitHub 链接给**完整 URL**（含 `/blob/main/...` 路径），让它能实读。
- 约束/红线**必须写进提示词**，防止高级 AI 建议越界操作。
- 输出格式固定为五段（结论/方案/风险/步骤/需确认），回复直接可落档、可执行。

> 现成示例：`docs/ai-advice/两大任务问诊提示词_2026-08-10.md` —— 照着这个结构和密度写即可。

## 4. 操作流程（怎么执行）

### 4.1 问 GPT 镜像版
1. 读 [01_镜像站GPT操作手册.md](01_镜像站GPT操作手册.md)：登录（localStorage 构造 URL）→ 选模型（Thinking·Extended）→ 注入长提示词（base64）→ 发送。
2. 深度问题至少等 15 分钟；后台轮询完成判定（stop 按钮消失 + 出现 assistant 消息）。
3. 出现空回复（assistant 0 字符 + 搜索来源块）→ 转 Claude 兜底。

### 4.2 问 Claude（claude.ai）
1. 读 [03_Claude操控手册.md](03_Claude操控手册.md)：`tab new` 开独立标签（**勿覆盖**流式输出中的标签）→ 确认 Sonnet 5 + 思考程度 High。
2. 提示词用**链接式完整版**（给 GitHub 链接让它实读）；末尾注明输出格式。
3. 完成判定：`document.body.innerText.includes("Claude is responding")` 连续 3 次 false。

### 4.3 通用
- 长文本一律 base64 + eval 注入（规则见 [02_OpenCLI操控手册.md](02_OpenCLI操控手册.md) §3.3）。
- 两个工具各开独立 session/标签，**互不覆盖**。

## 5. 回复怎么落

1. 完整回复保存到 **`docs/ai-advice/`**，文件名含日期 + 问诊对象：
   - 例：`docs/ai-advice/gpt56_问诊回复_<日期>.md`、`docs/ai-advice/claude_sonnet5_问诊回复_<日期>.md`
2. 合并多个 AI 结论 → 单独一份 `<主题>问诊合并结论_<日期>.md`。
3. 关键结论**提炼后更新对应方案/表格/规范**（不要只存回复不落地）。
4. 落档后按第 2 节三步：push 仓库 →（如需再问）继续。

## 6. 完成后汇报（四段式）

问诊完成 / 优化落地后，按四段式简短汇报给郭老师：
- **模块 × 验收项**（做了什么、对照什么验收）
- **变更清单**（改了哪些文件/方案）
- **验证**（怎么证明有效）
- **已知偏差**（哪些没做到/有出入）

> 只汇报**待决策事项**；已完成工作不反复汇报。被问时只给「需要决策的选项」。

## 7. 常见坑（实测）

| 坑 | 表现 | 对策 |
|----|------|------|
| 提示词含多个 GitHub 链接 | GPT 触发 Deep Research → 空回复 | 转 Claude，或拆成单链接分次问 |
| 没先 push 仓库 | AI 基于旧结构回答 | 问前必 push（第 2 节铁律） |
| 忘记给输出格式 | 回复冗长难落地 | 提示词末尾必写五段结构 |
| 凭证值写进提示词/落档 | 泄露 key/token | 只写「key 是否存在 / 是否需绑卡」 |
| 长文本直接 type | Windows 命令行解析失败 | 一律 base64 + eval 注入 |
| 覆盖流式输出标签 | 打断原会话 | 新标签 `tab new` |

## 8. 一句话记忆

> **先 push 仓库 → 给完整 GitHub 链接 → 具体列「请优化的点」→ 写明约束红线 → 固定五段输出 → 回复落 `docs/ai-advice/` → 四段式汇报。**
