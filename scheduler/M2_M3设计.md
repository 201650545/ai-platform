## 2. 数据源决策（v2）

**调度器实例配置真源 = 数据桥公开产物（`instances.json` + `capabilities.json`），复用已验证的 manifest 校验链路。**

- **为什么不是飞书 OpenAPI 直连**：本地无 `FEISHU_APP_ID/APP_SECRET/BASE_TOKEN`（只在 CI secrets）。直连需要凭证 + token 管理，且与「凭证值不入本地调度器」边界冲突。数据桥产物已经是从飞书导出的公开 JSON（含 manifest 校验），调度器读它零凭证风险。
- **需要扩展数据桥导出**（非敏感字段）：当前白名单缺 `endpoint / 路由组 / 认证方案 / 状态 / 限速 / 缺失环境变量 / 路由优先级`。这些是调度必需、非敏感，加进白名单 DTO 安全。
- **精确额度不导出**（安全边界，方案书 §6）：数据桥把额度模糊化为区间（充足/中等/偏低/耗尽）。调度器初始额度走**本地安全平面**（scheduler 本地配置），运行时 SQLite 扣减为准。数据桥区间可用于粗筛（「耗尽」实例直接跳过）。

## 3. M2：数据桥真源同步 + 并发路由

### 3.1 同步器 `sync.py`（新增）

- 读数据桥产物：本地 `public/`（优先）或线上 GitHub Pages，**带 manifest 校验**（复用 resources_bridge 的字节哈希思路：读 manifest → 对文件原始字节算 sha256 逐项比对 → 匹配才用）。
- **字段映射**（数据桥 → 调度器 SQLite）：

| SQLite instances 字段 | 来源 | 说明 |
|---|---|---|
| instance_id | instances.`instance_id` | `inst-<platform>-01` |
| capability_id | instances.`所属能力` | join capabilities |
| routing_group | capabilities.`路由组`（扩展） | 无则默认 = capability_id |
| canonical_model | capabilities.`逻辑模型` | 按 capability_id join |
| mode | capabilities.`调用方式` | `HTTP_REST`→`openai-compatible`；`OPENCLI_BROWSER`（Colab）→跳过 |
| upstream_base | capabilities.`endpoint`（扩展） | 真实上游 base_url |
| credential_id | instances.`缺失环境变量`/本地映射 | 有 key 平台才填（本地 `credential_map`） |
| quota_remaining | **本地配置**（安全平面） | 初始值；运行时 SQLite 扣减为准 |
| quota_unit | instances.`额度单位` | token / 元 / 万token |
| safety_margin | 本地配置 | 默认 0 |
| route_priority | instances.`路由优先级`（扩展） | 默认 99 |
| status | 数据桥 `额度状态` + 本地映射 | 充足/中等/偏低→可用；耗尽→额度耗尽；其余→待验证 |
| config_version | instances.`配置版本` | 用于变更检测 |

- **同步策略（关键）**：
  - **配置字段 upsert**：`routing_group / canonical_model / mode / upstream_base / credential_id / quota_unit / route_priority / config_version` 每次同步覆盖。
  - **运行态字段保留**：`status / quota_remaining / cooldown_until` 不被同步覆盖（错误切换后 SQLite 运行态为准）。
  - **新增实例**：INSERT；**数据桥消失/失效实例**：SQLite 有但数据桥没有 → 标记 `status=失效`（保留事件历史）。
  - 幂等：以 `instance_id` 为键，`config_version` 变更才更新配置字段。

### 3.2 并发路由（改 `scheduler.py`）

- 去掉请求级 `_request_lock`，改为 **per-instance 原子预留**：
  - 候选选择：过滤（模型匹配/可用/未冷却/额度>余量）→ 排序（priority，剩余额度）。
  - **预留**：`UPDATE instances SET status='预留' WHERE instance_id=? AND status='可用'` 受影响行数 = 1 才占用；否则跳过。
  - 调用完成：成功→释放回「可用」+ 原子扣额度（`UPDATE SET quota_remaining = quota_remaining - ?`）；失败→按错误分类写状态。
  - **预留超时保护**：预留后调用超时（120s）→ 自动释放回「可用」（防死预留）。
- 流式安全原则保留：**切换决策发生在向客户端输出第一字节前；已透传即不重放**。

## 4. M3：真实上游 + 流式逐块

### 4.1 真实转发（启用 `openai-compatible`）

- 同步后实例有 `upstream_base + credential_id`；本地 `credentials.json` 按 `credential_id` 提供 key。
- `OpenAICompatibleAdapter.call` 已写好，M3 接真实实例启用。
- 安全：key 只从本地读，注入 `Authorization: Bearer <key>`，不落日志/SQLite。

### 4.2 流式逐块转发（改 `OpenAICompatibleAdapter`）

- M1 整读：`urlopen().read()`。M3 改流式：`stream=True`，逐 chunk 转发 SSE 给客户端。
- 用 urllib 流式响应逐块读，`data: {...}\n\n` 逐块转发，含 `[DONE]`。
- 切换决策在首个 chunk 前完成；已透传即不重放。

## 5. 安全边界（最高优先，逐字）

- 凭证 key 值只从本地 `credentials.json` 读取；**绝不写入 SQLite / 日志 / 飞书 / 聊天**。
- 数据桥产物同步只读 `credential_id` / `缺失环境变量`（逻辑引用/变量名），不读 key。
- 精确额度数值不导出到数据桥（模糊化区间）；调度器初始额度本地配置。
- 日志 detail 白名单化（instance/model/kind/status），不记录请求体与 Authorization。
- 不创建/删除 API Key；不充值；不绑卡；不开后付费；不订阅套餐。

## 6. 落地顺序

1. **扩展数据桥导出**：exporter 白名单加 `endpoint / 路由组 / 认证方案 / 状态 / 限速 / 缺失环境变量 / 路由优先级` → validate 检查 → CI 重部署。
2. M2：`sync.py`（读数据桥产物 + manifest 校验 + 字段映射 + upsert）+ 并发路由改造。
3. M2 验证：同步后 `__admin/instances` 显示真实平台；并发请求正确预留。
4. M3：真实 adapter 启用 + 流式逐块 → 用 1 个真实 key 平台（DeepSeek）冒烟。
5. 测试：`test_m2_m3.py`（同步映射、并发预留、真实转发、流式）。

## 7. 已知风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 数据桥产物非实时（每日 CI 跑） | 配置变更延迟 ≤1 天 | 可接受（配置变更低频）；手动 `workflow_dispatch` 立即刷新 |
| 精确额度在本地安全平面（不与飞书同步） | 初始额度可能过时 | 运行时扣减为准；`credential_map` 人工维护 |
| 并发预留 SQLite 锁 | 高并发下吞吐 | WAL + busy_timeout 已有；原子 UPDATE 判定 + 预留超时释放 |
| 额度单位不一致（token vs 元） | 扣减错乱 | `quota_unit` 进同步；扣减按同单位；M2 先只启用 token 单位实例的真实扣减 |
| 真实 key 无效 | CRED_INVALID 循环 | 错误分类 → 状态失效，不切换（已有） |

## v2 变更（相对 v1）

- 数据源：飞书 OpenAPI 直连 → **数据桥公开产物**（本地无飞书凭证；复用 manifest 校验链路，零凭证风险）。
- 新增前置：**扩展数据桥 exporter 白名单**（导出 endpoint/路由组/认证方案/状态/限速/缺失环境变量/路由优先级 等非敏感字段）。
- 精确额度初始值明确为**本地安全平面**（数据桥模糊化区间不导出精确值）。
