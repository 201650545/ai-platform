## 2. 数据源决策

**调度器实例配置真源 = 飞书表 3（能力）/ 表 4（实例），直连飞书 OpenAPI。**

- 飞书是配置真源（方案书核心）；数据桥 public JSON 是「给人看/给 AI 读」的视图，**缺 endpoint/路由组/请求体模板/认证方案**等调度必需字段。
- 凭证 key 仍只从本地 `credentials.json`（受信平面）读取，**飞书只同步 `credential_id`**，不落 key。
- 飞书访问凭证（FEISHU_APP_ID/APP_SECRET/BASE_TOKEN）走环境变量，不落库。

## 3. M2：飞书真源同步 + 并发路由

### 3.1 同步器 `sync.py`（新增）

- 用 httpx 直连飞书 OpenAPI：`GET base/bitable/{app_token}/tables/{table_id}/records` 分页拉取表 3/表 4。
- **字段映射**（飞书中文 → 调度器 SQLite）：

| SQLite instances 字段 | 来源（飞书表） | 说明 |
|---|---|---|
| instance_id | 表4 `instance_id` | `inst-<platform>-01` |
| capability_id | 表4 `所属能力`（link） | join 表3 |
| routing_group | 表3 `路由组` | 无则默认 = capability_id |
| canonical_model | 表3 `逻辑模型` | 同能力多实例共享 |
| mode | 表3 `调用方式` | `HTTP_REST`→`openai-compatible`；`OPENCLI_BROWSER`（Colab）→跳过 |
| upstream_base | 表3 `endpoint` | 真实上游 base_url |
| credential_id | 表4 `凭证ID`（link 表2） | 有 key 的平台才填；无则 NULL |
| quota_remaining | 表4 `剩余额度快照`/`额度总量` | 初始值（运行态后续以 SQLite 为准） |
| quota_unit | 表4 `额度单位` | token / 元 / 万token |
| safety_margin | 表4 `安全余量` | 默认 0 |
| route_priority | 表4 `路由优先级` | 默认 99 |
| status | 表4 `状态` | 可用/待验证/额度耗尽/失效；失效平台跳过 |
| config_version | 表4 `配置版本` | 用于变更检测 |

- **同步策略（关键）**：
  - **配置字段 upsert**：`route_priority / upstream_base / credential_id / canonical_model / mode / quota_unit / safety_margin / config_version` 每次同步覆盖。
  - **运行态字段保留**：`status / quota_remaining / cooldown_until` 不被同步覆盖（错误切换后 SQLite 运行态为准）。
  - **新增实例**：INSERT；**飞书删除/失效实例**：不在飞书新列表中但 SQLite 有 → 标记 `status=失效`（不删行，保留事件历史）。
  - 幂等：以 `instance_id` 为键，`config_version` 变更才更新配置字段。

### 3.2 并发路由（改 `scheduler.py`）

- 去掉请求级 `_request_lock`，改为 **per-instance 原子预留**：
  - 候选选择：过滤（模型匹配/可用/未冷却/额度>余量）→ 排序（priority，剩余额度）。
  - **预留**：`UPDATE instances SET status='预留' WHERE instance_id=? AND status='可用' AND cooldown_until IS NULL` 受影响行数 = 1 才占用；否则跳过。
  - 调用完成：成功→释放回「可用」+ 扣额度；失败→按错误分类写状态。
  - 并发双扣防护：额度扣减也原子化（`UPDATE ... SET quota_remaining = quota_remaining - ?`）。
- 流式安全原则保留：**切换决策发生在向客户端输出第一字节前；已透传即不重放**。

## 4. M3：真实上游 + 流式逐块

### 4.1 真实转发（启用 `openai-compatible`）

- 同步后实例有 `upstream_base + credential_id`；`credentials.json` 按 `credential_id` 提供 key。
- `OpenAICompatibleAdapter.call` 已写好，M3 接真实实例启用。
- 安全：key 只从本地读，注入 `Authorization: Bearer <key>`，不落日志/SQLite。

### 4.2 流式逐块转发（改 `OpenAICompatibleAdapter`）

- M1 整读：`urlopen().read()`。M3 改流式：`stream=True`，逐 chunk 转发 SSE 给客户端。
- 用 `http.client` 或 urllib 流式响应，逐块 `data: {...}\n\n` 转发，含 `[DONE]`。
- 切换决策在首个 chunk 前完成；已透传即不重放（M1 原则延续）。

## 5. 安全边界（最高优先，逐字）

- 凭证 key 值只从本地 `credentials.json` 读取；**绝不写入 SQLite / 日志 / 飞书 / 聊天**。
- 飞书同步只读 `credential_id`（逻辑引用），不读 key。
- 日志 detail 白名单化（instance/model/kind/status），不记录请求体与 Authorization。
- 飞书访问凭证走环境变量（FEISHU_APP_ID/APP_SECRET/BASE_TOKEN），不落库。
- 不创建/删除 API Key；不充值；不绑卡；不开后付费；不订阅套餐。

## 7. 已知风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 飞书同步失败（token 过期/网络） | 调度器配置过时 | 同步失败保留旧配置并告警；可回退本地 public 兜底 |
| 真实 key 无效 | CRED_INVALID 循环 | 错误分类 → 状态失效，不切换（已有） |
| 并发预留 SQLite 锁 | 高并发下吞吐 | WAL + busy_timeout 已有；原子 UPDATE 判定 |
| 额度单位不一致（token vs 元） | 扣减错乱 | `quota_unit` 进同步；扣减按同单位；M2 先按 token 统一 |
