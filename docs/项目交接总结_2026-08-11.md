## 1. 项目目标

打通 **本地 ↔ 飞书 ↔ GitHub** 三端，让 AI 工具能读取完整资源清单并自主干活：

```
本地(ai-resource-hub) ──① 调研/记录──▶ 飞书 base(6表，AI 自助资源库)
飞书 ──② feishu-data-hub 导出──▶ GitHub Pages JSON（AI 可读）
本地调度器 ──SQLite WAL──▶ 即时额度监控（运行时真源）
```

**核心哲学**：AI 自主分配资源（不是用户分配）；架构用最先进模型把关、内容用性价比模型执行；凭证值永不落库。

## 9. 工作流约定（永涛偏好）

- **分工边界**：课件/配套练习**生成**专属执行Agent（我只写命令+复核）；删除/归档/改名/规范编辑/整理由我做
- **只汇报待决策事项**：已完成工作不反复汇报；被问时只给「需要决策的选项」让他拍板
- **交接需简短汇报**：交接任务给外部执行 AI 时，要求完成后写简短汇报（模块×验收项/变更清单/验证/已知偏差）
- **结尾转发块**：需转发时，每次结尾写约 50 字含文件路径的转发块，方便直接复制转发
- **架构>内容**：架构用最先进模型把关、内容用性价比模型执行
- **主动改进**：做完方案主动拿去问高级 AI（ChatGPT 5.6/Claude Sonnet）求优化；问诊=GitHub链接+细致提示词
- **Git 工作流**：`git pull --rebase` → `git diff` 凭证自查 → commit → push origin main
- **GPT对话流程**：问 GPT 前三步——先让它读 GitHub 仓库结构、有更改先 push 到 english-teaching-production、补齐上下文
