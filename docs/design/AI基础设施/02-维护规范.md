# AI 基础设施 — 维护规范

> 面向单人或 AI Agent 协作的轻量维护约定。核心目标：**让系统「不撒谎」**——
> 声明态、运行态、代码位置、文档四者一致，任何一层都不自造事实。

## 1. 事实层级（谁是真源）

```
Obsidian                ← 解释 / 索引 / 设计原因（为什么）
  │
config/gateways.json    ← 声明式真源（期望状态 / 身份 / canonical / 端口 / healthcheck）
  │
逐步任意运行态          ← Windows Runtime（PID / 监听 / health）
  │
D:\项目\services\*      ← 代码位置（运行版本所在）
```

- Obsidian **只登记**身份、路径、端口、职责、字段语义、治理规则；
  **绝不保存** PID、`online`、`last_seen` 等运行态，也不维护第二份 canonical。
- `gateways.json` 只写声明；运行态由 `inspect_gateways.ps1` 探测写入 runtime/drift。

## 2. 声明式配置规范（gateways.json）

- `schema_version` 必须为 `2`。
- 禁止写入：`online / alive / pid / health / status=running|down / last_seen / listener_pid / drift`。
- 可写入：`kind / lifecycle / desired_state / canonical_path / process.entrypoint / process.command_match / network.host / network.port / healthcheck.*`。
- `lifecycle`：active / legacy / deprecated / archived / experimental。
- `desired_state`：started / stopped。它是期望，不代表真实。

## 3. 运行态文件

- `gateway_runtime.json`：全量运行态快照，脚本**整体覆盖写入**，禁止手改。
- `gateway_drift.json`：异常投影（`has_drift` + `items[].reasons`），禁止手改。
- drift 判定维度：`unexpected_alive / orphan_listener / not_running / port_not_listening / port_owned_by_other_process / healthcheck_failed / duplicate_instances / wrong_instance`。

## 4. 修改流程

### 改声明（新增 / 启停 / 改端口 / 改 canonical）

1. 编辑 `D:\项目\ai-hub\config\gateways.json`（先备份旧版到 `config/_backup/`）。
2. 运行 `inspect_gateways.ps1`，确认 drift 符合预期。
3. 若改 canonical，遵循「运行真源唯一」原则，标 `canonical_status` 后观察一轮再归档旧副本。

### 启停服务

- 手动：`cd D:\项目; python -m runtime.cli status|start central|stop --all|doctor`
- 或经计划任务（`SearchGateway` 指向 `ai-hub\search_gateway\services\api_gateway.py`）。
- 建议长期服务启动命令用绝对路径入口：`python "D:\项目\services\central\server.py"`，避免 `cd + 相对` 导致探测无法归因。

## 5. 何时更新 Obsidian（不逐 commit 双录）

仅当出现**知识语义变化**时更新：

- 服务边界 / 端口 / canonical path / 目录结构变化
- 配置职责（gateways.json、runtime.yaml、三拆）语义变化
- 路由 / 策略 / 关键模块变化
- 新增 / 撤销 ADR 或重大里程碑
- Agent 维护规范变化

> Git 记「代码发生了什么」，Obsidian 记「系统现在是什么、为什么、以后如何维护」。

## 6. 安全红线

- Obsidian 记录 credential 的「字段意义 / 来源 / 管理规则」，**绝不复制真实 API key/token/secret 明文**。
- `channel_registry.json` 等渠道运行内容在工程 `data/`，Obsidian 仅登记职责，不同步运行态。
- 清理遗留文件前先确认 PID + CommandLine 归属，`Stop-Process -Id` 精确停止，不用 `-Name python`。

## 7. 验收标准（本次已完成）

- `gateways.json` 中搜 `online / pid` → 0 命中。
- `gateway_runtime.json` 中每个 started 服务都有 `alive/process_count/canonical_path_match/port_listening/port_owner_match/health/drift_reasons`。
- 8898 / 8899 无 listener，且无 registry 内服务占用。
- central/orchestrator canonical 唯一（`services/*`）。
- Obsidian 服务页不保存 PID/online。
