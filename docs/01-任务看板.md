# 01 任务看板

> **看板定位：本文件是「人类验收视图」，不是执行台账。**
> 机器的执行真源是仓库 `04_任务卡/`（含 task_XXX.md），由 orchestrator 机器消费，Obsidian 排除、本文件不开两套账。
> 本文件只记录每个任务的 **验收状态 / 验收结论 / 证据链接**，指向 `04_任务卡/task_XXX.md`，**不复制每步执行状态**；本文档**绝不出现「待办 / 进行中 / 执行完成」等机器执行状态词**——那套四态是参考形态，ai-platform 不继承。

## 看板字段约定

- **任务**：`[[]]` wikilink，链到 `04_任务卡/task_XXX.md`（vault 内部可链到任务卡原文）。
- **验收状态**：仅用验收语义词，例如 `验收通过`、`验收退回`、`待人工验收`、`验收挂起`。（`待人工验收`＝机器已产出、等人类看证据拍板。）
- **验收结论**：一段人话，说明达到/未达到什么验收标准。
- **证据链接**：指向产物、出图、测试输出、验收报告等**客观可查**的位置（相对路径或 wikilink）。
- **负责人**：本次验收的人类/角色。

## 验收标准 / 流程简述

1. **机器产出**：执行真源在 `04_任务卡/task_XXX.md`，机器按其完成执行并回写其自身状态（本文档不复制）。
2. **人工验收**：人类在本文档登记验收——对照任务卡的验收标准，看**客观证据**（产物 / 出图 / 测试输出 / 报告链接），给出 `验收通过` 或 `验收退回`。
3. **退回处理**：验收退回时，在「验收结论」写清不达标点，回 `05_` 对应记录；机器整改后重新走验收。
4. **定案归档**：验收通过后移入「历史验收记录」，本文档只存结论与证据，不保留执行过程账目。
