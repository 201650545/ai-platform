# 方案书 · 高级 AI 问诊包

> 用途：发给 **GPT 网站（ChatGPT 5.6）** 和 **Anthropic 网站（Claude.ai）** 审方案书架构
> 发法：把下方「提示词」整段复制，粘贴到 ChatGPT / Claude.ai 对话框；让模型先读 GitHub 链接再回答
> 反馈落档：收到长回复后，保存到本目录（或代码框一键复制），再按建议优化方案书

---

## 提示词（可直接复制）

```
你是一位资深的 AI 系统架构评审专家。请先阅读下面的 GitHub 仓库与方案书，
然后评审架构并回答文末 7 个问题。

【背景】
永涛是独立用户，拥有大量数字资源（各厂商 API、免费额度、账号权益、工具、网关）。
他要把这些资源统一收集到飞书多维表格（AI 可读的「可执行规格库」），凭证值安全留在本地，
由本地调度器按额度/轮换规则自主分配调用；AI 用 Open CLI 以他本人身份完成调研、验证、领取。
核心承诺：不降质、不换模型、不偷偷省钱；额度到点自动停，用尽自动跳下一个密钥。

【上下文（请先打开阅读）】
- 仓库主页：https://github.com/201650545/ai-resource-hub
- 方案书：https://github.com/201650545/ai-resource-hub/blob/main/方案书.md
- **多维表格设计**：https://github.com/201650545/ai-resource-hub/blob/main/docs/多维表格设计方案.md
  （4 张表的字段/类型/关系/视图初稿，**重点审这个**）
- 调研现状：docs/资源调研/验证记录_2026-08-10.md（10 平台登录态已确认）

【硬约束（方案不可违背）】
1. 凭证值绝不出设备：表里只留凭证 ID，值存本地 config/credentials.json
2. AI 以本人身份执行，被判定需要人工时立即停下通知
3. 密钥池轮换透明：不降级模型、不换低质渠道

【7 个待决策问题】
1. **多维表格设计**：审 docs/多维表格设计方案.md 的 4 张表（账号资产/免费资源/工具资产/任务日志）
   ——字段/类型/关系/视图是否最优？免费资源表是否真的够「AI 可执行」？
   密钥池（同模型多厂商轮换）要不要拆独立表？表4 日志能否支撑「避免重复验证」闭环？
2. 调度器形态：密钥池轮换 + 额度停止，最简可靠实现是本地进程 + base_url 代理，
   还是需要别的形态？
3. Open CLI 与飞书回写闭环：调研/验证/领取结果如何可靠回写表、避免重复验证？
4. 画布两功能（AI 搜索聚合 / HTML 制作可视化）优先级，哪个先做价值更高？
5. 安全模型：凭证 ID 引用 + 本地读取之外，还有哪些被忽略的泄漏路径？
6. 问诊机制本身：GitHub 公开 JSON 供官网连接器读取的数据桥方案，是否够高效？
   有无更优的数据桥？
7. 里程碑：M1→M6（调研→凭证库→调度器→飞书库→画布→全链路）的顺序与粒度是否合理？
   有无更早产生价值的最小闭环？

【输出格式】（严格按此结构）
- 结论（一页以内总评）
- 建议方案（逐问题给，可改动我原来的设计）
- 风险（每条一句话）
- 实施步骤（编号，可执行）
- 需确认（你拿不准、需要永涛拍板的点）
```
