二、五问直接回答
1. 注入位置

README 顶部 + AGENTS 顶部值得保留，但不能作为可靠注入点。不同 Agent 是否自动读取 AGENTS、README，没有统一保证；纯网页 ChatGPT 若用户只贴局部内容，更不可能收到未贴出的规则。最可靠位置是 memory.py bootstrap：任何记忆工作第一步必须运行它，并由它输出协议版本、项目列表、当前项目和 NEXT_ACTION。项目未选时，read/write/checkpoint/capture 对项目数据 fail-closed。这样“是否遵守”不再只靠模型记住文字。

2. 「强制/必须」的约束力

“必须”“禁止”有帮助，但对 LLM 来说仍只是上下文指令，不是安全边界；内容过长、上下文截断或存在更高优先级指令时都可能失效。更有效的是：短、靠前、条件明确、动作唯一、固定模板、程序校验。例如不要写十段解释，而写成：“若 ACTIVE_PROJECT=none，不得开展项目工作；必须先询问项目。”再让 bootstrap 输出这一状态，Agent 只需逐字段执行，而不是自行理解整套宪法。

3. 项目选择格式

建议采用混合模式，不要永远把六个项目全部抛给用户。如果用户只说“读取记忆项目”，列出注册项目让其选择；若用户明确说“读取 memory-system”，直接进入，不应再重复询问；若只表达明显意图，可建议一个项目并让用户确认。别名值得支持，并应写在项目注册表中统一解析。上次项目只能作为提示，新会话不要静默自动恢复，否则很容易把一个项目的信息带入另一个项目。

4. 与 R18 的关系

两者不冲突，应明确为两个不同层次：读记忆协议负责“当前工作属于哪里”，R18 负责“发生重要事件后是否值得保存”。建议增加逻辑状态 NO_PROJECT / PROJECT_SELECTED。处于 NO_PROJECT 时，可以读 global、可以执行 R18 的“检查”，但项目级检查结果只能是 no-op，不能写入任何项目。单纯“读取记忆”本身也不应产生记忆。项目切换时，则应先对旧项目执行一次 checkpoint 检查，再切换上下文。

5. 新会话闭环

现有 bootstrap + checkpoint 已接近闭环，但还缺四个关键环节：显式项目状态、项目切换协议、记忆新鲜度、失败行为。完整链路应是：bootstrap → 确认项目 → 读取 global + 项目记忆 → 工作 → R18/checkpoint → 必要时 capture/write → 新会话再次 bootstrap。bootstrap 最好同时返回 Git commit/同步状态，避免 Agent 基于旧 checkout 工作；如果记忆源没有同步成功，应明确报错，而不是继续假装已经加载最新记忆。

三、推荐落地方案（可直接执行）

建议不要继续增加大量 README 提示词，而是把现有机制收敛成下面这一套。

第一层：README / AGENTS 只保留一个很短的入口规则。

建议核心意思压缩成：

任何记忆相关任务，第一步必须执行 python scripts/memory.py bootstrap。
以后续命令返回的 ACTIVE_PROJECT、ALLOWED_SCOPE、NEXT_ACTION 为准。
禁止直接修改记忆文件；凭证永不进入记忆。

详细 R1'-R18 继续放在正式规范里，不要全部复制到首页顶部。

第二层：让 memory.py bootstrap 成为真正的协议入口。

无项目时建议固定输出类似：

MEMORY_PROTOCOL=v1
SOURCE_OF_TRUTH=github
ACTIVE_PROJECT=none
ALLOWED_SCOPE=global

PROJECTS:
- teaching
- courseware
- memory-system
- english-teaching
- english-learning
- devel-tools
- new-project

RULES:
- project memory is isolated
- read/write only through memory.py
- R17 project decisions take precedence
- R18 memory checkpoint is enabled
- credentials must never enter memory

NEXT_ACTION=SELECT_PROJECT

如果用户已经明确项目：

Bash
python scripts/memory.py bootstrap --project memory-system

则返回：

MEMORY_PROTOCOL=v1
ACTIVE_PROJECT=memory-system
ALLOWED_SCOPE=global+memory-system
NEXT_ACTION=READY

这样就不必再问一次用户已经回答过的问题。

第三层：项目未选择时，由程序而不是提示词阻止越界。

例如：

Bash
python scripts/memory.py read STATE

在没有项目的情况下直接返回：

ERROR=PROJECT_REQUIRED
NEXT_ACTION=SELECT_PROJECT

但：

Bash
python scripts/memory.py read global

仍允许执行。

write/checkpoint/capture 同样遵循这个状态。

第四层：规定 Agent 的固定首轮响应。

首次 bootstrap 且无项目：

已加载共享记忆协议：GitHub 是唯一记忆真源；项目记忆相互隔离，global 为全局规则；所有读写只通过 memory.py；R17 项目决策优先，R18 自动执行记忆检查；凭证永不进入记忆。
当前尚未选择项目。请选择：teaching / courseware / memory-system / english-teaching / english-learning / devel-tools，或告诉我创建新项目。

不建议每执行一次 read 都重新念这段。每个新会话首次 bootstrap 一次即可；协议版本改变时再重新输出完整理解。
