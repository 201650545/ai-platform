# Agent Guide 编写指南

> 本文档指导如何为 Feishu Data Hub 的每个项目编写 `agent-guide.md`——面向 AI 代理的分析规则与行为约束文件。

---

## 1. agent-guide.md 的目的

### 1.1 定位

`agent-guide.md` 是项目的 **AI 使用规则手册**，规定 AI 代理在分析该项目数据时"能做什么、不能做什么、应该怎么做"。

它与以下文件互补但不同：

| 文件 | 职责 | 维护方式 |
|---|---|---|
| `summary.md` | 项目业务说明：是什么、有什么、怎么用 | 人工维护 |
| `semantic.json` | 语义映射：字段含义、表角色 | 代码从 YAML 构建 |
| `schema.json` | 数据结构：字段类型、关联 | 代码自动生成 |
| **`agent-guide.md`** | **AI 行为规则：任务边界、分析优先级、禁止推断、输出要求** | **人工维护** |

### 1.2 为什么需要 AI 使用规则

AI 代理在分析数据时容易犯以下错误：

1. **过度推断**：从少量数据推断总体趋势，从单次正确断言长期掌握
2. **假设不存在的关系**：假设两张表之间有关联，但 schema 中没有关联字段
3. **混淆概念层次**：将"看过"等同于"掌握"，将"暴露"等同于"学习"
4. **忽视数据时效**：使用系统时钟而非数据快照时间判断"今天"
5. **过度读取**：扫描全部记录而非按需筛选
6. **越界操作**：声称已修改数据，或做出超出数据范围的承诺

`agent-guide.md` 通过明确的规则约束 AI 的行为，防止这些错误。

### 1.3 面向的读者

`agent-guide.md` 的唯一读者是 **AI 代理**。因此，编写风格应：

- 使用祈使句和禁止句（"必须..."、"禁止..."、"不应..."）
- 每条规则附带理由和数据依据
- 引用具体的表名和字段名
- 规则之间不矛盾，优先级清晰

## 2. 必须包含的章节

`validate-ai-docs.mjs` 校验 `agent-guide.md` 必须包含以下 10 个章节标题。缺少任何一个都会导致校验失败。

### 2.1 章节清单

| 序号 | 章节标题 | 校验关键字 |
|---|---|---|
| 1 | 适用任务 | `适用任务` |
| 2 | 不适用任务 | `不适用任务` |
| 3 | 分析优先级 | `分析优先级` |
| 4 | 读取顺序 | `读取顺序` |
| 5 | 计划制定规则 | `计划制定规则` |
| 6 | 错误分析规则 | `错误分析规则` |
| 7 | 时间范围处理 | `时间范围处理` |
| 8 | 数据不足时的处理 | `数据不足时的处理` |
| 9 | 禁止推断 | `禁止推断` |
| 10 | 输出要求 | `输出要求` |

### 2.2 各章节编写要求

#### 适用任务

**内容：** 用编号列表列出 AI 可以使用本项目数据完成的任务类型。

**编写要点：**
- 每个任务说明对应的表和数据来源
- 任务应基于项目实际的 capabilities
- 说明任务的具体内容，而非泛泛的"数据分析"

**示例（learning-english）：**
> 1. **复习调度建议**：根据 `vocabulary.下次复习`、`掌握状态`、`记忆阶段` 筛选到期单词，生成当日复习清单。
> 2. **学习计划制定**：综合词汇复习、计划任务、能力状态和错误改进，生成当天的英语学习计划。

#### 不适用任务

**内容：** 用编号列表列出 AI **不应**使用本项目数据完成的任务，并说明原因。

**编写要点：**
- 明确拒绝或标注限制
- 每条说明为什么不适用（数据不足、无此能力、只读限制等）
- 覆盖常见误区：实时交互、外部标准映射、写回数据等

**示例（learning-english）：**
> 1. **实时测验与评分**：数据是每小时同步的快照，不支持实时交互式测验。
> 2. **CEFR 等外部标准映射**：`competency-state.当前等级` 是项目内部自定义分级，未映射到外部标准。

#### 分析优先级

**内容：** 定义 AI 在处理请求时应遵循的分析优先级排序。

**编写要点：**
- 按优先级从高到低编号
- 每个优先级说明数据来源和筛选条件
- 附带理由（为什么这个优先级更高）
- 与项目的业务逻辑一致（如间隔重复系统中到期复习最高优先）

**示例（learning-english）：**
> ### 第一优先级：已到期复习任务
> - 数据源：`vocabulary` 表
> - 筛选条件：`下次复习` <= 当前日期
> - 理由：到期未复习的词遗忘风险最高

#### 读取顺序

**内容：** 用编号列表列出 AI 代理应遵循的数据读取顺序。

**编写要点：**
- 先读元数据（status → manifest → schema），再读业务数据
- 标注每张表的记录数，提醒 AI 大表需筛选而非全量遍历
- 与 `summary.md` 的"推荐读取顺序"保持一致
- 说明根据具体问题可以跳过哪些表

**示例（learning-english）：**
```
1. status.json          → 确认数据新鲜度
2. manifest.json        → 了解表结构和记录数
3. schema.json          → 了解字段类型和表间关联
4. vocabulary           → 筛选到期复习词（核心数据，6000 条）
5. study-tasks          → 筛选今日待办和延迟任务（508 条）
```

#### 计划制定规则

**内容：** 定义 AI 在制定学习计划时必须遵守的规则。

**编写要点：**
- 用编号规则形式编写（规则 1、规则 2...）
- 每条规则有明确的标题和详细说明
- 覆盖：优先级排序、掌握判断标准、维度平衡、历史参考、错误改进
- 包含具体的字段引用和数据来源

**示例（learning-english）：**
> ### 规则 1：优先处理已到期复习任务
> - 从 `vocabulary` 筛选 `下次复习` 到期的单词
> - 到期复习任务的优先级高于新词学习和能力训练
>
> ### 规则 2：不把"看过"直接当作"掌握"
> - 判断掌握状态必须使用 `掌握状态` 和 `记忆阶段` 字段
> - `学习次数` 高不等于掌握，必须结合 `正确次数`

#### 错误分析规则

**内容：** 定义 AI 在分析错误时必须遵守的规则。

**编写要点：**
- 定义错误归因分类（如知识、方法、审题、时间、策略）
- 要求交叉验证（多表对照）
- 要求标注样本量限制
- 要求区分已解决和未解决错误
- 不根据单次错误断言系统性问题

**示例（civil-service-exam）：**
> ### 规则 1：按五类归因分类
> 每条错题的 `错因分析` 应归入以下类别之一：
> - **知识**：知识点不熟/缺失
> - **方法**：解题思路/方法不当
> - **审题**：题干理解/条件遗漏
> - **时间**：用时不足导致仓促
> - **策略**：时间分配/放弃决策失误

#### 时间范围处理

**内容：** 定义 AI 在处理时间相关查询时必须遵守的规则。

**编写要点：**
- 明确"今天"的定义基准（`generated_at` 或 `last_success_at`，非系统时钟）
- 定义 `is_stale` 状态的处理方式
- 说明日期字段的时区可能
- 定义"最近/近期"需明确窗口
- 禁止推断同步间隔内的状态变化

**示例（learning-english）：**
> ### 规则 1：以数据快照时间为准
> - "今天"的定义应以 `manifest.json` 的 `generated_at` 或 `status.json` 的 `last_success_at` 为基准
> - **不应**使用 AI 工具的系统时钟作为"今天"的判断依据
> - 若 `last_success_at` 距当前已超过 2 小时，应提示数据可能不新鲜

#### 数据不足时的处理

**内容：** 定义 AI 在数据不足时的处理规则。

**编写要点：**
- 要求明确说明数据不足（不沉默、不掩盖）
- 禁止编造数据或用训练知识填补空白
- 要求说明数据不足的影响
- 建议补充数据
- 区分"无数据"和"无问题"

**示例（learning-english）：**
> ### 规则 1：明确说明数据不足
> 当遇到以下情况时，AI 代理**必须**在输出中明确说明数据不足：
> - 相关表的记录数为 0 或极少（如 `study-sessions` 仅 3 条）
> - 筛选后的结果集为空
> - 关键字段为空值
>
> ### 规则 2：不编造数据
> - 数据不足时**绝不**编造记录或字段值
> - **绝不**根据其他字段"推测"未提供的字段值
> - **绝不**用训练知识填补数据空白

#### 禁止推断

**内容：** 用编号列表列出 AI 严禁做出的推断。

**编写要点：**
- 每条用"禁止..."开头，明确禁止
- 每条附上理由和应使用的正确判断方法
- 与 `summary.md` 的"不应做出的推断"保持一致
- 覆盖项目特定的禁忌（如不假设表间关联、不映射外部标准、不预测命题概率等）

**示例（learning-english）：**
> ### 1. 禁止将"看过"等同于"掌握"
> - `text-library.覆盖词汇列表` 中包含某词，仅表示该词在文本中出现过
> - 不等于该词已被学习、已被测验或已被掌握
> - 掌握判断必须基于 `vocabulary.掌握状态` 和 `记忆阶段`

#### 输出要求

**内容：** 定义 AI 输出必须满足的要求。

**编写要点：**
- 要求标注数据来源（表名和字段名）
- 要求标注数据新鲜度
- 要求标注样本量限制
- 要求标注不确定性
- 要求结构化输出
- 要求区分事实和建议
- 要求使用项目术语
- 要求正确处理空结果

**示例（learning-english）：**
> ### 规则 1：标注数据来源
> - 每项分析结论必须标注数据来源（表名和字段名）
> - 示例："根据 `vocabulary` 表，当前有 45 个单词的 `下次复习` 日期已到期"
>
> ### 规则 2：标注数据新鲜度
> - 输出开头应说明数据的新鲜度
> - 示例："本分析基于 `generated_at: 2026-07-26T06:35:53Z` 的数据快照"

## 3. 编写原则

### 3.1 基于真实 schema 和 manifest

与 `summary.md` 相同，`agent-guide.md` 中的所有表名、字段名、记录数、关联关系必须来自真实的 `schema.json` 和 `manifest.json`。

**具体要求：**
- 引用的表名必须存在于 manifest.json
- 引用的字段名必须存在于 schema.json
- 引用的记录数应与 manifest.json 一致或标注"约"
- 引用的关联关系必须来自 schema.json 的 relation 字段
- 禁止虚构字段、表或关系

### 3.2 规则可执行

每条规则应具有可操作性——AI 代理读完规则后知道具体应该怎么做：

**好的写法：**
> 判断掌握状态必须使用 `掌握状态` 和 `记忆阶段` 字段，`学习次数` 高不等于掌握，必须结合 `正确次数` 和 `上次测验` 结果。

**不好的写法：**
> 要注意区分学习和掌握。

### 3.3 禁止规则附带替代方案

每条"禁止..."规则应附带"应使用...替代"的说明，让 AI 知道正确做法：

**好的写法：**
> 禁止将 `competency-state.当前等级` 映射到 CEFR 等外部标准。`当前等级` 是项目内部的自定义分级，应作为内部相对水平使用，不与其他标准换算。

**不好的写法：**
> 禁止映射外部标准。

### 3.4 与 summary.md 一致

`agent-guide.md` 和 `summary.md` 在以下方面必须保持一致：
- 读取顺序
- 已知限制
- 不应做出的推断 / 禁止推断
- 关键状态字段

`summary.md` 偏向"描述性"（项目是什么样的），`agent-guide.md` 偏向"规范性"（AI 应该怎么做）。两者对同一事实的表述应一致，但语气不同。

### 3.5 覆盖项目特定风险

每个项目有其特定的风险点，`agent-guide.md` 应针对性地覆盖：

| 项目 | 特定风险 | 对应规则 |
|---|---|---|
| learning-english | `lexical-units` 与 `vocabulary` 无关联 | 禁止假设关联 |
| learning-english | `study-sessions` 仅 3 条 | 禁止趋势推断 |
| learning-english | `是否公开` 字段不作为过滤条件 | 禁止推断过滤作用 |
| civil-service-exam | `practice-records` 仅 1 条 | 禁止总体水平评估 |
| civil-service-exam | `target-positions` 无外键 | 禁止强关联推断 |
| civil-service-exam | `exam-patterns` 频次非概率 | 禁止命题概率预测 |

## 4. 源文件位置

### 4.1 源文件

```
content/projects/<slug>/agent-guide.md
```

**当前项目的源文件：**
- `content/projects/learning-english/agent-guide.md`
- `content/projects/civil-service-exam/agent-guide.md`

### 4.2 构建时复制到公开目录

`agent-guide.md` 在 `sync-project.mjs` 同步过程中被原样复制到公开目录：

```
content/projects/<slug>/agent-guide.md
    │
    │  sync-project.mjs
    │  ├── fs.readFile(agentGuideSourcePath)
    │  ├── assertNoSecrets(content, secretValues)   ← 安全扫描
    │  └── fs.writeFile(tempDir/agent-guide.md, content)
    │
    ▼
public/projects/<slug>/agent-guide.md
```

**关键行为：**
- **原样复制**：代码不修改文件内容
- **安全扫描**：复制前执行 `assertNoSecrets()`
- **必须存在**：如果源文件不存在，同步抛出错误中止：`"content/projects/<slug>/agent-guide.md 不存在 — 必须提供人工维护的 AI 使用规则"`
- **原子替换**：先写入临时目录，同步成功后原子替换

### 4.3 内容长度要求

| 校验脚本 | 最小内容要求 |
|---|---|
| `validate-semantic.mjs` | >= 100 字符 |
| `validate-ai-docs.mjs` | >= 200 字符 |

内容过短会导致校验失败。

## 5. 维护规则

### 5.1 不自动覆盖人工内容

**核心规则：** 构建过程不会自动修改 `content/projects/<slug>/agent-guide.md` 的内容。

- `sync-project.mjs` 只执行复制操作，不修改内容
- 不存在任何代码逻辑会反向修改源文件
- 人工编写的规则是权威来源

### 5.2 何时需要更新

| 变化场景 | 是否需要更新 agent-guide.md |
|---|---|
| 飞书表结构变化（新增/删除字段或表） | 是（更新引用的字段名和表名） |
| 记录数显著变化（如样本量从少变多） | 是（更新样本量限制说明） |
| 新增关联字段 | 是（更新禁止推断中的关联假设规则） |
| 发现新的分析风险 | 是（更新禁止推断和数据不足处理） |
| 调整语义配置 | 否（语义映射在 semantic.json 中） |
| 调整路由配置 | 否（路由在 routing.json 中） |
| 更新 summary.md 的读取顺序/限制/禁忌 | 是（保持一致） |

### 5.3 更新后的验证

修改 `content/projects/<slug>/agent-guide.md` 后，运行：

```bash
# 1. 重新同步
node scripts/sync-project.mjs <slug>

# 2. 语义校验
node scripts/validate-semantic.mjs

# 3. AI 文档校验（检查必需章节和安全性）
node scripts/validate-ai-docs.mjs

# 4. 安全扫描
node scripts/security-scan.mjs
```

### 5.4 与 summary.md 的同步维护

如果 `agent-guide.md` 中的以下内容发生变化，必须检查 `summary.md` 是否需要同步更新：

- 读取顺序
- 已知限制 / 数据不足处理
- 禁止推断 / 不应做出的推断

两个文件在这些方面的表述应保持一致。`agent-guide.md` 使用规范性语气（"必须"、"禁止"），`summary.md` 使用描述性语气（"应"、"不应"）。

## 6. 校验机制

### 6.1 validate-semantic.mjs 中的校验

```javascript
// 检查 agent-guide.md 存在且内容充分
const agentGuidePath = path.join(projectDir, "agent-guide.md");
const content = await fs.readFile(agentGuidePath, "utf8");
if (content.trim().length < 100) {
  console.error(`  ✗ agent-guide.md 内容过短（<100 字符）`);
  totalErrors++;
}
```

### 6.2 validate-ai-docs.mjs 中的校验

```javascript
// 检查 agent-guide.md 存在、内容充分、安全扫描通过
// 检查必需章节
const requiredSections = [
  "适用任务", "不适用任务", "分析优先级", "读取顺序",
  "计划制定规则", "错误分析规则", "时间范围处理",
  "数据不足时的处理", "禁止推断", "输出要求"
];
for (const section of requiredSections) {
  if (!guide.includes(section)) {
    console.error(`  ✗ agent-guide.md 缺少章节：${section}`);
    errors++;
  }
}
```

校验逻辑是字符串包含检查（`guide.includes(section)`），章节标题必须与上述关键字完全匹配。建议使用 `## ` 二级标题格式编写章节。
