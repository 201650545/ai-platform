用 **opencli** 控制已打开的日常 Chrome（永涛登录态）：
- `opencli browser n8hh7hyn tab list` — 查看当前所有标签页，确认目标页面是否已开

### 0.5 防卡死边界（核心，替换 v1 隐含逻辑）

借用方案书 Open CLI 状态机语言：`PENDING → LEASED → RUNNING → SUCCEEDED | FAILED | NEEDS_HUMAN`

| 场景 | 停止信号 | 处理 |
|------|---------|------|
| Google OAuth | 出现「需手机验证/二次验证/短信验证码」字样 | 立即 `NEEDS_HUMAN`，**不得模拟输入验证码** |
| Onboarding 问卷（公司名/用途） | — | 用合理占位值（如 "Personal / Research"）尝试提交 **1 次**；仍卡住 → 立即停止记待办 |
| 绑卡要求 | 出现「需要支付方式才能激活」字样，哪怕声称不扣费 | 一律停止，记入待办，**不得输入任何支付信息** |
| 国内手机/微信登录墙 | 确认登录方式后 | 不点击任何登录选项，直接记录，进入下一平台，不等待/不重试 |
| 单平台总耗时 | 国内组 3 分钟 / 海外 OAuth 组 5 分钟 | 超时立即标注「未探测，时间超限」，跳下一个 |

## 风险（每条一句话）

1. 两个 Agent 并发写同一份验证记录文件，若没按 0.8 分段会互相覆盖——已用「分段 + 主 Agent 合并」处理。
2. Google OAuth 遇未预期 onboarding/二次验证时可能卡住——0.5 节边界可缓解但不能完全杜绝。
3. 免费额度政策随时变，调研当天数字几天后可能过期——靠「验证时间戳」配合后续复核周期。
4. 部分额度需「实际发起一次真实调用」才能验证（如 Colab 是否真给 GPU）——严格守「只看选项文案，不实际连接消耗」。
5. 官网公开定价页与控制台实际额度可能不一致——双源标注来源，不能只信一处。
6. Mistral/Together 免费层若已改「强制绑卡才可用」，按旧认知硬闯有被要求填支付信息、误触发扣费的风险——见到绑卡要求立即停。
7. 新增的 endpoint/模型名/限流字段，页面未说明时 Agent 有编造倾向——prompt 反复强调「未说明就写未说明」。
