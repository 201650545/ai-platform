# 飞书多维表格 · 设计方案

> 版本：v0.2（2026-08-10，按 GPT-5.6 问诊结论重构）
> 前版：v0.1（4 表初稿）→ 已按高级 AI 建议拆为 6 表体系
> 定位：AI 自助资源运营体系的**配置真源**（资源配置的唯一权威来源）
> 状态：方案定稿 → 在飞书 base 落地 → 对接本地 SQLite（运行时真源）
> 背景：现有飞书 base 已有「工具资产明细表」（8 字段 10 条记录），本方案在其基础上扩展

---

## 〇、真源分工（GPT 问诊核心结论，先读这个）

| 平面 | 谁 | 存什么 | 为什么 |
|------|-----|--------|--------|
| **配置真源** | 飞书多维表格 | 能力定义 / 账号 / 凭证引用 / 实例登记 / 人工可视化 | 人类和 AI 认这个为准 |
| **运行时真源** | 本地 SQLite | 实时额度计数 / cooldown / lease / 审计 / 调用日志 | 每请求写一次飞书会限流+一致性崩 |

同步规则：
- **配置 → 运行时**：飞书 → SQLite（sync worker，周期拉取）
- **运行时 → 配置**：SQLite → 飞书（按周期或关键状态变化同步**摘要**，不是每次请求都写）

> 结论：飞书**不承担实时额度计数**。表 4「剩余额度」等运行态列是**摘要快照**，真实计数在本地 SQLite。

---

## 一、设计原则（4 条，沿用 + 强化）

1. **AI 可读可执行**：每条能力带 endpoint / models / exec_type / 请求模板，AI 读表即知「怎么用」
2. **凭证不出表**：表里只有凭证 ID（引用），值存本地 `config/credentials.json`，绝不出设备
3. **能力与实例分离**：一个**逻辑能力**（模型+质量）可挂多个**实际实例**（平台+凭证+额度）→ 轮换只换实例、不换能力，从结构上保证"不降质"
4. **状态驱动**：调度器只消费 `status=可用` 的实例，绝不碰失效/冷却行

## 二、六张表总览

| # | 表名 | 定位 | 谁读/谁写 |
|---|------|------|----------|
| 1 | **账号资产汇总** | 我的账号与登录方式 | AI 写、调度器读凭证引用 |
| 2 | **凭证池 Credential Pool** | 密钥/代金券/权益引用（密钥池拆独立表） | 调度器读、Open CLI 回写 |
| 3 | **资源能力规格表** | **逻辑能力定义**（模型+质量+调用协议，可复用） | AI 写、调度器读 |
| 4 | **资源实例表** | **每个实际入口**（平台+凭证+额度+运行状态） | 调度器读、Open CLI 回写 |
| 5 | **工具资产明细表** | 工具/软件/网关注册（已建，保留） | 已建，保持 |
| 6 | **自动化任务日志** | 任务状态机 + 审计留痕 | Open CLI/调度器写 |

> 表 3+4 合起来 = 原 v0.1 的「免费资源表」。拆开的原因：**同一模型（如 deepseek-v4-flash）可能有 3 个平台入口**，若揉在一行里字段无法表达"每个入口各自的额度/状态"；拆开后「能力」定义一次，「实例」登记多个，轮换和状态各自独立。

## 九、表间关系

```
账号资产(1) 1 ──< 凭证池(2)      ← 所属账号
凭证池(2)   1 ──< 资源实例(4)    ← 凭证ID
资源能力(3) 1 ──< 资源实例(4)    ← 所属能力（轮换只换实例、不换能力）
资源实例(4) 1 ──< 任务日志(6)    ← 关联实例
工具资产(5)    独立
```

- **轮换路径**：表 3 能力（锁逻辑模型+质量）→ 表 4 该能力下 `status=可用` 的实例集 → 按 表 2 轮换组排序 → 取表 4 凭证 ID → 本地取密钥 → 调用
- 表 6 是「谁对表 4 做过了什么」的审计痕迹，幂等键阻止重复执行

## 十一、与执行层对接点（更新）

- **调度器（本地进程 + base_url 代理）**：读 表3+表4（status=可用）→ 本地 SQLite 取实时额度 → 本地 credentials.json 取密钥 → 调用 → **运行时计数写 SQLite**（不写飞书）→ 周期同步摘要回 表4
- **Open CLI（任务状态机 executor）**：领 lease → 执行 → 结构化结果（脱敏证据）→ 回写 表4 状态 + 表6 日志；需人工 → `NEEDS_HUMAN`
- **数据桥（Public Read Model）**：飞书 → Exporter → **字段白名单 + 脱敏/聚合** → `resource_catalog.public.json` → GitHub Pages。**不公开**：账号标识、credential_id、手机绑定状态、错误详情、内部路由优先级
- **长期监控**：按 next_verify_at 调度验证；额度快照由本地 SQLite 汇总后同步
